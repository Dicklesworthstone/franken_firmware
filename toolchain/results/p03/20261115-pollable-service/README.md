# Pollable production control service: host evidence

The normal `SettledRender` service route now retains an admitted SOAP envelope
while its journal is pending, services renderer/Stop turns, and retires the
original reply even after observer timeout or mailbox disappearance. The same
owner turn drives authenticated datagram commands. This is cooperative offline
host behavior, not a hard scheduling guarantee or a hardware acknowledgement.

`source-inputs.sha256` identifies the published source inputs. The strict
workspace/all-target Clippy result below covers the same Rust bytes. Two Python
runner files subsequently gained explicit `-j 1` admission and its assertion;
their ten mechanics tests passed. Actual smoke job 30109207290184159 then
passed all 14 child-process tests with zero capture loss and all six required
case names present. Its receipt matches all 15 published source inputs, checked
separately from the runner's internal-consistency validation. No production
Asupersync pin is advanced here.

## Qualification still open

P03 and P05 remain open. This evidence does not establish legacy-guest stack or
heap fit, allocation ceilings, real-time scheduling, provider sessions, retained
drivers, physical output or network reliability. The HTTP future-state layout
budget is shallow, and cooperative deadlines cannot preempt synchronous calls.
The large stopped-owner error/custody representation documented in the previous
owned-control evidence remains a target stack risk. Per-packet freshness still
cannot preempt a pause between sampling and admission. A source-review fix for
per-packet admission-clock freshness is a separate successor; it cannot repair
the measured sleep stalls.
