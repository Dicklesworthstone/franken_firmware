# N05: actual offline repair comparison (`ffw-8cy`)

The standalone `toolchain/n05-repair-study` crate consumes the real N04
`PlayoutEngine` and immutable Asupersync RFC 6330 algorithms. Its own workspace
and lockfile are separate from the production graph. No production stream or
allocation-probe manifest gains a study dependency. Root workspace exclusion
is the only root manifest change. The supervisor must resolve and retain
`toolchain/n05-repair-study/Cargo.lock` before a locked qualification. Ordinary
Cargo metadata/fetch resolution does not compile Rust; every compilation and
native execution uses strict RCH. No dependency lock is fabricated by authoring.

Asupersync is pinned to `14032b8f2c832ee7ef1946404f5efb18162af045`, defaults off.
Application/protocol code forbids unsafe. The study reuses the existing audited
`franken-alloc-probe` allocator and uses `raptorq =2.0.1` only as an independent
reference in its exhaustive test. No upstream source changes. Pure coding
algorithms exercise no Cx, TaskHandle or scheduler changes; P05's separate
cancellation-release gate remains open and is not an added N05 dependency.
Nothing here qualifies that runtime, a board, provider, acoustics or deployment.

## Frozen comparison

Profile `n05.rfc6330.k4-r4.v4`, seed `6221061` (`0x5eed05`): 64 packets of
48 kHz stereo16 PCM, 256 frames / 1024 bytes per packet. Source packet b is
sent at `floor(b*256*1e9/48000)` ns. Presentation starts at 500 ms; downstream
work and submission lead are 1 ms each, uncertainty 0.5 ms. Every strategy has
identical content, source packetization, source times, random seed, channel,
consume_by boundaries and 20 ms/window repair allowance.

`consume_by(b) = presentation(b) - 2.5 ms`; only arrival strictly before it is
on time. The source-trace digest includes each packet's identity, send time,
arrival (or loss), cutoff and duplicate arrival (or absence). Uniform integer
jitter is 0..50 ms, independent loss 1%, channel duplicates occur when the frozen
seeded draw modulo16 is zero and arrive 10 microseconds after the original.
For this seed the duplicate blocks are 14, 48 and 54. Reorder follows arrival
times. The same repair-window/offset channel draw applies to the repair
strategies, with their different actual algorithmic send schedules.

- Plain concealment forwards original arrivals to N04.
- Selective retransmission uses one 32-byte aggregate feedback message/window,
  at most four outstanding requests, one attempt per missing packet, a 20 ms
  feedback round trip and fixed 50 microseconds of virtual dispatch per request.
  The exact same collection, work-ledger and worst-return/slack admission seam
  is used by baseline retransmit and the hybrid tail. Feedback is charged only
  after at least one request is admitted. Declared late availability is included
  in both admission bounds, before spending work or wire bytes.
- Actual RaptorQ uses K4/R4, fixed 1024-byte symbols, the RFC precode/intermediate
  symbols, LT equations and inactivation solve. Four repair packets are encoded
  and sent even with no loss, exposing the 100% payload overhead. One solve per
  affected window; no retry-until-success. This is not N01 XOR parity relabeled.
- Hybrid performs the same actual FEC first, then requests only remaining
  originals through a bounded retransmission tail. Its dispatch costs share the
  same20ms/window ledger with encoding and decoding. A tail uses one aggregate
  feedback message/window, at most four outstanding originals, one attempt per
  original and the same20ms feedback round trip. Admission requires the declared
  worst return delay to fit strictly before that original's cutoff. A refused
  tail changes no work charge, reservation, payload queue, feedback or wire bytes.

Loss is never known before observation. The original collection barrier is the
later of the window end and last original send+2ms+declared maximum jitter.
The FEC collection barrier is last repair send+2ms+declared maximum jitter.
The maximum is50ms in the independent/burst channel and0 otherwise. The two late
fault cases explicitly declare their delayed repair availability barrier, shared
by pure FEC and hybrid. Only symbols observed by that barrier inform a decode or
tail request. The preassembled offline trace is used to deliver later arrivals,
not to select earlier requests or timing. A metamorphic control changes only
future delivery after the same nonempty observable prefix and requires identical
earlier admitted blocks, work starts/finishes and request send times. This calls
`collect_and_plan_window`, the same event-collection/planning seam as `run_model`.
A planted collector that reads future symbols is rejected by that seam before
reservation; the correct collector has a permitted positive path. The planning
boundary receives only events, completed recoveries and declared cost/return
bounds. It returns request send times; channel delivery runs afterward and has
no influence on those decisions. Profile v4 records this seam and uniform
admission correction before any native observation. Source content, channel,
seed, cutoffs and the frozen1ms coding reserve are unchanged.

Encoding and decoding each reserve a fixed 1 ms on the virtual repair worker.
A bounded calendar finds nonoverlapping work intervals; scheduling a far-future
repair never pushes an earlier source window past it. Any guarded inline job
that overlaps `[consume_by, consume_by+work+lead)` is deferred until that
protected interval's half-open end, here cutoff+2ms. This reserves the single
thread through rendering and submission lead, without an extra-core assumption.
A job may start exactly at that end. A due decision runs first. Host elapsed time never
changes a send time, channel loss, virtual completion or output. Host reserve
violations are recorded and fail the case. They do not silently alter the fault
trace. Actual `gauss_ops`, dense-core rows/columns, peeled symbols and pivots
are published separately as deterministic work proxies, not CPU measurements.

N04 admission is authoritative. A decode starts only if its fixed cost fits
the unchanged allowance and can finish strictly before at least one still-live
missing block's cutoff. An already-expired block cannot veto another live
block. Once a repair actually completes, every recovered missing block is
offered to `on_repair`, including expired blocks, so N04 counts Late itself.
Tasks are serviced at the later of their release and the inline worker's busy
interval; decision lateness is therefore measured in the model, not forced to
zero. Each block also publishes the protected render end and actual modeled
service end; every guarded case requires zero decision and render lateness.
A paired counterexample starts repair just after an on-time decision and delays
its render work; protecting only the decision instant fails that control. The causal control
disables both admission and cutoff protection for a planted 600 ms job: block6
becomes muted-overdue. The guarded run refuses that work and keeps block6 real.
A separate 9 ms observed-cost control leaves the burst output unchanged while
recording reserve violations, preventing host-load-dependent headline results.

This comparison is conditional on the frozen schedule and declared observation
barriers. The independent oracle predicts19 missing blocks for plain concealment,
5 for retransmit,17 for pure FEC and1 for hybrid in the burst case. These are not
native measurements or a selected winning policy. Changing virtual coding cost
can move transmitted repair symbols across the burst edge and change outcomes;
the earlier V4 sensitivity calculation used its earlier observation policy.
Host elapsed time never becomes that virtual cost. The1ms reserve is unchanged,
and a red native run must not be repaired by raising it.

The preregistered host recipe is `n05.host-test-o3-d0.v1`: this standalone
manifest sets both `[profile.test]` and `[profile.dev]` to `opt-level=3`,
`debug=0` before the first native observation. Both are specified because Cargo
can build the integration worker through dev while using test for its harness.
Other settings retain Cargo defaults. `build.rs` records Cargo's actual
`OPT_LEVEL`, `DEBUG`, and `PROFILE`; every worker observation carries them and
the recipe ID. The judge requires3/false/debug (Cargo's profile label for this
test/dev recipe), records the observed settings in its receipt, and fails any
different recipe. This is optimized host study code, not an admitted board build.

selects clean, positive recovery, complete-window outage and memory. Missing
proof is blocked (exit3), failures exit1; soak is NOT RUN (exit4). No denominator
shrinks because a binary, status or observation is absent.

The gate itself pairs a permitted finish at cutoff−1 with refusals at cutoff
and cutoff+1, and permits exactly20ms while refusing20ms+1ns without charging
the rejected work. A paired service control shows the unprotected straddling
job delays the cutoff while the protected job does not. The20ms allowance is
93.75% of a21.33ms four-packet window: it is a study accounting cap, not derived
from the bead's25% board execution reserve. That board reserve remains unmeasured.

The Python oracle independently generates source PCM, source trace, concealment
bytes, all strategy output sets, repair counts, fixed virtual charges, airtime
and gap proxies. The two information sets actually decoded by the frozen
headline scenarios are masks252/253; the exhaustive independent differential
probe covers them and every other admitted subset. There is no generic
“at least K packets implies successful FEC” assumption. Each compared case also
plants a byte-hash corruption and requires the oracle to reject it at block0.
No golden regeneration or forced winning policy. Promotion remains none; optional
FEC research and every required native integration remain in scope if no-FEC wins.

The third strategy remains **pure FEC**, retaining its zero-loss overhead and
failure comparisons. The fourth implements **FEC plus optional retransmission**
within remaining slack. Hybrid outcomes, feedback, encoded traffic, virtual work
and actual N04 admission are reported separately; its admitted requests are not
counted as recovered packets. Deadline/work/cancel refusal controls are paired
with permitted tail recovery, same-run next-window recovery and a fresh positive
restart. A separate channel-duplication control retains normal gates, duplicates
actual admitted tail deliveries, and requires32 N04 receipts:16 admitted and16
Duplicate, with unchanged output hashes and sender wire/work. The unenforced
Late control requires2 receipts, both Late, zero played, and a real following
block. The judge requires these nonzero branch observations and their named
Rust status, not a zero-only conservation identity. No policy is promoted before
the actual observations and independent judge.

## Separate measurements and containment

Publish separately: useful real output bytes; original/repair/feedback encoded
wire bytes; equivalent serialization airtime at6Mbit/s; actual encode/decode
host elapsed time; actual child CPU from rusage; deterministic virtual charges
and actual decoder operation counters; repair, decision and render latency; conceal/mute
counts, unrecovered block identities and longest nonreal run. Airtime is
arithmetic, gap counts are proxies, neither radio occupancy nor listening proof.
Packet-arrival handling and decision callbacks remain zero-cost tasks on the
virtual calendar. Whole-process host CPU includes their actual execution, but
arbitrarily long packet handling is not bounded by this model. This remains an
unmeasured endpoint qualification gap; render scheduling here does not prove
board WCET or a bounded implementation of every callback.

`CountingAllocator::measure(decode_window)` includes actual decoder construction,
constraint rows, solve, result construction and temporary drops. It runs over
all163 subsets on the calling thread; the actual path spawns no threads.
Every subset includes actual caller-owned Vec capacities plus cumulative bytes
requested inside the decode, including reallocations at full new size. This
conservatively overestimates simultaneous decoder heap and covers transient
matrices. Actual rank deficit, actual decoder result and independent raptorq
result must agree, with recovered bytes equal to the independent source oracle.
The report keeps every mask and the maximum, and states explicitly if no rank
deficit was observed. Bound remains1MiB; stack, allocator metadata/fragmentation,
mappings, kernel/driver/DMA and external source-oracle storage are excluded.
Whole-study VmHWM is reported separately and is never added to that bound.
The assembled-RHS byte counter alone cannot qualify memory or a32MiB endpoint.

Each isolated Linux worker has1GiB address-space,5s CPU and10s nominal wall
containment. Output is incrementally captured through selectors with a combined
256KiB cap; timeout/overflow kills only its own new-session process group,
including pipe-holding descendants, before reaping. Cleanup wait is bounded
by1s; incomplete cleanup fails. Normal completed PIDs are never signaled after
reaping. There is no unbounded communicate() or second drain. Stderr is bounded,
retained by byte count/hash and shown only through existing Q00 redaction.
Real Python child controls exercise positive capture, stdout/stderr overflow,
parent-exit/descendant-held pipes, timeout recovery and unrelated-process safety.
These host process controls are not firmware cancellation or board WCET proof.

Symbols here are generated offline and assumed authenticated before this codec
seam, just as N04 assumes authenticated input. This study does not apply N01 MAC
to a RaptorQ wire format and makes no authenticated-FEC admission claim. Cheap
actual metadata/size limits precede expensive recovery; N06 still owns any
network-facing authenticated/bounded profile and runtime integration.

## Central execution and evidence

The standalone Cargo integration test uses `CARGO_BIN_EXE_n05_repair_study` to
invoke Python on the RCH host. It emits36 actual strategy observations plus a
restarted worker (37 total), nine diagnostic begin/end pairs and versioned run boundaries.
Observe-only says `qualified=false`, `passed=0`, all12 qualification cases blocked;
its success certifies collection only. The Mac runs only the independent Python
judge, never a Rust worker. The judge rederives observed outputs, requires all
named unit/probe/remote-test statuses from the same Cargo log, and reuses D01/N04
`Logs` binary/section and split-nocapture attribution. A source META check ensures
every named study Rust test has a consumer. Missing/ignored/ambiguous proof blocks;
failed/conflicting/malformed/critical-lost proof cannot pass. Reruns retain earlier
failures; the main production lockfile is not rewritten for this study.

`--locked`; never a main-lock update to admit Asupersync). Explicit dev/test
