# Contract P06 — Portable Franken support-library subsets, slice 1: the readiness and datagram ABI

Bead `ffw-2nw`. Crate: `crates/franken-platform` (`#![forbid(unsafe_code)]`), new file `src/net.rs`. Inputs: P01 (workspace), E06 (inventory),
E03 (kernel ABI matrix). Consumer: P02's platform layer and its Linux leaf, and through them the renderer's control I/O and HAL
(`docs/contracts/p02.md`). Authority: offline engineering and synthetic qualification only; nothing here ran against a kernel, a guest or
a device. The Rust was not compiled or run by its author; the central host test, host clippy and BE check/clippy lines ran green on the landed
bytes (commit 1378365, ffw-2nw closed by independent review).

## What was selected, and why this and not an upstream library

No workspace crate depends on an upstream Franken crate, and none needs one for what the renderer does. The reuse that did happen was
elsewhere: P05 gave the 64-bit atomics (`franken-atomic`), U01 wrote its journal from scratch (`docs/contracts/u01.md`). What the renderer
**does** still lack is the part of P02's "clock, reactor wakeup, socket, memory and entropy" boundary that is neither clock, wakeup nor
entropy: E03 marks `poll` readiness, a UDP socket with truncated-datagram reporting over loopback, and character-device poll as
**Required** on the legacy images, and `docs/contracts/p02.md` leaves them out ("no code exists"). They are also the primitives where
"remove the architecture `compile_error` and rebuild" is wrong in a way that builds and passes on a laptop: on MIPS `SOCK_DGRAM` is `1`
and `SOCK_STREAM` is `2` (PowerPC the reverse), `SOCK_NONBLOCK` is `0x80` (PowerPC `0x800`), `SOL_SOCKET` is `0xffff` (PowerPC `1`), every socket option moves,
`POLLWRNORM` and `POLLWRBAND` move, and all ten network errnos move.

So the selected primitive is this ABI core, written for the two admitted ABIs, with its witnesses outside the Rust. The upstream
libraries are recorded in `tests/p06/ledger.json`, each with its exact revision, its disposition, the test that holds it and when the row goes away:

| Upstream | Revisions | Disposition |
|---|---|---|
| Asupersync (and `franken_kernel`, a directory of the same repository) | `8940119023c0…` (the workspace pin: E06's inventory and P05's scan) and `ddda2bf82cc8…` (what the assessment read; an ancestor, so superseded, not a second pin) | referenced, not consumed here; the legacy-runtime route is P05's. `franken_kernel` is the suite's identifier substrate (`TraceId`, `DecisionId`, …), not a task or budget type, and its manifest keeps serde's default `std` on at the pin |
| FrankenLibC | `76d7f3469f5f…` (E06's pin) and `a77173e433d6…` (the assessment's; an ancestor) | **semantic reference, rejected as a source of ABI numbers**: its errno module is the generic numbering with a thread-local cell; nine of the ten network errnos are defined and all nine are PowerPC's number and not MIPS's |
| frankenfs | `da7bbffaabcc…` (the assessment's) | not selected: no raw-flash or filesystem support is claimed; U01 is from scratch |
| franken_remote | `873f4827355d…` (the assessment's) | not selected: leases, epochs and fencing are native (G01, N02); LocalAPI delegation is not native Tailscale and nothing claims it |

A row is a check, not a report: `tests/p06/test_ledger.py` fails when a recorded revision does not resolve, when a claimed ancestry is
false, when the recorded upstream bytes (the errno table; the `serde` line) are no longer what the reason says, or when a lock entry or a
platform manifest names a crate the ledger says is not selected (`asupersync`, `franken-kernel`, `frankenlibc-*`, `ffs-*`, `fr-*`; `libc`
as a direct dependency of the platform crates).

## What is here (`src/net.rs`)

Pure, safe, stateless: no call is issued, no clock is read, no `errno` cell exists. A failure arrives in-band as `-errno` and is decoded by
`Abi::decode` (`src/abi.rs`).

| Piece | What it is |
|---|---|
| Numbers | `Abi::sock_type`, `socket_type_arg` (the kind with `SOCK_NONBLOCK|SOCK_CLOEXEC` set by the call itself, never afterwards by `fcntl`), `sol_socket`, `sockopt` (the **32-bit** timeout options, never the 64-bit `_NEW` ones, which need Linux 5.1), `pollwrnorm`, `pollwrband`, `poll_known_bits`; the common `AF_*`, `MSG_*` and `POLL*` |
| Network errno | `NetErrno` (ten), `number(abi)`, `Abi::classify_net_errno`, `net_errno_of`: a number names a network error on at most one ABI |
| Layouts, all big-endian | `PollFd` (8 bytes), `SockAddrIn` (16), `SockAddrIn6` (28), `Timeval32` (8); a read-back of the wrong length, family or padding is refused |
| Time widths | `Timeval32::from_duration`: 32-bit seconds and microseconds, rounded up, **zero refused** (the kernel reads it as "never time out"; `FOREVER` is asked for by name), seconds past 32 bits **refused, not truncated**, and seconds above `TIMEVAL_MAX_FINITE_SEC` (2 147 481) refused too, because the kernel's own `sock_set_timeout` reads `tv_sec >= LONG_MAX/HZ - 1` as "no timeout"; `PollTimeout`: an `int` of milliseconds in which `0` and `-1` are separate cases, rounded up, a value above `POLL_MAX_FINITE_MS` (2 147 482) refused, because the stock 2.6.14 `sys_poll` reads `timeout >= LONG_MAX/HZ` as forever (a public `Millis` above it is clamped to it by `to_raw`, never passed on) |
| `poll` | `PollFd::request` (no negative descriptor, no output-only bit, no bit outside the ABI's set), `decode_poll` (a count above the request is not believed), `PollFd::ready` (a ready bit outside the ABI's set is not believed), `poll_retrying` |
| Interruption model | `poll_retrying` retries an `EINTR` with the time **left** of the timeout (measured by a caller-supplied elapsed time, so no clock is read here), never with the whole timeout; bounded by `MAX_INTERRUPTED_ATTEMPTS`; a judge in the tests tells it from a naive repeat of the same call. This tested utility remains available; it is not the P03 runtime wait policy, whose admitted `PlatformLayer::wait_once` delegates to `wait::poll_once` and returns interruptions to its owner without retry. |
| Datagrams | `RECV_FLAGS` (`MSG_TRUNC`, always), `decode_datagram` → `Complete { len }` or `Truncated { stored, real }`: the E03 loopback fact (24 bytes into a 16-byte buffer returns 24) is a truncation; a length above 65527 (the 16-bit IPv6 payload length minus the 8-byte UDP header) is refused |

## What is not here

* **No syscall wrapper and no `KernelOps` method in this slice.** Its helpers remain safe ABI representations and models. Separate leaf socket/datagram wrappers now exist, and P02's `wait_route` and `sys::poll` route one raw call through `WaitOps`; `wait::poll_once` validates its inputs and answer. Those additions do not execute `net::poll_retrying` or qualify a renderer, guest kernel or device; see `p02.md` for the execution boundary and its evidence limits.
* **Raw `socket` on a stock PowerPC kernel.** The E03 probe issues `socket` as syscall 326 on the 4.9 harness guest. YellowBrook's reading of the kernel's own `unistd.h` (mail 6266, not reproduced in this repository)
  is that PowerPC has **no direct socket calls at 2.6.14 or 2.6.35** (`socketcall` 102, `poll` 167; `socket` 326 belongs to a later kernel), so a stock-PowerPC leaf must use `socketcall` (`SYS_SOCKET` 1,
  `SYS_RECVFROM` 12, `SYS_SETSOCKOPT` 14, arguments as an array of words), and that MIPS o32 has direct calls at both versions (`socket` 4183, `recvfrom` 4176, `setsockopt` 4181, `poll` 4188, `socketcall` 4102).
  No stock-kernel guest has run any of this; the leaf must settle it with a matching guest before a raw wrapper is written. The std/musl path is unaffected.
* **`SOCK_NONBLOCK`/`SOCK_CLOEXEC` in `type` need Linux 2.6.27.** `Abi::socket_type_arg` builds the modern call. On the stock PowerPC 2.6.14 kernel `socket` takes no flags and answers `-EINVAL` for them, and the only
  alternative (`fcntl` afterwards) is the race the E03 `accept4` row exists to avoid. The E03 guests (4.9, 4.19) are above the floor. Choosing by kernel version is the leaf's decision, not this module's.
* **No accept/`fcntl` policy.** `accept4` stays as `docs/contracts/p02.md` documents it.
* **No TLS, threads or futex.** E03 observes them as optional; this slice neither needs nor tests them. The one TLS fact is negative: FrankenLibC's `errno`
  is thread-local and this layer's is in-band, which is part of why nothing is taken from it.
* **No claim about any device, stock kernel, provider, or the retained audio driver's readiness.**

## Evidence and how to run it

`scripts/e2e/p06` runs `tests/p06/run_cases.py` and prints the central plan. The Python cases in `tests/p06/` are mapped to invariants by `tests/p06/cases.json`
(net), `tests/p06/test_durable.py` (durable) and `tests/p06/test_runner.py` (the runner); the exact denominator is what `--list --tier T` prints and what the
totals line reports. Tiers: `--tier smoke` runs the cases that read only this repository; `--tier full` (the default) adds the cases that need an upstream clone or
the `libc` crate's files; `--tier soak` is **not supported** (the acceptance names no soak requirement, there is nothing long-running to soak): it runs nothing,
reports one blocked case (`P06-SOAK`) and exits 3. A case that cannot run is **BLOCKED** and exits 3; a mandatory test module that contributes no case is a
blocked case too. None is ever a pass.

Every run writes its own bounded, redacted diagnostic log (`ff.diag.v1` JSONL, through the shared Q00 sink and the accepted D01/D03 adapter pattern in
`tests/p06/case_log.py`): a critical begin and end per decided case and a run summary. A pass cannot rest on a log that lost critical evidence (exit 1). With
`--receipts DIR` the log and a JSON receipt (`ffw.p06-receipt.v1`: tier, per-case results, versions, the sha256 of every judged artifact, the replay command) are kept
under `DIR`, created exclusively so a rerun never overwrites the first run's evidence. A run that is not a pass prints its first failing (or blocked) case with its
cause and the exact replay command (`--only CASE_ID`). Exit codes: 0 pass, 1 failed or evidence lost, 2 usage, 3 not qualified.
The expected values are hand-written (`crates/franken-platform/tests/vectors/p06_net_abi.json`) and are held by:

1. an independent restatement of every layout and decoder in Python (`struct.pack`, the ceilings, the retry arithmetic),
2. the E03 guest probe source (`toolchain/src/ffw-hello-init/src/main.rs`: `O_NONBLOCK`, `SOCK_DGRAM`, the `PollFd` shape, `NR_POLL`),
3. the `libc` crate's per-architecture files (every socket, option, poll, message and errno number), found in the local registry cache; the version used is the newest cached one that has the files (0.2.191, which is the locked version, when this was written),
4. the Rust text itself (the `match` arms are parsed and compared), so the unit tests cannot be edited around without a Python case failing,
5. planted wrong numbers in each source, each required to be reported, after the unplanted comparison is required to be clean.

A second reading of the constants against the Linux headers at v2.6.14 and v2.6.35 was made by YellowBrook (mail 6266): the ten network errnos, `SOL_SOCKET`, every option number, the socket types, `O_NONBLOCK`, the poll bits and `MSG_*` agree; it also found the two "forever" thresholds and the `type`-flag floor above, which are in this version. That reading is not reproducible from this repository.

The Rust unit tests (`net::tests`, 25) replay the same vectors. **Not run by the author:** `cargo test`, clippy and the device-target type checks are the supervisor's
central lines (`scripts/e2e/p06 --plan`). Expected: the 25 `net::` tests pass in `-p franken-platform`, clippy `-D warnings` is clean for the host and both BE targets,
and no existing franken-platform test changes.

## Slice A1: the durable-file ABI core (`src/durable.rs`)

Helper slice under the bead owner. **Consumer:** `franken_journal::Storage` (`read`/`program`/`erase`/`sync`, `crates/franken-journal/src/storage.rs`), which has no backing on
the legacy images (`docs/contracts/u01.md`: "P02: the real `Storage` over the board's flash or a file"; today only `examples/journal_crash.rs` backs it, with `std::fs`).
E03 marks "filesystem sync and atomic rename (write, `fsync`, rename over an existing file, read back, old name gone)" **Required**: observed on both guests, unqualified on the
stock kernels. **What is claimed: a bounded POSIX-file semantic. Not raw flash, not a generic filesystem, and not that a rename is durable** (E03 does not observe syncing the
containing directory, so neither the judge nor this document does).

Pure, safe, stateless, like `net.rs`: no call is issued. The syscall numbers, `KernelOps` methods and leaf wrappers are P02's (see "What A1 leaves to P02").

| Piece | What it is |
|---|---|
| Open flags | `OpenFlag::value(abi)` for `O_CREAT`, `O_EXCL`, `O_APPEND`, `O_DSYNC`, `O_SYNC`, `O_DIRECTORY`, `O_NOFOLLOW`, `O_LARGEFILE`; `O_RDONLY`, `O_WRONLY`, `O_RDWR`, `O_TRUNC`, `O_CLOEXEC` are common; `O_NONBLOCK` is `Abi::o_nonblock`. They differ in a dangerous way: PowerPC `O_APPEND` is MIPS `O_EXCL` (`0x400`), and PowerPC `O_LARGEFILE` is MIPS `O_DIRECTORY` (`0x10000`) |
| `OpenRequest::flags(abi)` | builds the argument, or refuses: `O_TRUNC`/`O_APPEND`/a sync flag on a read-only open, and `O_DIRECTORY` combined with write access, create, truncate, append or sync. `allows_positioned_write()` is false for an append open: **Linux ignores the offset of a positioned write on an `O_APPEND` descriptor** (`generic_write_checks`: `*pos = i_size_read(inode)`, 2.6.14 and 2.6.35), so `Storage::program` must not open that way |
| File errno | `FileErrno` (24): sixteen are the same on both ABIs; eight differ (`EDEADLK`, `ENAMETOOLONG`, `ENOLCK`, `ENOTEMPTY`, `ELOOP`, `EOVERFLOW`, `ESTALE`, `EDQUOT`). A number names at most one error per ABI and none is `EINTR`/`EAGAIN`/`EINVAL`/`ENOSYS`; MIPS `ELOOP` is `90`, which is PowerPC `EMSGSIZE`. An errno outside the 24 is kept as `Unknown(n)`, never reinterpreted |
| Decoders | `decode_open` (descriptor, or why not; past `i32` refused), `decode_write` (**a short write is neither success nor a fault**: `Full`, `Partial { written }`, `NoProgress` for `0` on a nonempty request, `OverReported`), `decode_unit` (`rename`, `unlink`, `ftruncate`, `close`: `0` or an error; a count is refused), `decode_fsync` (as `decode_unit`; `EINVAL` is `NotSyncable`; `EIO`/`ENOSPC`/`EDQUOT` are `SyncFailed`, **final**) |
| 64-bit offsets | `FileOffset`: a non-negative `i64` as big-endian words `(hi, lo)`, never wrapped or truncated; `positioned_tail()` = `[0, hi, lo]`, the three words after `(fd, buf, count)` in `pread64`/`pwrite64`; `to_i32()` refuses past `i32::MAX`; `from_llseek_result` reads the eight big-endian bytes `_llseek` stores and refuses a set sign bit |
| E03 sequence | `judge_replace_sequence`: write (whole), `fsync`, rename, read back, old name gone (`-ENOENT`), **in that order**; names the first missing, misplaced, failed or wrong step. `fsync` before the rename is the point |

**Kernel facts, read from the sources and not observed on a running kernel** (files and sha256 are in the vector file's `witnesses`; headers and sources fetched from the `v2.6.14`,
`v2.6.22`/`23`, `v2.6.32`/`33` and `v2.6.35` tags):

* `O_CLOEXEC` first appears in **2.6.23** (absent from 2.6.22's `asm-generic/fcntl.h`). `fs/open.c` at 2.6.14 passes the flags to the file unvalidated, so on the stock PowerPC
  2.6.14 kernel `open(O_CLOEXEC)` **succeeds and the descriptor is not close-on-exec**, silently. `cloexec_is_honored(release)` says which side of the line a release is.
* `O_DSYNC` is a separate flag from **2.6.33**, and `O_SYNC` changes value then (PowerPC `0x1000` to `0x101000`, MIPS `0x10` to `0x4010`). This module uses the 2.6.33 numbers: on an
  older kernel the new `O_DSYNC` is the old `O_SYNC` bit (a full sync, never a weaker one) and the extra bit of the new `O_SYNC` is not assigned to anything there, so one argument serves both.
* `fsync` reports a writeback error **once**: `filemap_fdatawait` does `test_and_clear_bit(AS_ENOSPC)`/`(AS_EIO)` (2.6.14 and 2.6.35). A second `fsync` after a failure can
  return `0` over data that is not on the medium, which is why `SyncFailed` is final. `do_fsync` returns `-EINVAL` when the file has no sync operation.
* `rename` returns `-EXDEV` when the two paths are on different mounts (`fs/namei.c`, 2.6.14 and 2.6.35).
* **`pread64`/`pwrite64` take six argument slots** on both ABIs: `(fd, buf, count, pad, hi, lo)`. 32-bit PowerPC: `compat_sys_pread64(fd, ubuf, count, reg6, poshi, poslo)`
  (`arch/powerpc/kernel/sys_ppc32.c`); MIPS o32: `sys pread64 6` in `scall32-o32.S`. Word order for MIPS o32 is the o32 rule (the most significant word in the lower slot on big-endian), not a
  line in a kernel file I read.

## What A1 leaves to P02

* **The syscall numbers, the `KernelOps` methods (the layer, both doubles, the leaf and the speaker's `Fake`) and the wrappers.** They move the unsafe inventory in `sys.rs`.
* **A gap to settle there:** `franken-platform-linux`'s trampoline carries **five** arguments, and `pread64`/`pwrite64` need six. The options are a six-argument trampoline, or
  `_llseek` (five arguments: `fd, hi, lo, &result, whence`; the result is a `loff_t` stored through a pointer, which `FileOffset::from_llseek_result` reads) followed by `read`/`write`,
  which is not atomic against another thread and is acceptable only for a single-threaded owner. `ftruncate64` takes four on MIPS and a pad word on PowerPC.
* **Whether `O_CLOEXEC` is honoured** on a given image (see above) and whether the stock images have the E03 behaviours at all: every stock cell is still unqualified.
* **A directory `fsync`** after the rename, which no one has observed.
* **The `Storage` adapter itself (A2)**: it needs a path edge from `franken-platform` to `franken-journal`, which changes `Cargo.lock` and so stales the lock-bound E06 and central records.
  It is not part of A1.

## Applicability: the syscall, TLS and target facets, and the consumer matrix

The bead asks for "BE layout, errno, time-width, syscall/TLS and target tests as applicable" and for genuine inapplicability to be explained. Earlier
text in this contract said the syscall facet was "not applicable to this slice" and "waits on P02". That was too coarse; this section replaces it
and nothing here is a waiver.

**Syscall.** For the selected primitives a syscall test can mean four different things:

| | What it is | Status |
|---|---|---|
| S1 | The call's argument and return conventions: the constants, the BE structures, the errno decode, the time and offset widths | **Applicable, tested** (net: v2 vectors; durable: A1 vectors). Host unit tests plus an independent Python model and the libc-crate and kernel-header witnesses. |
| S2 | The call executed on a legacy guest | The E03 probe issued `socket`/`poll`/UDP loopback/`pipe2` as raw syscalls on both guests and recorded `UDP_LOOPBACK rc=24` and `FS_RENAME rc=0` (run `1412ac47`, MIPS and PowerPC). The net decoder test replays the 24-byte datagram read into a 16-byte buffer. The transcript carries the judged `rc` of the file sequence, not each step's raw return, so the durable judge models the order E03 describes and does not replay raw values. Nothing was run on a stock kernel. |
| S3 | The call numbers and slot counts of the calls these primitives are used with, per ABI | **Actual P02 work, not a P06 condition** (P06 code issues no call and holds no call number). The pure argument-layout vectors stay applicable P06 tests: `FileOffset::positioned_tail` gives `[pad0, hi, lo]` after `(fd, buf, count)`, and its six-slot and word-order vectors are S1 above. The audited `Numbers` table (`crates/franken-platform-linux/src/numbers.rs`) covers seven calls (`getrandom`, `eventfd2`, `pipe2`, `open`, `read`, `write`, `close`) and none of `poll`, `socket`/`socketcall`, `setsockopt`, `recvfrom`/`recv`, `fsync`, `rename`, `unlink`, `_llseek`, `pread64`, `pwrite64`. This is pure data: it is supplied as table rows and rows in `tests/p02/test_syscall_numbers.py` (three witnesses each: the E03 probe where it issued the call, the libc crate's musl tables, the kernel's `unistd.h`), with the slot count of each call recorded because the leaf trampoline carries five (`recvfrom`, `pread64` and `pwrite64` need six). It needs no wrapper, no `KernelOps` method and no `unsafe`. The rows, their delivery through a real six-argument trampoline and the kernel effects remain P02's acceptance; the pure helper does not establish them. |
| S4 | The leaf issuing the call: the wrapper, the trampoline, the `KernelOps` method, the answer to an absent syscall | **Not a selected P06 primitive.** No upstream syscall wrapper was selected (FrankenLibC's `syscall` module has code for `x86_64` and `aarch64` only; the ledger rejects it). The leaf's trampolines are P02's native, audited code, and their tests are P02's acceptance ("no fake syscall success; test absent syscalls"). P06 claims nothing about S4. |

**TLS** in the original legacy-ABI criterion means thread-local storage: the embedded plan's §4 says "thread creation and thread-local storage, if
threads are required".
* *Thread-local storage and its layout* (an `errno` cell, the thread pointer, the TCB offset): no selected primitive uses it. Failures arrive in-band as `-errno`. `the_source_has_no_thread_local…` (net) and `the_source_has_no_unsafe…` (durable) fail if a `thread_local` appears in the code, and `P06-ORACLE-001` records why FrankenLibC's thread-local `errno` is not consumed. E03's TLS probe results are E03's.
* *Network TLS authentication* (Tailscale, Spotify, AirPlay, HTTPS) is not a second meaning of this criterion and not a P06 criterion. It stays required in its own service-integration scope: `franken_remote` is not selected, and the native adapters own that path (T04, X05, Q06).

**Target.** The target tests are the type-check and clippy lines for `mips-unknown-linux-musl` and `powerpc-unknown-linux-musl` in `scripts/e2e/p06 --plan`.
They are compile-level only. Executing the unit tests on a big-endian target is an optional experiment that was **not run and is not claimed**; it
is not a P06 condition, and no guest or stock-kernel qualification is claimed. Running it would need a worker with user-mode QEMU
(`qemu-mips`, `qemu-ppc`) as the `cargo test --target` runner, or a guest run. The code uses explicit big-endian conversions, but that is a reason
the host result is informative, not a substitute for the run.

tombstones to N02, and their journal- and tombstone-specific malformed-input cases are those beads' tests. That is non-applicability from the absence
of the selected algorithm, not an omission, and it is not a blanket exemption for parser negatives: net's byte-layout decoders are selected parsers,
and their malformed inputs are tested (a `sockaddr_in` of the wrong length, family or padding; ready bits outside the ABI's set; an impossible poll
count; a `timeval` that is not a time), as are durable's negative and overflowing offsets, a negative `_llseek` result and impossible returns. "Downstream compatibility matrix at pinned revisions … reject accidental host-only dependencies" is `tests/p06/ledger.json` (pins resolve,
ancestry holds, the recorded upstream bytes are still true) with `P06-ISO-001` (no unselected upstream crate in the lock and no `libc` dependency),
plus the BE-target builds, which fail on a `std` or host-only dependency.

**The finite list P06 is judged on** (decided by the original acceptance, not by what was later built):
1. the `net::` and `durable::` unit tests, and the whole `franken-platform` test, on the final `net.rs` bytes (39 and 147 at the first run);
2. clippy `-D warnings` on the host and on both BE targets, and `check` on both;
3. `scripts/e2e/p06`: the Python cases (pins, ledger, isolation, the independent model, the witnesses);
4. the six-slot argument and word-order vectors of the positioned calls (S1), inside item 1; the call-number rows (S3) are actual P02 work and
   not a condition here;
5. the P01 contract row for `tests/p06`, landed with the slice;
6. the BE target lines are those of item 2; executing the unit tests on a BE target is an optional experiment, reported as not run, with no
   runtime claim, and not a condition.

**Not conditions of P06:** A2; any syscall wrapper, allocator, socket or `accept4` (P02 keeps all of them); stream sockets; any FrankenLibC or
frankenfs extraction. They have no selected consumer here, so they are not part of this bead's acceptance.

## Known limits

* The selected primitives are the readiness and datagram ABI core and the durable-file ABI core. Stream sockets and `accept4`, the allocator and memory-budget primitives, and any
  extraction from FrankenLibC (`inet` text parsing, for example) or FrankenFS were **not selected**: nothing consumes them, P02 keeps the socket, allocator and syscall
  obligations, and they are not conditions of this bead (see "Applicability").
* The constants are those of the **musl 32-bit MIPS and PowerPC** `libc` files and the E03 probe. A `-gnu` target or a kernel with different values would need its own row.
* `poll_retrying` rounds the remaining time up to a millisecond, so a retried wait can end up to one millisecond late and never early.
