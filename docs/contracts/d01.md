# D01 contract: fixed-size audio blocks and conversion (`ffw-f3b`)

Scope: canonical stream format descriptors, channel layouts and strides, bit-exact sample
conversion, saturation and non-finite policy, and a bounded SPSC ring with no allocation on the
render path. Code: `crates/franken-dsp/src/{format,convert,ring}.rs`. Offline and host-only;
nothing here is measured on a Sonos board. Verification status lives on the bead, not in this file.

## Formats

| `SampleFormat` | Bytes | Significant bits | Notes |
|---|---|---|---|
| `S16` | 2 | 16 | two's complement |
| `S24In32` | 4 | 24 | right-justified in a 4-byte container. Writers sign-extend into the top byte; readers ignore the top byte and sign-extend bit 23 |
| `S32` | 4 | 32 | two's complement |
| `F32` | 4 | n/a | IEEE-754 binary32, nominal full scale `[-1.0, 1.0]` |

`Endian` (`Big`, `Little`) is explicit on every `StreamFormat` and independent of the host CPU.
`StreamFormat { sample_format, endian, channels 1..=16, sample_rate 8 000..=384 000 Hz }` exposes
`bytes_per_sample()` and `bytes_per_frame() = channels * bytes_per_sample` (at most 64).
`CANONICAL_WIRE_FORMAT` is big-endian `S16`, stereo, 48 kHz (the existing stream payload).

## Layouts and strides (`BufferSpec`)

* Interleaved: sample `(frame, ch)` at `frame * stride + ch * bps`; `stride >= bytes_per_frame`;
  padding between frames is never written. `required_len(n) = (n-1) * stride + bytes_per_frame`.
* Planar: sample at `ch * stride + frame * bps`; `stride >= bps` at construction and
  `stride >= n * bps` for every block of `n` frames (planes may not overlap).
  `required_len(n) = (channels-1) * stride + n * bps`.
* `stride <= 1 MiB`. All offset and length arithmetic is checked (`LengthOverflow`).

## Conversion rules (`convert_block`, `convert_packed`)

| From -> to | Rule |
|---|---|
| int -> wider int | left shift (zero fill); exactly reversible |
| int -> narrower int | `(v + 2^(shift-1)) >> shift` (round half up), then saturate |
| int -> `F32` | `v / 2^(bits-1)` in `f64`, rounded once to `f32` (nearest-even) |
| `F32` -> int | non-finite -> 0; else `round_ties_even(x * 2^(bits-1))` in `f64`, saturate to `[-2^(bits-1), 2^(bits-1)-1]` |
| `F32` -> `F32` | non-finite -> `+0.0`; finite clamps to `[-1.0, 1.0]`; `-0.0` and subnormals pass bit-for-bit |

Consequences: `+1.0` saturates to the largest code, `-1.0` is exactly the smallest, and every one of
the 65 536 `S16` values round-trips through `S24In32`, `S32` and `F32` unchanged. NaN and +/-inf
become silence, never full scale. Saturations and flushed non-finite samples are counted per block in
`ConvertStats { saturated, non_finite }`; there are no per-sample logs. `convert_block` never mixes
channels or resamples: channel counts and sample rates must match.

**Scale change (D01).** `i16_to_unit_f32` / `unit_f32_to_i16` in `franken-dsp` previously used a
`/ 32767` scale in which `-32768` became `-1.0` and came back as `-32767`. They now delegate to the
rules above (`/ 32768`). Results differ by at most 1 LSB; signatures and `StereoAudioBlock`'s
`from/to_be_i16_bytes` are unchanged. Approved by the orchestrator (message 3460).

## Block lengths and errors

Packed block length is checked in this order: zero -> `EmptyBlock`; not a multiple of
`bytes_per_frame` -> `MisalignedBlock`; more than 256 frames -> `BlockTooLarge`. Exactly 256 frames and
any shorter final partial block are accepted. `convert_block` checks, in order: frames (zero, >256),
channel count, sample rate, `required_len` of source then destination, then buffer lengths. Errors are
`Copy` values (`PcmError`) with stable names from `PcmError::code()`: `empty_block`, `block_too_large`,
`misaligned_block`, `invalid_channels`, `invalid_sample_rate`, `stride_too_small`, `stride_too_large`,
`channel_mismatch`, `sample_rate_mismatch`, `buffer_too_small`, `length_overflow`,
`invalid_ring_capacity`, `ring_full`, `ring_underrun`. On any error the destination is untouched.

## Ring and sink (`ring_channel`, `BoundedCaptureSink`)

* `ring_channel(format, capacity_frames 1..=65 536)` allocates once and returns a `RingProducer` and a
  `RingConsumer` (neither `Clone`, so single producer and single consumer are enforced by the types).
* Safe code only: byte slots are `AtomicU8`; head/tail publish with `Release` and are read with
  `Acquire`. Positions live in `[0, 2*capacity)`, so occupancy is `(tail + 2c - head) % 2c` for any
  capacity and a counter wrap cannot become a buffer index.
* `push`/`pop` are all-or-nothing and take the block size from the slice length. Full -> `ring_full`
  (counted in `overruns()`); too few frames -> `ring_underrun` (counted in `underruns()`); a block larger
  than the whole ring -> `block_too_large` with the capacity as `max`, which is not counted as an overrun.
* `BoundedCaptureSink` reserves its capacity at construction; `write_block` rejects empty blocks and
  overflow without partial effect.

## No allocation on the render path

`crates/franken-alloc-probe` holds the workspace's only `unsafe`: one `unsafe impl GlobalAlloc` that
forwards unchanged to `System` and bumps per-thread, destructor-free counters. It is a probe, not a
dependency of any firmware crate. Its test binary asserts the counter is installed and counts (positive
control, growth control), then runs convert -> ring -> convert -> sink over 2 597 frames plus every typed
error path inside `measure` and requires zero `alloc`/`realloc`/`dealloc` calls, and checks the output
bytes. Construction (`ring_channel`, `with_capacity`) is shown to allocate, which is where allocation
belongs. Counters are per thread; other threads are not measured.

## Running and evidence boundary

```
RCH_REQUIRE_REMOTE=1 rch exec -- cargo test -p franken-dsp -- --nocapture   > dsp.log
RCH_REQUIRE_REMOTE=1 rch exec -- cargo test -p franken-alloc-probe          > probe.log
scripts/e2e/d01 --tier full --judge dsp.log probe.log [--receipts DIR]
```

The judge compares each `D01-OBSERVED` line with the Python reference and reports the first divergent
frame, channel and format. A case or required Rust test with no observation is `blocked` (exit 3) and the
run is NOT QUALIFIED; blocked is never counted as passed.

Log shape. Through RCH the `Running ...` header lines (stderr) and the `running N tests` ...
`test result:` sections (stdout) arrive as separate streams, so a test is not under its own header. Both
streams keep cargo's execution order, so the n-th header (a `Running` or `Doc-tests` line) is paired with
the n-th section, but only when the counts match and every section holds the tests it declared. Otherwise
tests are matched by exact name, and a name seen in more than one section is ambiguous and stays blocked.
A test printed under another binary is not credited to the required one. Repeated inputs never change the
denominator: a log with the same sha256 is read once, an identical repeated observation is ignored, and a
conflicting one fails its own case without adding a case. The reference's hand-computed anchors
(`tests/d01/anchors.py`) are the same literals asserted by the Rust unit tests; the Python and Rust sides
share no code. Limits: host-only synthetic PCM; no board CPU or timing measurements (the `f64`
intermediates were chosen for exactness, their cost on the MIPS and PowerPC targets is not measured);
byte-granular atomic ring throughput is not measured; no dither, channel mixing or resampling (D02, D03).
