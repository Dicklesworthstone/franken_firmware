# Contract P02 — Minimal legacy platform capability layer

Bead `ffw-jub`. Crate: `crates/franken-platform` (`#![forbid(unsafe_code)]`). Inputs: P01 (workspace), E03 (kernel ABI matrix),
P06 (upstream subset selection). Authority: offline engineering and synthetic qualification only. Startup has run on the named QEMU harness kernels;
socket syscall execution, stock kernels and physical devices remain unqualified.

## What this slice is, and is not
**In:** the policy layer for three capabilities (monotonic clock, reactor wakeup, secure entropy), the per-ABI decoding of the raw
kernel return convention, the admission gate that builds the layer, the test doubles that drive it, the Linux backend as a separate
leaf crate (`franken-platform-linux`, "The real backend"), the device speaker's startup over it ("The device speaker's startup"), and
the socket capability's seam and policy ("The socket capability": `socket.rs`, and the route plan in the leaf's `numbers.rs`;
host-tested; kernel socket execution unqualified), and the leaf's socket backend (`SocketKernel`, `socket_route.rs` and five wrappers in `sys.rs`; host-tested; kernel socket execution unqualified).
**Not in:** a socket call that any kernel has answered (no guest has issued a `socketcall`),
a `uname` read of the kernel release (the caller supplies it), the socket calls in `PlatformLayer` (`layer.rs` has no socket method and no admission check for them), a datagram sender's address
(`recvfrom`) and the peer address of an accepted connection, a runtime memory ledger beyond the E03 budget type that already lives in
`lib.rs`, and any stock-kernel or physical-device qualification.
Nothing is claimed for stock kernels: every stock cell in E03 stays unqualified.

## The seam
`KernelOps` has one method per call the layer issues (a monotonic reading, `getrandom`, `open_dev_random`, `eventfd2`, `pipe2`, `write`,
`read`, `close`) and returns **exactly what the backend got**: a non-negative result, or `-errno`. The policy in
`clock`, `entropy` and `wake` decodes that with `Abi::decode`, so a backend never decides that a failure was fine.

What a backend must declare, with no default: `provenance()` (`Kernel` or `Simulated`) and `backend_abi()` (the ABI a real
backend was compiled for; `None` for a double). `PlatformLayer::admit` refuses a backend whose ABI differs from the profile's
(`LayerError::AbiMismatch`) before any kernel call, because the errno numbers and flag values the layer decodes with are the
profile's and the numbers the backend issues are its own. `PlatformLayer::provenance()` carries the answer to the layer's owner;
anything a caller records about what a layer produced should carry it.

What a backend must guarantee (a duty of every future backend, tested by none today because none exists):
* **No emulation.** A call the kernel lacks returns the kernel's `-ENOSYS`; it is not rebuilt from other calls. A libc shim that
  answers `getrandom` with `/dev/urandom`, `accept4` with `accept` plus `fcntl`, `eventfd` with a pipe, or `clock_gettime` with
  `gettimeofday` is exactly the substitution this contract forbids. The seam has no `gettimeofday`, `accept` or `fcntl` method and
  **no general `open`**: `open_dev_random(flags)` takes no path and opens the one constant `/dev/random`, so `/dev/urandom` and any
  other file cannot be written against it (a source test pins that the leaf has exactly one byte-string path literal).
* **Error convention.** A failure is `-errno`. MIPS o32 reports errors with a flag register and a positive errno in `v0`; its
  backend converts, and the E03 `ERR_ENOSYS` calibration line (the guest's own `ENOSYS` equals the table) is how a run proves it did.
* **Monotonic time.** A `Timespec` carries a monotonic reading whose epoch is the backend's (see "Monotonic clock"). The layer
  validates the fields and the monotonic guard catches a reading that goes backwards.

## Decoding (`abi.rs`)
* A non-negative value is a result. A value in `-4095..=-1` is an errno. **Any other negative value is `SysError::Malformed`**: it
  is never coerced to success or to a guessed errno.
* `-ENOSYS` means "the call does not exist" **only with the guest ABI's own number** (38 PowerPC, 89 MIPS). The other ABI's number
  is an ordinary errno there. The decision is the E03 oracle's (`tests/e03/abi.py`), reproduced here and cross-checked.
* **`EINVAL` is not absence.** A call that exists and rejected its arguments is a different fact from a call that does not exist
  (see "Accept and fcntl" for why it matters).
* `EINTR` is repeated at most `MAX_INTERRUPTED_ATTEMPTS` (8) times per logical call and then **reported**, not swallowed and not
  turned into success. **`close` is the exception: it is issued once.** On Linux a `close` that answers `EINTR` has already released
  the descriptor; a second call could close an unrelated descriptor another thread was just handed under the same number. The error
  is reported as the kernel returned it and the descriptor is treated as gone.
* `EAGAIN` is never retried here: it is `WouldBlock`, and each capability says what it means.
* The numbers are in `tests/vectors/p02_errno.json`, generated from the oracle. A unit test holds `abi.rs` to the file, and
  `tests/p02` holds the file to the oracle, to the table text in `abi.rs` and (when the registry has it) to the `libc` crate. Only
  `ENOSYS`, `ENOENT` and `EBADF` are also seen in a committed QEMU transcript; the rest are Linux uapi header facts.

## Admission (`layer.rs`, `lib.rs`)
`PlatformLayer::admit(&matrix, ops)` starts with `KernelCapabilityMatrix::check_admission`. A profile with no matching full-system
guest, or with a required capability not observed `Supported`, is refused **before any kernel call**. The same holds for a triple
that is not one of the two legacy ABIs (`UnknownAbi`) and for a backend of the other ABI (`AbiMismatch`). The ABI is read from the
matrix's own target triple, never passed separately. Only then is the admitted wake mechanism opened. The matrix gained
`getrandom_syscall` and the status `ObservedUnseeded` (E03's `GETRANDOM` `UNSEEDED`: the call exists and answered `-EAGAIN`); the
status is meaningful for that one field and fails `check_admission` anywhere else.

## Capabilities
### Monotonic clock (`clock.rs`)
`CLOCK_MONOTONIC` only. **There is no wall-clock path**: `KernelOps` has no `CLOCK_REALTIME` method, which makes "emulating a
monotonic clock with wall time" (section 4 of the E03 bead, which also names accept-plus-fcntl races and deterministic
randomness as unacceptable emulations) unrepresentable and not merely unpracticed. A failing monotonic clock is an error.
A reading is validated before it is believed: success is exactly `0`; `tv_sec` is not negative; `tv_nsec` is in `0..1_000_000_000`;
the nanosecond total fits a `u64`. The layer keeps the previous reading and a smaller one is `ClockError::WentBackwards`, which
does not replace it (`CLOCK_MONOTONIC` cannot go backwards, so a smaller value means a backend split or truncated a word).
**The epoch is the backend's.** A reading is nanoseconds from an origin the backend chooses (a double's scripted value; for the Linux leaf,
the time since it was created, from `std::time::Instant`), so only differences between readings of one backend mean anything and the
layer never compares a reading with a time from outside its backend.
**Which case the leaf is in (orchestrator ruling, mail 4029): the default, `Instant`, with no `unsafe` site.** The exception, a raw call, is
only for a consumer of the kernel's absolute `CLOCK_MONOTONIC` values (`timerfd_settime` with `TFD_TIMER_ABSTIME`, or kernel timestamps
compared against). **No such consumer exists in this slice**: the repository has no `timerfd`, no `SO_TIMESTAMP`, and nothing outside
`franken-platform` calls the layer's clock. A slice that adds one must use libc's `clock_gettime`, not a raw syscall number (on 32-bit
musl 1.2 `time_t` is 64-bit and the raw `__NR_clock_gettime` is the y2038 ABI), and count that site with its invariant in the leaf's
unsafe inventory. Because `Instant` cannot fail, the error paths above are policy for the seam, tested with scripted replies; a real
kernel without `CLOCK_MONOTONIC` is refused at admission by the matrix, not at run time.
*Observed (E03, both harness guests):* `clock_gettime(CLOCK_MONOTONIC)` and `clock_getres` (1 ns reported; the tick is not measured).

### Secure entropy (`entropy.rs`)
**There is no insecure entropy fallback, and a provider is selected, never fallen back to.** The acceptance criterion is *no insecure
entropy fallback* (the bead's own words); it never said "`getrandom` only". That was this contract's first **implementation** choice, and
root's decision (`ffw-jub` comment 205, mail 5126) replaces it with an explicit selection while keeping the criterion whole: two providers
exist, each a kernel facility that answers "nothing yet" instead of inventing bytes, and an `EntropyProfile` selects one **explicitly**:
`getrandom(GRND_NONBLOCK)` (`EntropyProvider::Getrandom`, **the default**, Linux 3.17 and later) or a nonblocking read of `/dev/random`
(`EntropyProvider::LegacyDevRandom`, for retained kernels older than 3.17, selected by naming it). **No failure of one provider ever
selects the other**: a `getrandom` that answers `EAGAIN`, `EINVAL` or `ENOSYS` leaves the selection as it was, and a layer that selected the
legacy provider never calls `getrandom` (each is pinned by tests below and by a source test). Refused by construction, each being the
insecure fallback the acceptance criterion forbids: `/dev/urandom` (it never blocks and cannot say whether the pool is seeded: E03's MIPS
guest logged `uninitialized urandom read` while the read passed, and `getrandom` answered `UNSEEDED` on the same boot; in the stock
kernels' source it draws from a pool with no entropy limit, see below); any deterministic or time/PID-seeded generator; `GRND_INSECURE`
and `GRND_RANDOM` (the flag is a constant, not a parameter); and any bytes from an injected test backend presented as entropy.
`urandom_entropy` in the matrix is a liveness observation and is read nowhere as a secure-entropy claim: with the default provider
`secure_entropy()` follows `getrandom_syscall` alone.

| kernel answer | result |
|---|---|
| bytes | `Ok`; short reads continue from where they stopped |
| `-EAGAIN` | `NotSeeded`: no bytes, retryable, **never cached, never papered over**; the layer does not spin or sleep |
| `-ENOSYS` (own ABI) | `Absent` |
| `-EINVAL` | `Invalid` (not absence) |
| `0` bytes for a nonzero request | `NoProgress`; more bytes than asked: `OverLong` |
| 16 or more identical bytes | `Degenerate` (a sanity check against a backend that reports success without bytes; not a randomness test) |
| matrix says unavailable | `Unavailable`, **without a kernel call**; the buffer is zeroed |

On every error the whole caller buffer is zeroed, including bytes an earlier iteration received, so a caller that ignores the
`Result` cannot use half a key. *Observed (E03):* PPC harness `PASS rc=16`; MIPS harness `UNSEEDED rc=-11`. The PPC pass is a fact
about that guest's boot, not a claim that boards seed at boot.

#### The legacy provider: a nonblocking `/dev/random` read (explicit selection only)
**Why it exists.** E03 puts the stock kernels at 2.6.14 (PowerPC) and 2.6.35 (MIPS), both older than 3.17, the first kernel with
`getrandom(2)` (kernel history, not repository evidence). With `getrandom` as the only provider the retained-kernel speaker would refuse
`entropy:absent` on every stock device, whatever the seeding. That is an inference: no stock kernel has been run and every stock cell in
E03 is unqualified. The legacy provider is the path that does not depend on a call those kernels may lack.

**What the kernel source says** (primary source: `drivers/char/random.c` at the tags `v2.6.35`, sha256 `3611d2b6a49022eb…`, and `v2.6.14`,
sha256 `a9b39865d4f1426a…`, fetched from `github.com/torvalds/linux` on 2026-11-05 and read, not committed; the man page `random(4)`
describes the same behavior: partial reads and `EAGAIN` for `O_NONBLOCK`). Line numbers are `v2.6.35` (`v2.6.14` in brackets); the two
are identical for this purpose:
* `random_read` (997 to 1051 [937 to 997]) extracts at most `SEC_XFER_SIZE` = 512 bytes (line 259 [254]) per pass and **returns after its
  first successful extraction** (the `break` commented "this break makes the device work like a named pipe", line 1046 [986]): a short
  read is the device's normal answer, not a fault.
* `account` (770 to 807 [721 to 757]) clamps a limited pool's extraction to `entropy_count / 8` (line 787 [739]); the blocking pool, which
  `/dev/random` reads, is limited (`.limit = 1`, line 436 [427]); the **nonblocking pool, which `/dev/urandom` reads, is not** (lines 442
  to 445 [433 to 436]), and `urandom_read` (1053 to 1057 [999 to 1004]) draws from it with no seeding check.
* **`-EAGAIN` is the only "nothing available" answer** of an `O_NONBLOCK` read: the extraction returned 0 (lines 1017 to 1021 [957 to 961]).
  A blocking read would sleep there; this provider never opens the device blocking.
* A signal surfaces only when the extraction produced nothing: `-ERESTARTSYS` (lines 897 and 1032), which user space sees as `EINTR`.

| kernel answer to a read of the legacy device | result |
|---|---|
| bytes (fewer than asked) | `Ok` only when the request is filled: the read is continued from where it stopped, within [`LEGACY_MAX_READS`] = 16 reads |
| `-EAGAIN` | `NotSeeded`: **waiting**, no bytes, retryable, never cached; every byte already received in this call is discarded with the rest |
| `-EINTR` | repeated at most 8 times (the same bound as every call here), then `Interrupted` |
| `0` bytes, or more than asked | `NoProgress` / `OverLong`; a trickle that does not fill the request within 16 reads is `ReadBudget` (mapped to `no_progress`) |
| `open` answers `ENOENT`, `ENXIO` or `ENODEV` | `DeviceAbsent` (`absent`): no other file is tried |
| any other errno from `open`, `read` or `close`; a positive `close` result | `Failed(errno)` / `Malformed`, never read as waiting or as `getrandom` absence |
| a request over 64 bytes | `RequestTooLarge` (`invalid`) **before any kernel call**: each byte is debited from a pool that every reader shares |
| 16 or more identical bytes | `Degenerate`, as for the default provider |
| the profile says unavailable | `Unavailable`, **without a kernel call**; the buffer is zeroed |

On every error the whole caller buffer is zeroed (including the bytes of earlier reads in the same call), the device is **closed exactly
once** whatever the reads did (a close that answers `EINTR` has released it on Linux and is not retried; any other close failure discards the
bytes), and the descriptor is opened for each call and not kept: nothing is cached across calls, so a pool that was seeded a moment ago is
asked again and "seeded" is never assumed. The device is opened `O_RDONLY | O_NONBLOCK | O_CLOEXEC` in the ABI's own flag values; the plain
`open` is used (not `openat`, which arrived in 2.6.16, after the stock PowerPC kernel's 2.6.14). No entropy work happens on the audio render
path: the only caller is startup, which asks for 16 bytes and keeps nothing.

**How it is selected, and what qualifies it.** `PlatformLayer::admit` still builds the layer with `EntropyProfile::Getrandom`; a caller selects
the legacy provider only with `with_entropy_profile(EntropyProfile::LegacyDevRandom(q))`, which makes no kernel call. `q` is a
`ProviderQualification`: `Observed(status)` (a matching guest was observed doing the read; `Supported` or `ObservedUnseeded`),
`Unqualified` (no observation exists: refused `unavailable` with no kernel call), or `TestEnvironment` (the caller names an admitted test
environment: the provider may be tried, and what it returns is **not** an observation about any kernel). The matrix is unchanged: it has no
cell for this provider and `secure_entropy()` still reads `getrandom_syscall` only. **No observation of the legacy device exists in the
E03 guest evidence that qualification reads** (E03's probes opened `/dev/urandom` and called `getrandom`), so the speaker's evidence-qualified
selection is `Unqualified` and refuses `unavailable` today; replacing that constant requires a matching-guest transcript that carries a line for
the device and an evidence generator that reads it. The retained provider-mode run below names a test environment, so it is **not** that
transcript and qualifies nothing.

**The speaker.** `franken-speaker --platform-startup` keeps the default provider: with no further argument its output is byte-identical to
every committed transcript. `--platform-startup --entropy-provider <name>` selects `getrandom`, `legacy-dev-random` (qualified by the
committed evidence: `unavailable` today) or `legacy-dev-random-test-environment` (an admitted test environment); any other argument, a
missing or repeated flag, or an unknown name exits 2 and starts nothing. The `ENTROPY` marker line carries `provider=legacy_dev_random` or
`provider=legacy_dev_random_test_environment`, between `provenance=` and `reason=`, **only** for a non-default selection (on PASS, REFUSED
and NOT_RUN alike), so a transcript shows which provider produced or refused its entropy. No reason code was added: a missing device is
`absent`, a trickling one `no_progress`, an over-limit request `invalid`, a pool with nothing to give `not_seeded`. The legacy examples are
pinned in their own file, `crates/franken-speaker/tests/vectors/p02_legacy_entropy_markers.json` (schema
`ffw.p02.legacy-entropy-markers.v1`), **not** in `p02_platform_markers.json`: that file is the one the QEMU smoke judge reads, its default
lines are unchanged, and the smoke judge in its default mode, which selects no provider, still (correctly) rejects a line that carries one.
The same judge has an explicit **provider mode** (`toolchain/SPEAKER_SMOKE.md`: `run-qemu-verification.py --speaker-platform
--entropy-provider legacy-dev-random-test-environment`). There the guest runs `--platform-startup --entropy-provider=<name>`, the `ENTROPY`
line must carry `provider=legacy_dev_random_test_environment` and no other line may, `not_seeded` is `degraded` on both guests (a refusal:
**no credit for the positive path**), and every other refusal, `absent` (the `/dev/random` node missing) included, is red. The
evidence-qualified provider has no guest step.

**What one bound central run shows** (`toolchain/results/runs/2a405e88bb10497b98b85abeae7dffaf/RUN.md`, landed in `331100a`; Debian harness

### Reactor wakeup (`wake.rs`)
The mechanism comes from the gate: `eventfd2` observed `Supported` selects the eventfd, observed absent with the fallback admitted
selects the self-pipe (`pipe2`). The module never decides for itself and never falls from one to the other; if the admitted
mechanism cannot be opened it says so and stops (`Absent`, `Sys`). There is no plain-`pipe` fallback: E03 probed `pipe2`, not `pipe`.
Descriptors are opened nonblocking and close-on-exec in each ABI's own flag values (`O_NONBLOCK` 0x800 PowerPC, 0x80 MIPS; `O_CLOEXEC`
0x80000 both). A descriptor the kernel hands over but that cannot be used (negative, or both pipe ends equal) is refused and closed
once, not leaked.
* `signal`: one `u64` counter write of 1 (eventfd) or one byte (pipe). `EAGAIN` is **`Backlogged`**, a different value from
  `Signalled`: documented Linux behavior says a wake is already pending, but E03 did not observe what a full pipe or an overflowing
  counter answers, so it is never reported as a fresh wake and a reactor must drain regardless.
* `drain`: an eventfd read yields the counter (zero or a short read is an error); `EAGAIN` means nothing pending. A pipe is read
  in 64-byte chunks until `EAGAIN`, at most 64 reads, so a pipe that never empties cannot hold the reactor (`more_pending`); end of
  file is an error because this layer holds the write end.
* `close`: each descriptor exactly once, first failure reported after all were attempted (see Decoding).
*Observed (E03):* a blocked `poll` woken by a write to a `pipe2` pipe from another context, consumed once (`REACTOR_WAKE`); a
nonblocking read of an empty pipe answers `-EAGAIN`; `eventfd2` creates a descriptor whose counter reads back what was written.
*Not observed:* the nonblocking-write-when-full answer above, and `epoll_wait`.

## Test doubles (`sim.rs`)
Both answer `Provenance::Simulated` and name no ABI; neither may be cited as evidence about a kernel.
* **`ScriptedOps`** (test builds only) replays replies a test chose, one per call, and logs every call, so "no fallback was
  attempted" is a statement about the log. An unscripted call panics, so a test cannot pass by accident through a reply it never
  chose (`close` alone defaults to success: cleanup is not what a test is about). It models nothing.
* **`SeededSim`** (cargo feature `sim`, off by default, **never enabled for a device image**) is the stand-in a host harness needs:
  a SplitMix64 byte stream for `getrandom` (reproducible, therefore **not secret**; the generator is pinned to the published
  reference vector), a virtual strictly-increasing clock, in-memory eventfd and pipe descriptors that follow Linux for a bad
  descriptor, a short buffer and a full counter, and an optional unseeded window (the first N `getrandom` calls answer `-EAGAIN`).
  It uses only the errno numbers that are the same on both ABIs. A harness enables it with `franken-platform/sim`; a device build
  (`-p franken-speaker`, default features) does not compile it.

## Accept and fcntl: concurrency implications (the rules; their policy is "The socket capability", below)
The sockets slice must accept connections with `accept4(SOCK_NONBLOCK | SOCK_CLOEXEC)` through the seam. `accept` followed by
`fcntl(F_SETFD, FD_CLOEXEC)` and `fcntl(F_SETFL, O_NONBLOCK)` is not equivalent, in two ways:
1. **A window where the descriptor is inheritable and blocking.** Between `accept` returning and the two `fcntl` calls the new
   descriptor exists without close-on-exec (a `fork`+`exec` in another thread, or a signal handler that spawns, leaks it into the
   child) and without `O_NONBLOCK` (a concurrent reader on a multi-threaded reactor can block on it). With one thread and no
   spawning the window is invisible; the layer does not assume that.
2. **Substitution hides absence.** A library `accept4` that answers `EINVAL` or `ENOSYS` by falling back to `accept` plus `fcntl`
   (musl's wrapper is the case to check first; E03 notes its probes are freestanding raw-syscall code and qualify no library) turns
   "the kernel does not support this flag" into a silent window. This is why `EINVAL` is not absence in `abi.rs`, and why a
   missing `accept4` must surface as `Absent` and be a profile decision, not be repaired underneath. (`abi.rs` still does not read
   `EINVAL` as absence; `socket::accept4` does, for that one call, as the profile's decision: see "The socket capability".)
E03 observed `accept4` over a TCP loopback pair on both harness guests (the flags set by the call itself, checked with `fcntl`);
the stock kernels are unqualified, so `accept4` is "optional; none admitted" there: an exact `-ENOSYS` is a classified absence with
no fallback. Datagram receive must use `MSG_TRUNC` semantics (E03 observed the real length 24 in a 16-byte buffer over `lo`) and
report truncation as a distinct outcome. The decoder rules are in `abi.rs` and `net.rs`; the policy that applies them to the socket
calls is "The socket capability", written and host-tested; kernel socket execution unqualified.

## The socket capability (`socket.rs`; written, host-tested; kernel socket execution unqualified)
`franken-platform::socket` puts the socket calls on the seam without changing `KernelOps` or any implementor of it. `SocketOps: KernelOps`
is a separate trait with five methods, `socket`, `bind`, `listen`, `accept4` and `recv`, each one raw call returning a non-negative result
or `-errno` (the "No emulation" duty of "The seam" holds for each). The policy functions take `ops`, the `Abi` and the arguments, as
`Waker` does: `open_stream_socket`, `open_datagram_socket` (which returns a `DatagramSocket`), `bind_v4` and `bind_v6`, `listen` (which
returns a `Listener`, the only thing `accept4` accepts), `accept4` and `recv_datagram` (which takes a `DatagramSocket`). What `net.rs` (P06)
already gives is used and not restated: the per-ABI socket type, `SOCK_NONBLOCK` and `SOCK_CLOEXEC`, `MSG_TRUNC` (as `RECV_FLAGS`), the
`sockaddr` codecs and `decode_datagram`.

**Status.** Compiled and host-tested; **socket kernel execution remains unqualified**. Compilation is not kernel execution.
The tests drive the policy with a scripted double that answers `Provenance::Simulated`; the test double and the leaf's `SocketKernel` are the only `SocketOps` implementations. No real socket descriptor has been observed through this boundary. 25 Rust unit tests in `socket.rs`, 7 Rust unit tests for the route plan in `numbers.rs`, and 37 Python tests in `tests/p02/test_socket_slice.py` (counted from the files).

The rules, and what holds each:
* **The flags are set by the call.** `open_stream_socket` and `open_datagram_socket` build `type` with `socket_type_arg(kind, true, true)`; `accept4`
  passes `accept4_flags(abi)`, the ABI's `O_NONBLOCK` (0x800 on PowerPC, 0x80 on MIPS) with `SOCK_CLOEXEC` (0x80000). The seam has no `fcntl`
  and no `accept`, so a flag cannot be set afterwards and `accept` plus `fcntl` cannot be built from it. Tests:
  `open_socket_sets_nonblock_and_cloexec_in_the_call_itself_on_both_abis`,
  `accept4_sets_both_flags_in_the_call_and_returns_the_descriptor`. The double models a descriptor's status from the flags it was given,
  with the per-ABI bits typed from the E03 probes, so a wrong constant leaves a descriptor blocking in the model.
* **`accept4` answering `ENOSYS` or `EINVAL` is `Absent`, after exactly one call.** A profile decision (BeigeMaple, mail 6790), stated once, in
  `accept4`; nothing is issued to repair it. Tests (each paired with the permitted positive, and each asserting the call log is that one
  `accept4`): `accept4_enosys_is_absent_and_no_second_call_is_issued`, `accept4_einval_is_absent_and_no_second_call_is_issued`. `EAGAIN` is
  `WouldBlock`, not absence (`accept4_with_nothing_pending_would_block_and_is_not_absence`). `listen`, `bind`, `socket` and the read keep
  `EINVAL` as `Invalid` (`only_accept4_reads_einval_as_absent`); on `socket` it means a kernel before 2.6.27 that takes no flags in
  `type`, and the socket is **not** made plainly and fixed up (`a_socket_refused_with_einval_is_reported_and_never_made_plainly_and_fixed_up`).
* **The `EINVAL` reading is defensive: it is reachable on none of the kernels whose source was read.** The kernel lines are in
  `tests/p02/socket_kernel_evidence.json` (v2.6.14, v2.6.26, v2.6.27, v2.6.28, v2.6.35). A PowerPC `socketcall` answers a sub-call above its bound with
  `-EINVAL`, not `-ENOSYS`: at v2.6.14 and v2.6.26 the bound is `SYS_RECVMSG` (17) and `accept4` is sub-call 18. But those kernels take no flags in
  `socket`'s `type` (`type >= SOCK_MAX` refuses them; the flags arrive at v2.6.27), so `open_stream_socket` fails first, `Invalid`, and there is no
  `Listener`: `accept4` is never reached. At **v2.6.27** flags are accepted and sub-call 18 exists, but it is **`paccept`** (`SYS_PACCEPT`, a six-word block,
  `sys_paccept(fd, addr, addrlen, sigmask, sigsetsize, flags)`), not `accept4`: through `socketcall` the call is not refused, it **runs a different call**
  on a four-word block, and nothing in the answer says so. From v2.6.28 sub-call 18 is `accept4` (four words). `accept4` also answers `EINVAL` for flags
  outside `SOCK_CLOEXEC | SOCK_NONBLOCK` and for a socket that is not listening (v2.6.35); the flags are fixed by the function and it takes a `Listener`,
  which only a successful `listen` builds, so neither can come from it. So the reading can fire only on a kernel that takes flags yet refuses `accept4`
  with `EINVAL` (none read), or on a descriptor closed through `fd()` and reused (below): that would read as absence. The mapping stays because the
  profile asked for it; the evidence says it is a safety net, not an observed behaviour.
* **`EINTR` is bounded** at `MAX_INTERRUPTED_ATTEMPTS` (8) and then `Interrupted`; seven interruptions then a result is a result. Tests:
  `socket_interruptions_are_bounded_and_the_last_attempt_still_counts`, `bind_and_listen_interruptions_are_bounded_and_the_last_attempt_still_counts`,
  `accept4_interruptions_are_bounded_and_the_last_attempt_still_counts`, `recv_datagram_interruptions_are_bounded_and_the_last_attempt_still_counts`.
* **A datagram is never silently cut, and only a datagram socket can be read this way.** `recv_datagram` always passes `RECV_FLAGS` (`MSG_TRUNC`), so the
  kernel reports the real length, and `decode_datagram` turns a datagram longer than the buffer into `Truncated { stored, real }`; a datagram exactly as
  long as the buffer is `Complete`. It takes a `DatagramSocket`, which only `open_datagram_socket` builds: on a stream socket `MSG_TRUNC` is not "report the
  real length" (by the independent reviewer's recollection of `tcp_recvmsg`, not read here, the kernel discards the bytes it was asked to truncate, so the
  function would return `Complete` over an untouched buffer). Tests: `recv_datagram_asks_for_msg_trunc_and_reports_a_cut_datagram` (its double reports the
  real length only when the flag was asked, as the kernel does, and the test asserts the flags the read passed), the control
  `the_double_cuts_silently_without_msg_trunc_which_is_why_the_flag_is_asserted`, and
  `a_datagram_token_comes_only_from_a_datagram_open_and_carries_its_descriptor`.
* **Tokens.** `Listener` and `DatagramSocket` are built only by `listen` and `open_datagram_socket`. `fd()` is for inspection, polling and `bind`, and
  does not consume the token; the close path is `into_fd()` handed to `KernelOps::close`, which consumes it
  (`the_tokens_are_closed_through_into_fd_which_consumes_them_and_fd_does_not`). A descriptor closed through `fd()` leaves a live token whose number the
  kernel may reuse; the types cannot prevent that, and it is the one way an `accept4` `EINVAL` could be misread as absence.
* **No fake success.** A descriptor above `i32::MAX`, or a `bind` or `listen` that returns anything but 0, is `NotAResult`
  (`a_descriptor_above_i32_max_is_not_a_result`); a negative value outside `-4095..=-1` stays `Malformed`.

`SERVER_POWERPC32` and `SERVER_MIPS32_O32` (`listen`, `accept4`), so no number is stated twice. A `socketcall` route is syscall 102 with two
slots (sub-call, block address) and the call's own arguments in a block of machine words in memory; a direct route is the call's own number.

* **The leaf backend has no socket guest-execution proof.** Host tests cover the pure route policy; target compilation covers the
  unsafe wrappers, not their execution. A `uname` wrapper, which would take the release from the kernel itself, is not here.
* **A kernel-version hazard for the `socketcall` route.** Sub-call 18 is `paccept` (six words) at v2.6.27 and `accept4` (four words) only from v2.6.28
  (`test_socketcall_sub_call_18_is_three_different_things_across_the_kernels_read`). The plan is data and cannot know the kernel, so the leaf refuses that
  kernel for the `socketcall` route in `socket_route::admit`, by name and before any socket call, because the answer to the call would not say.
* **`recvfrom` and the peer address.** `recv` does not return the sender, and `accept4` is called with a null address. A reply to a
  datagram's sender (SSDP) needs `recvfrom`: six slots, which the five-slot trampoline cannot carry as a direct MIPS call
  (`every_route_of_the_plan_fits_the_leaf_and_recvfrom_direct_is_the_call_that_does_not`), so its route would be `socketcall` on both ABIs.
* **No admission.** `layer.rs` has no socket method, and nothing checks a `SocketOps` backend's ABI against the profile
  (`PlatformLayer::admit` does that for `KernelOps`); a caller passes the `Abi` explicitly.
* **No qualification.** The stock 32-bit PowerPC kernel has no `accept4` and refuses flags in `socket`'s `type`, so on it the policy
  reports `Invalid` at the first call and stops; whether a profile may run sockets there is its decision. Nothing here qualifies a kernel.

## The datagram seam (`franken-platform/src/datagram.rs`, `franken-platform-linux/src/datagram_route.rs`; written, host-tested; kernel execution unqualified)
`N07` (`ffw-ybr`) needs a datagram carrier to send to a named peer and to learn who sent the datagram it read. That is `sendto` and `recvfrom`,
the gap the last section's "`recvfrom` and the peer address" bullet names. This section adds them **additively**: `SocketOps`, `SocketOp`,
`SocketPlan`, `issue_for` and `admit` are unchanged, and so are the P02 pins that read them.

**The API** (`franken_platform::datagram`, safe Rust). `DatagramOps: SocketOps` has two raw methods, `sendto` and `recvfrom`, one kernel call each,
so only a backend that passed socket admission can implement it (in the Linux leaf, `SocketKernel`). Above them, `send_datagram_to(ops, abi,
&DatagramSocket, &PeerAddr, payload)` and `recv_datagram_from(ops, abi, &DatagramSocket, buf) -> Received { datagram, from }`. `PeerAddr` is an
IPv4 or IPv6 address (`Copy`, ordered, hashable, with the IPv6 scope id and without flow information). `DatagramSocket` is the same token
`recv_datagram` takes, so a stream descriptor cannot reach either function.

**The rules**, each held by a Rust test in `datagram.rs` (16 tests, all against a scripted double that answers `Provenance::Simulated`):
* **Send flags are 0 and receive flags are `MSG_TRUNC`.** The socket is nonblocking, so a full send buffer is `EAGAIN`, reported as `WouldBlock`
  and neither retried nor dropped silently.
* **A datagram goes whole or not at all.** A send returning fewer bytes than the payload is `ShortSend`, **including 0 for a non-empty payload**;
  0 is a result only for an empty datagram. A return above the payload is `NotAResult`. A payload above `MAX_DATAGRAM` is refused before any call.
* **The sender is never guessed.** The kernel is offered a `sockaddr_in6`-sized buffer (28 bytes) and its reported length is read back. A length
  above 28 (the address was cut), a length that is not a whole IPv4 (16) or IPv6 (28) address, an unknown family, or non-zero IPv4 padding is an
  error and never a `PeerAddr`.
* **An `Err` for a bad sender means the datagram was consumed.** The kernel has already taken it off the socket; the caller must count it and keep
  reading. A truncated datagram, by contrast, is a result and still names its sender (an oversize flood can be accounted per source).
* **`EINTR` is bounded** (`MAX_INTERRUPTED_ATTEMPTS`), and every receive attempt starts with a fresh, zeroed address buffer and the full room offered
  again, so a retry never sees the previous attempt's length or bytes.

**The route** (`datagram_route.rs`, 7 host tests, plain data, no `unsafe`). Both calls are issued as **`socketcall` on both ABIs** (102 on PowerPC,
4102 on MIPS o32; sub-calls 11 and 12; a six-word block). A direct six-argument call would need a wider trampoline than `raw5`: on MIPS o32 the
sixth argument goes at `20($sp)`, where `raw5` saves a register, and `test_the_trampolines_are_still_the_audited_two_and_no_wider_one_exists` forbids
one. The kernel files in `tests/p02/socket_kernel_evidence.json` give `SYS_SENDTO` 11, `SYS_RECVFROM` 12 and `nargs` 6 for both at v2.6.14, .26,
.27, .28 and .35, and MIPS's `sys_socketcall` table entry. No number is typed in the new file: the `socketcall` number and the sub-calls come from the
`P06Calls` rows. Both sub-calls are inside the stock 2.6.14 `socketcall` bound (17) and neither is sub-call 18, so the release refusal of
`socket_route::admit` (which concerns only `accept4`/`paccept`) does not apply to them.

**What this does not claim**
* **No guest has issued a `socketcall` on either ABI.** On MIPS o32 the leaf's other socket calls are direct, and the E03 probes issued those; these two
  would be the first `socketcall` that ABI sends, so on MIPS this is **weaker evidence than a direct call would be**, not equal to it. The wrappers
  compile for both big-endian targets only when the central build says so; none has run in a guest.
* **Old-kernel policy is unchanged.** `open_datagram_socket` still refuses the pre-2.6.27 flag form with `Invalid`, and nothing falls back to
  `socket` plus `fcntl`. A legacy non-atomic fallback would need its own reviewed process, thread and exec safety contract and guest evidence.
* **The unsafe inventory moves.** `sys.rs` gains **two `unsafe { execute(issue) }` blocks** (`sendto`, `recvfrom`), each with a SAFETY comment; the
  `unsafe fn` set is unchanged (two `raw5` trampolines and `execute`), and no `unsafe` appears in the new files. E06's committed inventory for
  `franken-platform-linux` predates this and is not regenerated here: a re-audit of the landing revision is owed.
* **Host evidence only.** A carrier tested over `std::net` sockets behind a double is evidence about the carrier's logic, not about this leaf, a
  kernel or the big-endian ABIs. IPv6 is in the API and unexercised on a wire.

## The real backend (the approved design; `franken-platform-linux` landed in `6ab9020`)
Real syscalls need `unsafe` (inline assembly, as in the audited `sys_raw5` of `toolchain/src/ffw-hello-init`: PowerPC `sc` with the
error in `cr0.SO`, MIPS o32 `syscall` with the flag in `$7`). P01's rules did not permit that in the speaker's device closure:
`tests/p01/reference.py` allowed `deny_with_scoped_allow` only for `host_tool` and `test_support` and rejected it as
`unsafe_in_device_closure` for any device artifact. **Decision (orchestrator, mail 3975):** approved, as one leaf member
`franken-platform-linux`, role `platform`, `deny_with_scoped_allow`, and **one counted exception edge**
`franken-speaker -> franken-platform-linux`; the speaker keeps `forbid(unsafe_code)`. The P01 gate change (allow `platform` +
`deny_with_scoped_allow`, a counted `unsafe_exceptions` edge list, and planted negatives for an unlisted edge and a second unlisted
edge to the same crate) is made by the gate's owner, not by the crate that benefits, and **the leaf lands in the same batch, not
before**. This crate (`franken-platform`) keeps `#![forbid(unsafe_code)]` and contains no backend.

**The leaf's unsafe surface is one trampoline per ABI** (the audited `raw5`, reproduced unchanged) **plus fourteen typed wrappers**, in a single
`sys` module: seven of one line each (the kernel calls), and seven socket wrappers that hand the words `socket_route` (the five of the socket capability) or
`datagram_route` (`sendto` and `recvfrom`) chose to one executor (`execute`), the only
other `unsafe` site (socket execution unqualified; see "The socket capability" and "The datagram seam"). Of the seven, the seventh, `open_dev_random`, was added for the legacy entropy provider: the one pointer it passes
is the address of the `'static` NUL-terminated constant `b"/dev/random\0"`, the method takes no path, and its SAFETY comment states that. A wrapper takes Rust references, fixes the syscall number for its compiled ABI, and passes only
pointers and lengths derived from those references, so a safe caller cannot pair a number with the wrong call or pass a stray
pointer. Every `unsafe` block carries its SAFETY comment. The crate's only dependency is `franken-platform`. On any other target the
type `LinuxKernel` does not exist (`numbers` is plain data and compiles everywhere), so the host build stays safe Rust.

**Why each call is raw and not std's** (the orchestrator's rule: use std's safe API wherever it gives the exact kernel semantics
with no hidden fallback). Library behaviors named here are the known ones for musl and were not re-verified against the vendored
musl in this work:

| call | std or libc offers | why the leaf issues it raw |
|---|---|---|
| the monotonic clock | `std::time::Instant` | **not raw: `Instant` is used**, with no `unsafe` site; see the ruling under "Monotonic clock" (no consumer of absolute `CLOCK_MONOTONIC` values exists) |
| `getrandom(buf, len, GRND_NONBLOCK)` | no public API with explicit flags | the flags are the policy (`GRND_INSECURE` and `GRND_RANDOM` must be unreachable) |
| `open("/dev/random", O_RDONLY \| O_NONBLOCK \| O_CLOEXEC)` | `std::fs::File::open` (blocking open flags are the caller's, `O_NONBLOCK` is not offered; a library may retry `EINTR`) | the legacy entropy provider needs exactly one nonblocking open of exactly one path, and the kernel's own `ENOENT` for a missing device; the plain `open` (not `openat`, absent before 2.6.16) is the one the stock kernels have |
| `eventfd2` | none in std; a libc `eventfd` wrapper may fall back to the older call | an absent `eventfd2` must be the kernel's `-ENOSYS`, which selects the self-pipe by the matrix and not at run time |
| `pipe2(flags)` | `std::io::pipe` (no nonblocking flag at creation); a libc `pipe2` may fall back to `pipe` plus `fcntl` | the fallback is not atomic, and the descriptors must be nonblocking and close-on-exec from birth |
| `read`, `write`, `close` on those descriptors | `File` needs `from_raw_fd`, which is itself `unsafe`; a libc `close` decides what `EINTR` means | the layer's policy needs the kernel's answer: `close` is issued once and its `EINTR` reported (see Decoding) |

Sockets are the next slice and std's `net` is safe for most of it, but `TcpListener::accept` cannot set `SOCK_NONBLOCK` at accept time
(only `SOCK_CLOEXEC`), so the accept4 rule above would need a raw `accept4` there; that call and its reason join this table then.
`ppoll`/`epoll` are not needed by this slice (the reactor polls `wake_fd`).

**Syscall numbers are cross-checked per ABI by a test, not a comment:** `tests/p02/test_syscall_numbers.py` holds
`crates/franken-platform-linux/src/numbers.rs` to the E03 guest probes (`toolchain/src/ffw-hello-init`, always required) and to the
`libc` crate's musl tables (skipped with a stated reason when the registry lacks the locked version); it plants a wrong number, a
non-numeric expression and a swapped table and requires each to be reported. The two witnesses agree with each other too.

**The P06 calls: numbers and slot counts (`P06Calls`, S3 of `docs/contracts/p06.md` "Applicability").** `numbers.rs` has a second table, `P06_POWERPC32` and
`P06_MIPS32_O32`, for the seventeen calls the P06 primitives (`franken-platform`'s `net` and `durable`) are used with: `poll`, `socketcall`, `socket`, `bind`,
`connect`, `getsockname`, `send`, `recv`, `sendto`, `recvfrom`, `setsockopt`, `fsync`, `rename`, `unlink`, `_llseek`, `pread64`, `pwrite64`. It is data and tests only:
**no wrapper, no `KernelOps` method, no `sys.rs` change, no `unsafe`, and nothing issues these calls.** Each row has the syscall number and the **slot count** (the
arguments the kernel's entry takes; a 64-bit argument takes two, on an even register pair, and the pad slot counts), and each socket-family call also has its
`socketcall` sub-call number (`linux/net.h`: 1, 2, 3, 6, 9, 10, 11, 12, 14) and a `direct_on_stock` flag.

* **The stock 32-bit PowerPC kernel has no direct socket syscall.** Neither the v2.6.14 nor the v2.6.35 PowerPC table has `socket`, `bind`, `recvfrom` or any other; there is
  `socketcall` (102) and nothing else, so on that image a socket call is `socketcall(sub, args)`: two slots, the arguments in a block in memory. The direct numbers in the
  PowerPC table (326 and on) are those of newer kernels, which the E03 guests (4.x) run and the E03 probes issued; `direct_on_stock` is `false` for all nine. MIPS o32 has both
  forms at 2.6.14 and 2.6.35 (`socket` is 4183, `recvfrom` 4176, `setsockopt` 4181), so its flag is `true`. A caller that wants a socket on a stock PowerPC kernel must use
  `socketcall`; one that issues `socket` directly there gets the kernel's own `-ENOSYS`, as everywhere in this backend.
* **Four calls need more argument slots than the leaf's trampoline carries** (`LEAF_ARG_SLOTS` = 5, the two `raw5` functions): `sendto` and `recvfrom` (six), `pread64` and
  `pwrite64` (six: `fd, buf, count, pad, hi, lo`). `recv` and `send` (four) fit, and `_llseek` (five, the 64-bit result stored through a pointer) fits. A test fails if that
  set changes, so a six-slot trampoline, or the use of `recv`/`send`/`_llseek` in their place, has to be a decision that updates it.
* **Witnesses, each where it applies** (`tests/p02/test_syscall_numbers.py`, 19 new cases): the E03 probes for the ten calls they issued (`poll` and `socket` in `main.rs`;
  `fsync`, `rename`, `unlink` in `e03_probes_rt.rs`; `bind`, `connect`, `getsockname`, `recv`, `send` in `e03_probes/net.rs`), with the seven they did not issue named and
  checked absent so that a future probe cannot go unnoticed; the `libc` crate's musl b32 tables (its MIPS musl table defines no `pread64`/`pwrite64`, so the crate's glibc
  MIPS table is used for those two, and a test fails if musl ever gains them); and the kernel's own files at v2.6.14 and v2.6.35 (`unistd.h`, the MIPS o32 call table
  `scall32-o32.S` for slots, the 32-bit PowerPC `systbl.h` and `sys_ppc32.c`/`net/compat.c` for the compat entries, `linux/net.h`, and the prototypes), whose names and sha256 are
  recorded in the test. The kernel literals were machine-extracted from those files, not typed, and every extracted entry was checked by function name or table index. Slot
  counts have the kernel as their only witness. A wrong number, slot count, sub-call or stock flag, planted in a copy, is reported by each witness that applies.
* **Not claimed:** nothing here ran against a kernel. The 2.6.14 PowerPC `unistd.h` read is `asm-ppc` (the 32-bit PowerPC table of that tree); the 2.6.14 call table and prototypes
  were not read for slot counts (v2.6.35 was), on the evidence that the numbers did not change between them. The PowerPC direct socket numbers have no 2.6 kernel witness by
  construction: they are attested by the E03 probes (4.x guests) and the `libc` crate.

Status: **landed in `6ab9020` with the P01 exception; its host unit tests pass (the number tables); compiled for both BE triples** by the central P01
device builds (see the `open` row of the proof-class table); **run in both harness guests** by two QEMU speaker smoke runs (`toolchain/results/runs/570cd370db04436dbf19e0329b17a944/`, default provider: the PowerPC guest started, the MIPS guest refused on an unseeded

commit's message reports it clean). No statement in this contract is about a kernel other than those two harness guests.

## The device speaker's startup (`franken-speaker --platform-startup`)
On a big-endian MIPS or PowerPC build, `franken-speaker` builds its platform layer in **one function**, `platform_start::bring_up`, and the Linux leaf
backend (`franken_platform_linux::LinuxKernel`) in **one place**, `platform_start::bring_up_device`. Every start of the device speaker goes through them,
`--platform-startup` included; `main.rs` only calls `platform_start::check_device`. The clock, wakeup and entropy the device uses therefore come from the
platform layer, and a host or simulated stand-in is not reachable from that path. Today the check is the only device start there is: the speaker has no
`--run` mode, and one would be a placeholder success until the playout and control paths exist. So "normal startup and the startup check are the same code"
is a rule for the next mode to inherit, and it is pinned by a source test (`the_speaker_builds_a_layer_and_the_backend_in_exactly_one_place_each`, mirrored
on the host by `tests/p02/test_platform_markers.py`, class `OneConstructionSiteTests`, with a control that plants a second site): no file in the crate's
`src/` or `tests/` builds a layer or the backend anywhere else, and none of them names the leaf crate, `SeededSim` or `ScriptedOps`. (`--catalog` and its
output are unchanged. The Virtual House harness keeps its own labelled `simulated_boot_entropy`; this change does not touch `harness.rs`.)

Startup is a sequence of refusals, each a typed `StartupError` with a stable `reason=` code and no fallback:
1. **The backend must be the kernel.** `Provenance::Simulated`, or a backend that names no ABI, is refused before any call
   (`simulated_backend`, `no_abi`). **Planted negative:** a build wired to a simulated backend, with or without an ABI, is refused with zero kernel calls.
   **Paired positive:** a backend that declares `Kernel` starts, and every capability line then reports `provenance=kernel`. Both are unit tests with a
   double that says what the test tells it to, so they prove the logic and not the real backend; the proof for the real backend is the QEMU speaker smoke below.
2. **The ABI picks the evidence; the probes decide; the running kernel's release is recorded and never compared.** The capability matrix is generated from
   the E03 transcripts of the two harness kernels (`guest_evidence.rs`, by `scripts/p02/gen_guest_evidence.py` through the E03 oracle, no status typed by
   hand) and is chosen by the backend's ABI, which the target fixes at compile time. A real board's kernel is the vendor's and never equals a harness
   kernel, so a release check would refuse every board; the speaker therefore reads `/proc/sys/kernel/osrelease`, records it in the `BEGIN` line as
   `kernel=` (one to 64 bytes of `[A-Za-z0-9._+-]`, else the literal `invalid`), and refuses on nothing about it (an unreadable release is
   `kernel=invalid`, still a start). If a kernel lacks a call, the probe says so and startup refuses with that call's typed code: a missing `eventfd2` is
   `wake_open_failed`, a missing `clock_gettime` is `clock:absent`. **Control:** stock and unreadable releases start; the verdict of the reference judge
   does not change when only the `kernel=` value does. The evidence says nothing about a board.
3. **The layer is admitted and each capability is tried once, independently:** two monotonic readings; 16 bytes from the **selected**
   entropy provider (`getrandom(GRND_NONBLOCK)` by default; the legacy `/dev/random` provider only when `--entropy-provider` names it;
   kept by nothing, printed by nothing); one wake signalled and then drained (exactly one wake seen, then none). An error is the
   refusal. **An unseeded entropy pool is `not_seeded`, retryable by the caller, and is never answered with a seeded or time-derived
   value:** startup makes one nonblocking request to its provider and does not wait, substitute or try the other provider. Waiting
   policy belongs to the readiness state machine.

**Markers** (stdout, six lines, always, newline-terminated, nothing after `END`): `FFW_PLATFORM:BEGIN abi= evidence= backend= kernel=`, then `KERNEL`, `CLOCK`,
`ENTROPY`, `WAKE`, `END`, each capability `PASS`, `REFUSED` (with `reason=`) or `NOT_RUN` (nothing could be tried), with the provenance the layer declared, so
failure and not-run counts survive in the transcript. A `REFUSED` capability line is always `provenance=kernel` (a capability can only be refused after the layer
exists, and a simulated backend is refused at `KERNEL` before any layer); `none` appears only on `NOT_RUN` lines. `END` is `started=1`, or `started=0 refused=<capability>:<reason>` naming the first refusal. A
`NOT_RUN` always follows a `REFUSED`: a wake source the kernel cannot open is reported on the `KERNEL` line (`wake_open_failed`) so that `CLOCK`, `ENTROPY` and
`WAKE` read `NOT_RUN` after it, never before. The speaker prints no clock value and no entropy byte. Exit 0 started, 3 refused, 2 on a target with no kernel
backend. **For the default provider the `ENTROPY` line has no `provider=` token** and every line above is unchanged; a non-default selection adds
`provider=` to that line alone (see "The legacy provider"; its examples are in their own file and are not part of the smoke judge's grammar). The
grammar, the closed reason sets (no code names the kernel release) and nine example outputs are pinned in
`crates/franken-speaker/tests/vectors/p02_platform_markers.json`; `platform_start.rs` runs each scenario and compares, and
`tests/p02/test_platform_markers.py` holds the examples to the grammar, defines the reference judge a smoke runner can adopt, and plants faults the judge must report.

**What the QEMU speaker smoke must show** (the runner and its judge are DarkPeak's, agreed in their mail 4149): after the `--catalog` step,
`/franken-speaker --platform-startup` as a second child with the same byte/FNV measurement; the guest accepts exit 0 or 3 as "the step ran" and the host judge
decides. PowerPC (getrandom was seeded in run `1412ac47`): every line `PASS` with `provenance=kernel`, `END started=1`, exit 0. MIPS (getrandom was
`UNSEEDED` at PID-1 boot, one run): KERNEL, CLOCK, WAKE `PASS`, ENTROPY `PASS`, or `REFUSED reason=not_seeded` with `END started=0 refused=entropy:not_seeded` and
exit 3, reported as `degraded` (E03's own verdict, neither green nor red), because one run per guest does not say the pool stays unseeded. Red on either
guest: a missing, duplicated, reordered or malformed line, any `provenance=simulated`, a `REFUSED` capability line whose provenance is not `kernel`, `backend=simulated`, a reason code outside the closed set, an `END` that
disagrees with the lines above it, a `NOT_RUN` no earlier `REFUSED` explains, or any output after `END`.

**Not proven here:** that the real backend runs on a board or a stock kernel (each harness guest has run it in two smoke runs, see the leaf status), what
either guest answers on another boot, what string a real board reports in `kernel=`, or anything about a board or a stock kernel. The markers say
what the harness guests did, in two smoke runs per guest (`toolchain/results/runs/570cd370db04436dbf19e0329b17a944/RUN.md`, `toolchain/results/runs/2a405e88bb10497b98b85abeae7dffaf/RUN.md`). A host build cannot print them: it has no kernel backend and exits 2.

## Actionable startup diagnostics
`franken-speaker --platform-diagnose [--entropy-provider NAME]` runs the same admitted startup path as `--platform-startup`.
It preserves the marker stdout and exit status, and adds a bounded human diagnostic on stderr for the first refusal: capability,
typed reason and a safe next action. The original command keeps its byte-exact judged output, including its unsupported-host error.
No backend is substituted on a host. Both commands reject malformed provider arguments before startup. The diagnostic uses static
advice, not a dump of kernel inputs, identifiers or entropy. Only an unseeded pool advises a later retry; a wake-open error does not
claim that the syscall is absent, because resource/permission errors share that coarse marker.
Three existing absence tests now exercise both admitted ABI profiles, using PowerPC ENOSYS 38 and MIPS o32 ENOSYS 89; the other
ABI's errno remains an ordinary failure. The startup unit tests also pair resource/permission refusals with permitted startup.

## Memory failure and arithmetic
`socket::kernel_allocation_failure_is_typed_without_retry_or_invented_descriptor` injects kernel `ENOMEM` (-12 on both ABIs)
into all five socket wrappers, checks the typed operation/error and one attempted call, then exercises explicit permitted recovery
and descriptor close. This tests syscall allocation failure; it does not simulate Rust global-allocator exhaustion.
`MemoryBudgetLedger` is admission accounting, not a memory measurement. Its sums use a wide intermediate; signed headroom clamps
only the final difference, and admission compares remaining RAM to the safety floor without an overflowing addition. Tests cover
ordinary limits, inclusive boundaries, both signed extremes, sums beyond `u64`, and a one-byte deficit between large values.
Startup still allocates (including the `Arc` clock-epoch token); a process allocator abort is not claimed as a typed syscall error.

## Known limits
* The unit tests have not run against a kernel; the speaker's startup has, on two harness kernels, in two smoke runs each (`toolchain/results/runs/570cd370db04436dbf19e0329b17a944/RUN.md`, `toolchain/results/runs/2a405e88bb10497b98b85abeae7dffaf/RUN.md`), and nothing has on a stock kernel or a device. A scripted reply is an input a test chose, so a passing test shows what the policy does with
  that reply and nothing about what any kernel does.
* The `Degenerate` check is a sanity check on a backend, not a randomness test; the layer cannot tell a seeded pool from an
  unseeded one other than through the kernel's own `EAGAIN`, and the matrix status is a boot-time observation of two guests, one run each.
* A kernel that answers `close` with `EINTR` is treated as having closed the descriptor (Linux behavior); another kernel might not.
* The legacy provider's behavior is the **source's** (two tags, read), plus one observation per harness guest, which is not a property of any kernel: in `toolchain/results/runs/2a405e88bb10497b98b85abeae7dffaf/` the MIPS guest read bytes from `/dev/random` and
  the speaker started, and the PowerPC guest was refused `not_seeded`; nothing has read `/dev/random` bytes on a stock kernel or a device. A kernel that differs (a vendor patch to `random_read`, a pool that never credits entropy on an embedded board) would
  show as `not_seeded` or `no_progress`, never as bytes the kernel did not credit, but the wait could be unbounded: waiting policy and a
  persisted seed or a hardware generator for such a board are the owner's decision, not this layer's.
* The 64-byte request limit and the 16-read budget are this layer's policy for key-sized requests, chosen from the source (a read yields at
  most what the blocking pool holds, and each byte is debited); they are not kernel limits.
* `ProviderQualification::TestEnvironment` is a statement by the caller that the environment is a test one. By the source the device returns only
  what its pool has credited, so the statement does not make the bytes weaker (not observed on any kernel), but a start it reports is not
  device evidence, and the marker says which selection ran.
* The layer is single-threaded by construction (`&mut self`); nothing here is `Sync`. The wake descriptors are shared with a
  reactor by number (`wake_fd`), and a signal from another thread needs its own handle on the write end, which the sockets/reactor
  slice has to decide.
* `SeededSim` is a model of the behaviors the policy layer uses and nothing more; it must not grow into a kernel.
* The socket policy has never seen a kernel, and the stock 32-bit PowerPC kernel cannot run its positive path (no flags in `socket`'s `type` before
  2.6.27, no `accept4` before 2.6.28). `accept4` reading `EINVAL` as absence is the profile's decision and is reachable on none of the kernels whose
  source was read (`tests/p02/socket_kernel_evidence.json`); the kernel that comes closest, v2.6.27, runs `paccept` on `socketcall` sub-call 18 and the
  leaf refuses it for that route by name (`socket_route::admit`). None of this is observed on any kernel.
