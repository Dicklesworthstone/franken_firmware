# Contract P01 — FrankenFirmware Cargo Workspace & Crate Topology

## Scope & Mission
Defines the layered Rust 2024 Cargo workspace for `franken_firmware`, enforcing `#![forbid(unsafe_code)]` across all protocol, session, clock, stream, control, and DSP crates, static memory budgeting with a hard `>= 4 MiB` free-headroom floor on 32 MiB PowerPC boards (`S5` Play:5 Gen1), and deterministic cross-compilation to `powerpc-unknown-linux-musl` and `mips-unknown-linux-musl`.

## Crate DAG & Layer Boundaries

1. `franken-test-support` (`Q00`): Deterministic SplitMix64 network impairment schedule, sample continuity oracle, epoch fencing oracle, command idempotency oracle, readiness truthfulness oracle, secret-redacting non-blocking sink, and JSON receipt schema.
2. `franken-board-profile` (`E01`): Board profiles (`S1`, `S3`, `S5`, `S9`, `S12`, `Sub`, `ZB100`), SHA-256 profile digests, provenance verification, and permutation-invariant fleet reconciliation.
3. `franken-atomic` (`P05`): The semantic 64-bit atomic replacement that `franken-platform` consumes in place of its `portable-atomic` re-export: `std` only, no dependencies and no `unsafe` (built on `std::sync::Mutex` and `AtomicU32`), placed below `franken-platform` so that edge points downward.
4. `franken-journal` (`U01`): The crash-safe settings journal over a `Storage` trait: CRC-32 framed records and snapshots on a two-segment flash-like medium, tombstones, poisoning and a cut-point oracle; `std` only, no workspace dependency, no `unsafe`.
5. `franken-platform` (`E03`, `P02`, `P05`): Kernel capability matrix (`2.6.14` PPC / `2.6.35` MIPS / `4.x` QEMU), re-exports of `franken-atomic`'s 64-bit shared cells (`SharedU64`, `SharedI64`, `Sequence`, `LocalU64`), and static memory budget verifier (`MemoryBudget`).
6. `franken-platform-linux` (`P02`): The Linux kernel backend (role `platform`, one `sys` module, scoped `unsafe` with a SAFETY invariant on every block): the only crate with an unsafe allowance in a device image, and only through the counted exception `franken-speaker -> franken-platform-linux`.
7. `franken-hal` (`E04`, `P04`): Typestate audio DMA HAL (`Closed ->OpenMuted -> Prepared -> Running -> FaultedMuted`) enforcing silence priming before unmute and DMA lease quarantine on drop.
8. `franken-dsp` (`D01`..`D04`): Deterministic `f32` audio blocks, big-endian `i16` wire conversion, 4-point Hermite fractional ASRC (`<= 500 ppm`), DC blocker, Linkwitz-Riley crossover, and soft-knee transducer protection limiter.
9. `franken-clock` (`N03`, `V01`, `V02`): IEEE 1588v2-lite PTP Follower PI servo, outlier rejection, holdover/resync state machine, per-board calibrated output delay compensation, and automatic YouTube/AirPlay lip-sync delay reporting.
10. `franken-stream` (`N01`, `N04`..`N06`): Authenticated `FFWP` audio frames (`HMAC-SHA256`), 64-packet sliding replay window, `consume_by` deadline enforcement, 4-packet XOR parity FEC, and bounded jitter buffer with cosine PLC fade.
11. `franken-session` (`G01`, `G02`, `N02`): Unified S1+S2 group coordinator (`UnifiedGroupSession`), epoch fencing, command sequence idempotency, logarithmic volume laws, and stop-tail silence zeroing.
12. `franken-control` (`G03`, `S01`, `A01`, `T01`, `X01`): `fsonos`-compatible UPnP/SOAP/GENA shim, Spotify Connect (`librespot`) session state machine, AirPlay 2 receiver adapter, Alexa intent bridge with confirmation gate, and Tailscale remote-access control boundary.
13. `franken-speaker` (`P01`, `Q01`, `UX01`): Top-level speaker daemon (`franken-speaker --self-test` / `--virtual-house`) and multi-room virtual house harness.

## Build identity contract (typed target and profile contract, `ffw-h3g`)

The workspace states what it is in one place: `crates/franken-board-profile/src/build_contract.rs`
(`WorkspaceContract`, schema `ffw.build_contract.v1`). It extends the board-profile identity of this crate
(`CpuIsa`, `target_triple`) instead of running beside it. The contract is data with a canonical-JSON SHA-256 digest;
the declared workspace is `crates/franken-board-profile/tests/vectors/p01_workspace_contract.json`.

### Rules, and the codes that name them

| Invariant | Rule | Stable codes |
|---|---|---|
| Distinct ISA artifacts | An artifact has exactly one target (`host`, `mips_be`, `powerpc_be`) and `runs_on == [target]`. There is no universal artifact and no ARM target (it does not parse: no evidence admits one). | `universal_artifact_claim`, `parse_error` |
| Identity agrees | Declared `triple` and `isa` belong to the target; an observed ELF has `e_machine` 8 (MIPS) or 20 (PowerPC), 32-bit class, big-endian. | `triple_target_mismatch`, `isa_target_mismatch`, `elf_machine_mismatch`, `elf_not_32bit_big_endian` |
| Layered DAG | Normal dependencies point to a strictly lower layer; no self, unknown or cyclic dependency, including cycles that exist only through dev-dependencies. | `self_dependency`, `unknown_dependency`, `layer_violation`, `dependency_cycle`, `dev_dependency_cycle` |
| One owner | Every crate, interface and fixture has exactly one non-empty owner. | `owner_missing`, `asset_unowned`, `asset_duplicate`, `asset_conflicting_owners`, `asset_owner_mismatch` |
| Required vs optional | Every profile selects every required feature; a full-product profile cannot disable one; a disabled feature states why; a narrow profile states why it is narrow. | `required_feature_missing`, `full_profile_disables_required`, `disabled_without_reason`, `narrow_profile_without_reason` |
| Disabled required never qualified | Qualification is computed by `admission`, never asserted. Evidence cannot be attached to a feature the profile disables, and `status: qualified` beside a blocked admission is refused. | `qualified_while_disabled`, `qualification_not_supported` |
| Evidence is bound | A qualification names the artifact digest, target and profile it was gathered for and cites a receipt; the evidence kind (`host_simulation`, `guest_execution`, `real_service`, `physical_output`) must be one the feature accepts. A host simulation never stands in for a real-service or physical result. | `stale_evidence`, `evidence_kind_insufficient`, `evidence_receipt_missing` |
| Native services independent | A native-service feature requires only core features; a core feature never requires a native service. | `native_feature_requires_native`, `core_feature_requires_native`, `feature_cycle` |
| Device images stay clean | No test-only, host-only or scoped-unsafe crate is in a device artifact's normal-dependency closure unless a counted exception names the edge (`test_support_exceptions`, `unsafe_exceptions`); **every** edge into such a crate that the artifact's build activates must be named, so a listed edge never excuses a second one and an artifact's own crate is never excused; an exception for a missing edge, or onto a crate of the wrong kind, is stale and excuses nothing; device artifacts build with `panic = abort`. | `test_support_in_device_closure`, `host_tool_in_device_closure`, `unsafe_in_device_closure`, `stale_unsafe_exception`, `unsafe_exception_without_reason`, `stale_exception`, `device_profile_not_abort` |
| Optional dependencies | A dependency Cargo makes optional is modelled as one: it is in an artifact's closure only when that artifact's profile enables the feature that activates it, the feature has a real Cargo flag (`cargo_feature`), and the flag belongs to the crate that carries the dependency. Optional edges count in cycle and layer checks. | `optional_dep_without_flag`, `optional_dep_wrong_owner`, `unknown_feature`, `unknown_dependency` |
| Linkers | A device artifact built from a workspace member (the speaker) is linked by a declared wrapper: `linkers` names, per device target, the crates it covers, the wrapper's repository path and SHA-256, the zig version and zig target it enforces, and the ISA revision and float ABI the linked file must show. The wrapper path is relative and stays in the repository; every such artifact has a linker; no crate and target pair is covered twice. The bootstrap probe links with rust-lld and has no entry. | `linker_malformed`, `linker_unknown_crate`, `linker_duplicate`, `device_artifact_without_linker` |
| Linked file | A receipt row for such an artifact must be static (no `PT_INTERP` or `PT_DYNAMIC` segment; a header table that cannot be read is not static). Where the ELF can state the declaration (MIPS, in `.MIPS.abiflags`, read from the program headers so a stripped file keeps it) the row's ISA revision and float ABI must equal it, and a missing marker fails closed. Where it cannot (PowerPC has no marker) the declaration is not measured, but a marker that is present must still agree. | `artifact_not_static`, `isa_revision_mismatch`, `float_abi_mismatch` |
| Metadata documents | Two `cargo metadata` documents (default features, and `--features franken-speaker/harness`) are judged, not just read: the gate holds in both resolve graphs, and both describe THIS tree (same workspace members, same workspace edges as the manifests give by an independent static resolve, the gating feature resolved in the harness document and not in the default one, every package present in `Cargo.lock`). These codes belong to the runner (`metadata_check.py`), not to the typed Rust contract. | `metadata_default_has_edge`, `metadata_harness_missing_edge`, `metadata_harness_dropped_dependency`, `metadata_malformed`, `metadata_members_differ_from_tree`, `metadata_closure_differs_from_manifests`, `metadata_feature_not_resolved`, `metadata_feature_resolved_by_default`, `metadata_not_from_this_lock` |
| Receipt identity | A receipt row carries the contract digest, target, triple, profile, SHA-256 and ELF identity; one digest for two targets, one artifact with two digests, or a missing declared artifact is refused. | `contract_digest_mismatch`, `observed_target_mismatch`, `observed_profile_mismatch`, `observed_digest_mismatch`, `artifact_digest_conflict`, `artifact_not_observed` |

### How the rules are tested

* `tests/p01/reference.py` re-implements the rules from this document, independent of the Rust. 137 shared vectors in
  `crates/franken-board-profile/tests/vectors/p01_contract_vectors.json` (written by hand, regenerated and checked by
  `tests/p01/make_vectors.py`) mutate the declared contract and state exactly which codes and subjects must result. The Rust
  test `crates/franken-board-profile/tests/p01_contract.rs` replays the same file. Every rule has a rejection vector and, where
  there is a permitted behavior, a positive one. `P01-META-005` breaks 43 rules in a copy of the reference one at a time and
  requires the vectors to notice each.
* `tests/p01/facts.py` reads `Cargo.toml`, every member and excluded manifest, `Cargo.lock` and the tree, and holds them to the
  declared contract: members, pending and excluded crates, dependency edges in both directions, lockfile edges, lint policy,
  `[profile.release]` values, gated Cargo features, binaries, and ownership coverage of `crates/*` and `tests/*`. A crate that
  exists but is not a member is allowed only if the contract declares it pending, with a reason. 34 planted-drift cases run the
  same check on a synthetic workspace.
* `tests/p01/metadata_check.py` holds centrally produced `cargo metadata --format-version 1 --locked --offline` documents to the
  speaker gate. `check` is the gate alone (what `scripts/e2e/p01 check-metadata` runs; hand-written documents exercise it in
  `P01-MD-*`). `judge` is the gate plus proof that the documents describe this tree and lockfile, and is what `P01-BLK-007` runs on
  the real documents given as `--metadata-default` and `--metadata-harness`. Without them the case is **blocked**: counted, named
  and never skipped or passed; giving only one of the two is a usage error. With them it passes only if the unplanted documents are
  clean and each of nine faults planted in copies of them is caught with its expected code (a direct and a transitive leak of the
  harness crate into the default build, a harness build that lost the edge, the two documents swapped, a different set of
  workspace members, a workspace edge the manifests still have but the document lacks, the feature not resolved in the harness
  document, the feature resolved in the default one, and a package from a different `Cargo.lock`). A receipt written with
  `--receipts` names the documents by SHA-256, never by path. The comparison with cargo's resolver is independent only on documents
  cargo produced: the unit tests (`JudgeTests`, `MetadataRealCaseTests`) use documents synthesized from the manifests, so they prove
  the judgement and the wiring, not cargo.
* `tests/p01/plan.py` builds the central command plan and `check_plan` holds it to the rules: `rch exec` only, `RCH_REQUIRE_REMOTE=1`,
  no bypass variable, `--locked --offline`, an absolute `--manifest-path`, a working directory that is not the repository root (except the device speaker steps, below), a
  positive job count (`-j N`, default 1: rch admits a build against a worker's slot count and ignores `CARGO_BUILD_JOBS`, so the plan
  names it on every cargo step; one is the default because a one-slot worker cannot admit two, and it changes how long a build takes, not what it builds), and `--target` plus `-Z build-std` for device builds. A device speaker step also carries the contract's linker and static flags as
  inline `--config` arguments (`target.<triple>.linker="<repo>/toolchain/linker/<wrapper>"` and
  `target.<triple>.rustflags=["-C","target-feature=+crt-static","-C","link-self-contained=no"]`) and `check_plan` refuses one that
  lacks either (`plan_device_without_linker`, `plan_device_not_static`). rustc's default for these musl targets is a dynamic PIE that
  needs `ld-musl-*.so.1` (the initramfs has none) and `-lgcc_s` (zig ships none), and the plan that failed to link in run b9d
  was accepted by every earlier rule; the inline form keeps absolute paths and the whole identity in the recorded argv, with no
  discovered config file. Those two steps run from the workspace root and `check_plan` requires it
  (`plan_linker_step_not_from_root`): RCH syncs to the worker only the Cargo closure of the project a step runs from, so from
  `crates/franken-board-profile` the sync was 91 files with no `toolchain/` in it and the build failed with the wrapper not found
  (run b15). The wrapper is mirrored at the same absolute path on the worker and keeps its exec bit, so the absolute form stays; the
  root has no `.cargo/` for cargo to discover. Every other step still must not run from the root. Cargo reads `.cargo/config.toml` from the
  working directory, not from the manifest, so the bootstrap probe's build must name its config with `--config` when run from
  elsewhere. The plan has one toolchain step, plain `rustc -vV`, the compiler a bare `cargo` resolves to on the worker (the repository's
  pin), which the workspace test and the host build use; a receipt records it as `toolchain_default`. There is no `rustc +nightly -vV`
  step: rch drops the `+nightly` and prints the default compiler, so it would label one compiler as another (see "Toolchain" below).
  Only the host-target build carries `RCH_ALLOW_FOREIGN_ARTIFACTS=1`: rch refuses
  to fetch a Linux executable to a macOS operator otherwise, and the file is fetched to be hashed and have its header read, never run.
* `tests/p01/central.py` turns the raw rch logs of a central run into an evidence record and judges it. The logs name the worker's
  address and local paths, so they are not committed; `scripts/e2e/p01 ingest` keeps the revision, the worker's name, each remote
  command with the export directory written `<repo>` (rch's own `--config env.RCH_*` trailer removed), its exit status, the SHA-256
  of the raw log, the compiler facts, the workspace test totals and the artifact identity read from the built files, in
  `toolchain/results/p01/rev-<rev12>/receipt.json` (written exclusively; a rerun never overwrites it). A step counts as `ok` only if
  it ran remotely exactly once, exited 0, and ran the command the plan builds for it. `P01-BLK-001` judges the newest record against
  the CURRENT plan and contract: **pass** only if every step in scope (the toolchain query, the workspace test, the host speaker
  build and the two bootstrap-probe builds) ran the current plan and exited 0 with no failed test; **fail** if a step failed or the
  record is inconsistent; **blocked**, with the stale step or digest named, if the record is for another plan or contract or a step
  never ran. No record at all is blocked too. Evidence is therefore bound to a revision, and a plan or contract change makes it stale
  until the plan is run centrally again.
* **`P01-BLK-002` and `P01-BLK-003` are judged from the same record,** with the same pass/fail/blocked meaning, and are never
  static. `BLK-002` (the four device speaker builds: `speaker-*-full`, and the minimal ones, which are builds of their own): all
  four steps ran the current plan and exited 0, and the four device speaker
  rows (`speaker-{mips,ppc}-{full,min}`) are present and verify against the contract's `linkers`: no `PT_INTERP` or `PT_DYNAMIC`,
  ELF32 big-endian, the right machine, and for MIPS the declared ISA revision and float ABI (PowerPC has no marker; its declaration
  is not measured); a row missing after an exit-0 build fails, an unrun build is stale. `BLK-003` (the Rust replay by the typed
  contract): `ingest` also records the tests of `crates/franken-board-profile/tests/p01_contract.rs` BY NAME from the
  workspace-test log, as the one `running N tests` block whose tests are exactly the `#[test]` functions of that file at the
  revision (a combined log interleaves cargo's `Running ...` stderr headers between the stdout lines, so a block is recognized
  by its own markers and never by a header), with each test's status and the SHA-256 of the test file and of the vectors. The
  case passes only if every one of those tests is `ok`, the record's test file and vectors are the CURRENT ones, the contract
  digest is current and the workspace-test step ran the current plan; a replay test that failed is a **fail**; a log with no
  block of exactly those tests, a test file or vectors changed since the run, or a record from before replay capture is
  **blocked**, never passed on totals.
* **`P01-BLK-005` is judged from E06's committed inventory** (`tests/p01/inventory.py`). The E06 audit
  (`toolchain/results/e06/rev-<rev12>/audit.json` or `audit-<rev12>/audit.json`, `ffw.e06.audit.v1`) records the pinned per-target
  dependency, unsafe and licence facts of ONE lockfile and binds it by hash. The case passes only if an audit binds the CURRENT `Cargo.lock` and agrees with it: every
  external package of the lock pinned (exact version, source, checksum, on every platform that lists it), every pin in the lock, every
  workspace crate recorded, every package record carrying its `unsafe` and `license` fact, all three platforms present, no blocker in
  its summary. An audit of another lock is **blocked**, not wrong, and the delta is named (workspace crates added or removed, pins no
  longer in the lock, packages in the lock never pinned); an audit that binds this lock and disagrees with it, or was edited to claim
  a lock it was not made from, **fails**. `P01-INV-001..004` plant each of these on a synthetic lock and audit, with the unaltered pair
  as the control. What a pass does not show: that any dependency is admitted (the audit's `review` items are human decisions, counted
  and not judged), that E06's unsafe or licence findings are right, or anything about a build, a link or a device. When several
  audits are committed, one that binds the current lock beats any that does not (an older audit beside a current one never blocks it);
  among those a pass is the result and a failing audit of the same lock is named beside it; with none current, the audit with the
  smallest delta is reported. A re-audit is E06's job, a local resolver read of a clean export of the revision, and
  `python3 tests/p01/inventory.py AUDIT.json` judges it before it is committed.
* Receipts (`ffw.p01.receipt.v1`) are written exclusively (a rerun never overwrites an earlier receipt), after every step, and a
  cancelled run leaves a partial receipt marked `incomplete`. Artifact digests and ELF identity are read from the built bytes.

* **Planning reconcile (`P01-REC-001..008`).** Generated planning files (`docs/planning`: the task catalog, the alias map and the
  Beads snapshot) can stay internally consistent while the tracker moves on, so generated validation is not whole-project proof
  until it is compared with the live Beads. `tests/p01/planning_reconcile.py` does that, read-only (it opens nothing for writing,
  starts no process, never invokes `br`, and edits no generated or live field), from a live export (`.beads/issues.jsonl`, or a
  JSON document with an `issues` list and optional `total`/`limit`/`offset`/`has_more`). It compares the complete ID sets, the
  typed dependency edges, titles, descriptions, `acceptance_criteria`, the key-to-issue aliases and the design-package lines,
  and names every difference by a stable code. Cases 001 to 006 run on synthetic worlds that exist only in
  `tests/p01/planning_fixtures.py`: a catalog that matches passes (in memory and through the command line), and each planted
  negative fails with exactly its hand-written codes: a required task absent from the catalog, a change to only
  `acceptance_criteria`, a removed gate edge, a stale or paginated export (four shapes), and one plant for every other compared
  field. Case 007 judges the real files against the real export: `.beads/issues.jsonl` is git-ignored, so a git-archive snapshot
  has none and the case is **blocked** (set `FFW_BEADS_EXPORT` to supply one); where the files differ from the live Beads it is
  blocked too, naming the counts, and never passed. **Required features are compared:** the sole authority is one
  `FFW_REQUIRED_FEATURES_V1` marked, fenced JSON block in the live P01 description, with a nonempty, duplicate-free
  `required_features` list. The generator projects that list onto the existing P01 catalog and snapshot rows while copying
  the complete description byte for byte. The read-only checker compares both projections and the actual workspace
  contract feature declarations with the live list. Missing, malformed or duplicate authority, projection drift, missing
  native features and required-to-optional demotion fail; optional `artwork` and `virtual_house_harness` remain optional.
  Case 008 exercises the permitted positive and each named negative; no mapping from individual features to tasks is inferred. Status, priority, labels and comments are not compared, so a
  later comment or status change on a bead cannot fail it; a changed title, description, `acceptance_criteria` or edge, or a new
  bead, can, until the files are regenerated. **`docs/planning/generate_from_beads.py` regenerates them**, one way: the live export
  in, `task-catalog.json`, `bead-map.json`, `bead-manifest.json`, `beads-snapshot.json` and `bead-bodies/` out. It never runs `br`,
  never writes under `.beads/`, never reads an earlier generated file (so a stale generated value cannot reach the output: the live
  field wins), and does not copy comments, notes, the assignee or the absolute `source_repo_path`. A body that follows the generated
  template is parsed into the catalog's fields (`"form": "template"`); a body written by hand in Beads, with none of the template's own
  lines, is `"form": "freeform"` and `docs/planning/check_planning.py` skips only the template-field checks for it (the whole-body,
  title, edge, count and manifest checks still apply, and a templated body marked freeform is refused). A live body with no
  `Mapped design packages:` line maps to no package. A body that starts like the template but does not parse is refused by name.
  `docs/planning/render_planning.py` rebuilds the same files from `docs/SLIM_SPEAKER_PLAN.md`, the opposite direction, and would
  overwrite what is live: run the generator, not that script, for these files.

### What a pass does not show

This is a host check. It never runs cargo, rch, QEMU or a device; the command plan is printed and checked, not run. The Rust module
and its vector replay were not compiled or run by their author; running them is the supervisor's central step. One author wrote the reference, the vectors and the Rust, so
agreement is a cross-check and not a second author. A receipt is a record of what a build host built, not an attestation of the
remote compiler. Nothing in the declared contract is qualified: no evidence exists.

### Known limits, stated

* The harness, the four native services and `artwork` each have a Cargo flag on `franken-speaker` (`spotify_connect`,
  `airplay2`, `tailnet_native`, `alexa_bridge`, `artwork`: `cargo_feature` in the contract, `owner_crate = "franken-speaker"`), and
  the manifest and the contract name the same flags in both directions (`P01-DRIFT-020`, `P01-DRIFT-035`). A profile that
  disables one is built without its flag, so `speaker-*-min` and `speaker-*-full` are different cargo invocations in different
  target directories (the minimal ones under `variants/minimal_renderer`, step ids
  `build-franken-speaker-<target>-minimal_renderer`) and different files. **Nothing is implemented behind any of these flags yet.**
  A build that selects a service reports it selected, unimplemented and unqualified, never ready; one that does not select it
  reports it absent (`crates/franken-speaker/src/services.rs`). The speaker binary prints that report with
  `franken-speaker --services` (one `FFW_SERVICE:<feature> absent` or `FFW_SERVICE:<feature> selected unimplemented unqualified`
  line per service, never the word "ready"): the report has a caller in the composition root, so the flags change what the binary
  does and a build that selects the services is not the same file as one that does not. A flag is not evidence, so `admission` does not depend on it: a
  disabled required feature is `required_feature_disabled` and an enabled one is `required_feature_unqualified` until real
  evidence of an accepted kind is bound to the artifact. Each service's bead (S01, A01, T01, X01, and artwork's owner) takes over its
  own flag: it puts its implementation behind it and changes its entry in `NativeService::implemented`; that is not this
  contract's work. `protected_render` and `synchronized_groups` have no flag: they are the render path and the group session the
  speaker is built from, so a flag would either remove the speaker or change nothing observable. A receipt's
  `unbacked_disabled_features` now lists what the artifact's own build cannot omit: the bootstrap probe's required features (it is
  built from a crate that carries none of the flags). `P01-BLK-006` judges the flags from the tree (contract, manifest, the
  speaker's source, the `--services` option in `main.rs` and the real-binary tests in `crates/franken-speaker/tests/cli_services.rs`,
  the command plan, admission) and that the Rust tests which prove the behaviour exist by name, and it then passes only if the newest
  central run, current for the plan and contract, shows the full and the minimal device speakers as different files (it is
  **blocked**, named, until such a run is ingested; the same digest for both is a **fail**), **and** shows the Rust tests that
  prove the behaviour passing **by name**. There are 32 per configuration: 22 that do not depend on a service flag (13 library
  tests and 9 real-binary tests, 3 of which keep the old behaviour of a host build without the harness), and per service a
  library test and a real-binary test that are the off pair with no service flag or the on pair with all five (the real-binary
  tests start the built binary and compare what it prints with the build's own selection). The `default` configuration is read from the `workspace-test` log
  and the `all_on` one from the plan step `test-franken-speaker-services` (`cargo test -p franken-speaker --lib --test
  cli_services` with the five flags, bare `cargo` on the pin). `scripts/e2e/p01 ingest` records, for each wanted name, the status
  libtest printed (a name the log does not show is left out of the record) and the SHA-256 of `services.rs` and `cli_services.rs`
  as the ingested revision holds them (the raw logs stay uncommitted). The verdicts: a step that never ran, a different command,
  a name the log does not show, a record made before this capture, or source files that have changed since the run is
  **blocked** and named; a named test that printed `FAILED` or `ignored`, or a step that exited non-zero, is a **fail**. What it
  proves is a central run of the **host** test binary on a worker: the device ELFs are built (and shown different) but never run
  here, and `main.rs` is not hashed (the static check holds its `--services` arm).
* `franken-test-support` is gated out of `franken-speaker`: it is an optional dependency behind the off-by-default `harness` Cargo
  feature (plus a dev-dependency for unit tests), and the whole Virtual House harness is every module that
  `crates/franken-speaker/src/lib.rs` declares under `#[cfg(any(test, feature = "harness"))]` (`harness.rs` and the helpers it uses,
  `clock_log.rs`, `playout_adapter.rs` and `control_adapter.rs`; a module added under that attribute joins it), compiled only for unit
  tests or with `--features harness`. A default (device) speaker build has no dependency edge onto it. The
  contract models this as an optional dependency (`virtual_house_harness`, `cargo_feature = "harness"`); device profiles disable
  the feature, the `host_full` profile enables it, and the test-support exception list is empty. `--virtual-house` and `--self-test`
  now need `--features harness`; the default `franken-speaker` binary supports `--catalog` only. The default speaker build is
  checked from the manifests (`P01-CON-004`, `P01-RESOLVE-*`) and from `cargo metadata` (`P01-MD-*` on hand-written documents;
  `P01-BLK-007` on the real ones: judged when `--metadata-default`/`--metadata-harness` are given, blocked when not).
* The linker block and the static and ABI rules are checked here on hand-written rows and on ELF files built by the tests, and
  `P01-BLK-002` checks them on the rows read from the device speakers a central run actually built and linked. That is a
  statement about those files' headers (static, machine, ISA revision and float ABI where the ELF states it). It is not a
  statement that they run: a boot on a guest is a separate result (a smoke run, with its own markers), and at the time of
  the first links the speaker's default binary printed a catalog while linking most of the stack without calling it.
* The ISA revision and float ABI in `linkers` are the ones rustc's target spec asks for (MIPS: soft-float `mips32r2`, o32;
  PowerPC: hard-float). They are rustc tier-3 assumptions, not facts about the device, whose image evidence records no ABI for the
  MIPS board, so every device artifact stays `unqualified`. PowerPC's float ABI is declared by the wrapper's zig target and not
  measured; counting FPU instructions would be a heuristic and is not a gate.
* `link-self-contained=no` in the static flags is inferred from the target specs, not yet run. If rustc still adds its own crt
  objects the first link fails on a missing `crt1.o` and the fix is one flag. A worker that sets `RUSTFLAGS` in its environment
  silently overrides `target.*.rustflags` (cargo gives the environment precedence); the static check on the built file is what would
  catch it.
* The linker wrappers (`toolchain/linker/`) are repository files whose digest and exec bit the drift check holds
  (`linker_wrapper_missing`, `linker_wrapper_digest_mismatch`, `linker_wrapper_not_executable`); they enforce the worker's zig
  version themselves and exit 97 on a mismatch. `scripts/e2e/p01 ingest` reads the contract at the named revision under the current
  schema, so a revision from before the `linkers` block cannot be ingested; run the plan at a revision that has it.
* Owners are bead identifiers proposed by this contract; the lane owners ratify them.

### Toolchain (P01-BLK-004: judged; it passes only from a central record made under the pin)

**The pin.** The repository root holds `rust-toolchain.toml`: `[toolchain]`, `channel = "1.99.0"`, and nothing else. A bare `cargo` (the
workspace test, the host speaker build, every `cargo test -p …` line in `scripts/e2e/*`) resolves it. The channel is an EXACT release,
never `nightly`, `stable`, `beta`, a dated nightly or `X.Y`, because a floating channel is whatever each worker has that day. It names no
`components`, `targets` or `profile`: the supervisor proved only the bare channel on the workers, and a legacy `rust-toolchain` file beside
it is refused. The floor is Rust 1.88 (edition 2024, `if let` chains); the guest's nightly (`-Z build-std`) stays explicit in each build
command and is not part of the pin, because `cargo +X` overrides it.

**A correction.** An earlier version of this section said there was no stable release a pin could name and left the decision to the owner.
That read only each worker's DEFAULT compiler (a nightly). The supervisor then established through `RCH_REQUIRE_REMOTE=1 rch exec` (mail 5443;
these observations are not in a committed record) that with this file at the root a bare `cargo` resolves `1.99.0` (commit `b940084d7eb6`) on
the workers that have it; that a worker without it refuses (`RCH-I006 missing_runtime`) and never substitutes another compiler; that
`cargo +nightly-2026-08-31` builds with that nightly whatever the pin says; and that `rustc +X -vV` drops the `+X` and prints the default
compiler (which is why `rustc +stable -vV` once printed a nightly), while `cargo +X rustc -- -vV` is refused (`RCH-E301`). The 1.99.0 workspace
checks and clippy and 218 `franken-speaker` lib tests ran green there; the workspace tests on 1.99.0 had not run.

**The plan.** Device builds ask for ONE dated nightly, `plan.DEVICE_TOOLCHAIN` (`nightly-2026-08-31`), held in that one constant; host builds
ask for no selector (they resolve the pin); no step asks `rustc +X`. The `rustc +nightly -vV` step is gone. Beside the toolchain name sits
the compiler string it must produce, `plan.DEVICE_RUSTC_VERSION` (`1.100.0-nightly (908501772 2026-08-30)`): a dated nightly is immutable, so
this is a fact of the date, MEASURED with `rustc +nightly-2026-08-31 -V` on a host that has the toolchain (2026-11-05); its commit prefix
agrees with the commit `90850177249e` the supervisor saw on a worker. It has not yet been seen in a central receipt, so the first receipt is
its test: it either shows exactly this or `P01-BLK-004` fails with both strings. The plan check keeps the two constants in step (the string's
commit date must be within three days before the toolchain's date, never after it; measured on five dated nightlies: one day before on four,
three on the one that follows a holiday weekend).

**What is judged (`tests/p01/toolchain.py`, `P01-BLK-004`; `P01-TC-001..005` plant each rule on a synthetic pin file, plan and record).**
1. The pin file is exactly one exact `channel`, nothing else (`pin_*` findings).
2. The plan's device lines carry `+<plan.DEVICE_TOOLCHAIN>` and that constant is a dated nightly, host lines carry no selector, and no
   `rustc +X` step exists (`plan_*` findings).
3. A committed central record names the compiler that built what it holds. `ingest` records the pin file as the revision holds it
   (`toolchain_pin`: file, sha256, channel, or null when the revision has none) and, per built artifact, the `rustc version …` strings found
   in the artifact's own bytes (`artifact_compilers`; rustc leaves it in `.comment`, and it survives `strip = "symbols"`; read on the real
   stripped BE-MIPS and PowerPC device ELFs and the host ELF of the e77f24d and 53f83cf runs). The case requires: the record's steps are the
   current plan's and exited 0 (`central.judge`); `toolchain_default.release` equals the pin; every host artifact names the pin's release and
   is not a nightly; and every device artifact names exactly `plan.DEVICE_RUSTC_VERSION` (one string, the same for every device artifact).

**Verdicts.** A pin file or plan that breaks a rule is a **fail**. No committed record, a record made before the pin or before artifact
compilers were recorded, a record made under another pin, or a stale record is **blocked** with "no receipt for this compiler", never a
pass. A record whose bare `cargo` or artifacts name another compiler is a **fail**. The case passes only from a record made on a revision
that has the pin; before the supervisor's central run of this plan it reads blocked.
Seen on the real runs before any pin: the PowerPC `ffw-hello-init` of the 53f83cf run was built by `1.101.0-nightly (2d20b42b8 2026-11-04)`
and every other device artifact by `1.101.0-nightly (708c94ef0 2026-11-03)`: two floating nightlies in one plan run. `device_artifacts_disagree`
is that finding.

**Not shown.** That `rch --clean-overlay` resolves the toolchain from the committed file (the supervisor's central line, after landing); that

### Tiers and the diagnostic log (the original test-asset and logging clauses)

**Tiers are explicit.** `run_cases.py --tier smoke|full|soak` has no default. `smoke` and `full` select cases (a case lists the tiers it
belongs to; the blocked ones stay counted, so the full tier exits 3 until the central records exist). **`soak` is NOT RUN, and says so:**
P01 is a one-shot offline check (manifests, the lockfile, fixed vectors, committed central records), nothing in it is long-running,
randomised or repeated, so there is nothing to soak. `--tier soak` executes no case, prints why on stderr, writes a receipt that says
`status: not_run, qualified: false` and the reason when `--receipts` is given, and **exits 4**, which is not a pass (the E06 runner
exits 4 for the same reason). A soak of the render path, the group clock or a provider belongs to the owners of those features, on their own
targets. Combined with `--case`, `--list` or the metadata flags, or with an unknown or missing tier, the runner refuses with exit 2
(`P01-SOAK-001`, `INV-P01-28`). Exit codes: 0 qualified; 1 a case failed **or the run's evidence is incomplete**; 3 only blocked cases stand in
the way; 2 usage; 4 soak.

**Every executed case is logged, through the shared sink and no logger of our own.** `tests/p01/case_log.py` is an adapter over
`scripts/test/test_support/diagnostics.py` (`DiagnosticSink`, schema `ff.diag.v1`, loaded by explicit path as `scripts/test/run-suite`
does). For each case the runner actually executes it emits a CRITICAL `case.begin` and a CRITICAL `case.end` (status, the detail clipped to
600 characters, duration, the causal error chain of a case that raised) and, last, one CRITICAL `run.summary`. The log goes beside the
receipt (`--receipts DIR` -> `p01-diag-<tier>-<run id>.jsonl`, created exclusively, so a rerun never overwrites or appends to the first
run's evidence); with no receipts directory the same sink writes a temporary file that is audited and removed. The receipt carries
`evidence` (`complete`, `reasons`, the `log` block: sha256, events, dropped, bytes, truncated, critical_lost, and the sink's
`ff.diag.summary.v1`) and `outcome`. The receipt schema stays `ffw.p01.case_receipt.v1`; the fields are additive.

**What the sink guarantees, and what the runner adds.** The sink never blocks the caller, never raises and never performs I/O in `emit()`;
event rate, queue, event size and file size are bounded; every event ends as written or dropped with a counted reason; secrets, tokens,
account and site identifiers, MAC and e-mail addresses and the home directory are redacted before anything is queued. The runner then
closes it, re-reads the file with the shared `audit_log` (header first, footer last, monotonic order, the closure identity `emitted =
written + dropped`) and checks that the number of critical events equals the `2 x cases + 1` this run must have written, independently of
the sink's own accounting. **Evidence is complete only if all three agree.** A lost critical event, a torn, unreadable or never-closed log,
a hung writer, an existing log at the same path, a shared module that does not load, or a case with no end event makes the evidence
incomplete: the run is `incomplete`, **not qualified, and exits 1 even if every case passed**; a failure stays a failure and a blocked case stays
blocked (`run_cases.judge_run`). A slow, full or unavailable sink costs evidence, never a verdict (`P01-LOG-001` plants each).

**The original logging invariant, mapped to what exists.**

| Original requirement | Where it is met here |
|---|---|
| versioned structured JSONL plus a concise human summary | `ff.diag.v1` from the shared sink; the printed case lines and the one `diag run=...` summary line (`format_summary`) |
| monotonic timestamps and timebase; run, case and correlation ids | the sink's header `timebase` and per-event `mono_ns`; `run` = `p01-<tier>-<run id>`, `case` = the case id, `corr` = `<run id>.<case id>` |
| bound event rate, memory and disk; dropped-event counts exposed | the sink's token bucket, queue and file limits; `dropped` in the receipt's `log` block and the footer; `INV-P01-29` |
| redact tokens, keys, account and site identifiers, audio payloads | the sink's redaction (a secret value, a token and the home directory are planted in `P01-LOG-001`); `P01-META-003` scans the P01 files for site data |
| the causal error chain and the first causal event | `cause` on `case.end` of a case that raised; the case's own detail names the code and subject |
| the injected fault schedule | the planted fixtures of this runner are named by case id (`P01-DRIFT-*`, `P01-TC-*`, `P01-INV-*`, `P01-REC-*`, `P01-BLK-007`'s nine faults); each one's expected and observed codes are in its logged detail |
| critical test evidence loss marks the result incomplete | `Evidence.complete`, `judge_run`, `P01-LOG-001`, `SoakAndDiagnosticsTests` |
| slow, full or unavailable log sinks do not change the verdicts | `P01-LOG-001` plants a full, an unavailable and a hung sink and requires every verdict to be unchanged |

**Genuinely inapplicable here, with the reason (`INV-P01-30`).** Pseudonymous member and group ids, source epoch, command and state revision,
and queue, latency and resource counters: a P01 run has no member, group, source, command stream, queue or audio, so a field for any of them
would be invented. "Slow, full or unavailable sinks do not change audio deadlines": there is no render path and no deadline in a host check of
manifests and records; the deadline property is the Q-series' on-target work, and the sink's own nonblocking guarantee is the shared module's
tested contract (`scripts/test/test_support/test_diagnostics.py`), which `P01-LOG-001` exercises through the runner rather than restates.

**What this does not show.** It proves the runner's own evidence handling on the host. It does not qualify any device, provider or render
path, does not make a missing central record a pass, and adds no mutation campaign: the planted worlds are fixtures with their controls.
