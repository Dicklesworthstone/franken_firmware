# Contract N01 — Authenticated Stream Framing (`ffw-ey5`)

**Status: implemented offline in `crates/franken-stream`; central verification pending; bead open.**
Scope is the datagram framing, its authentication, and the receive-side admission gate. Compatibility
negotiation, transport lifecycle (N07), the control channel (N02) and FEC coding (N05/N06) are not
specified here. Nothing in this contract touches a device, a network beyond loopback, or a provider.

## 1. Datagram

A datagram is `header (64 B) || payload (4..=1024 B, multiple of 4) || tag (16 B)`. Total 84..=1104
bytes. Every integer is big-endian; no native struct is serialized.

| Offset | Size | Field | Rule |
|---|---|---|---|
| 0 | 4 | magic | `FFWS` |
| 4 | 1 | version | `1`; any other value is rejected, never interpreted |
| 5 | 1 | kind | `1` media, `2` repair; others rejected |
| 6 | 1 | flags | `0xF0` critical bits: any set bit is rejected. `0x0F` ignorable: accepted, preserved, authenticated |
| 7 | 1 | format | `1` = signed 16-bit big-endian stereo PCM, 48 kHz; others rejected |
| 8 | 8 | stream_id | nonzero; random per stream start (§4) |
| 16 | 8 | epoch | group-transition epoch (§4) |
| 24 | 8 | seq | per (stream, epoch), starts at 0; `u64::MAX` reserved |
| 32 | 8 | start_frame | multiple of 256 (a defined frame boundary, not a receive time) |
| 40 | 8 | presentation_time_ns | at most 2^62 ns |
| 48 | 8 | consume_by_ns | at most `presentation_time_ns` |
| 56 | 2 | fec_group_id | coding block |
| 58 | 1 | fec_index | symbol position |
| 59 | 1 | fec_group_size | media: 0 (no FEC, index must be 0) or 1..=16 with index < size. repair: 1..=16, index < 16 |
| 60 | 2 | frame_count | 1..=256 and `payload_len == frame_count * 4` (frame count is derived and checked) |
| 62 | 2 | payload_len | at most 1024 |

There are no reserved bytes: a field a receiver might silently ignore is either defined as ignorable
(`flags & 0x0F`) or rejected.

## 2. Authentication

`tag = HMAC-SHA256(key, "FFWS-v1-auth" || header || payload)[0..16]`, compared in constant time. The
tag therefore covers every routing, timing, epoch, format and payload byte, and the context prefix
separates this protocol's MACs from any other that shares key material. The key is one shared 32-byte
stream key; it is never serialized, formatted, or logged (`StreamKey` prints `[REDACTED]`).

Threat model: this stops forgery, mutation and replay by parties without the key. A party **with** the
key can still send authenticated packets, so admission is additionally bounded (§3 step 7, §4) so that
one such packet cannot fence out the genuine stream. Per-sender keys or signatures are out of scope.

## 3. Receive order (`StreamReceiver::accept`)

1. Length: under 80 B is `PACKET_TOO_SHORT`; over 1104 B is `DATAGRAM_TOO_LONG`.
2. Magic, then version (`BAD_MAGIC`, `UNSUPPORTED_VERSION`).
3. Declared `payload_len` over 1024 is `PAYLOAD_TOO_LARGE`; the datagram must be exactly
   `64 + payload_len + 16` (`TRUNCATED`, `TRAILING_BYTES`). Steps 1-3 are O(1) and run before any MAC,
   so unauthenticated garbage costs no hashing. `mac_verifications` counts MACs actually computed.
4. MAC (`AUTH_FAILED`). Nothing below runs, and no state changes, before this passes.
5. Field validation in table order (`UNKNOWN_PACKET_KIND`, `UNKNOWN_CRITICAL_FLAGS`, `UNKNOWN_FORMAT`,
   `FRAME_COUNT_OUT_OF_RANGE`, `FRAME_COUNT_MISMATCH`, `MISALIGNED_START_FRAME`, `INVALID_TIMESTAMPS`,
   `INVALID_FEC_FIELDS`, `INVALID_STREAM_ID`). The encoder runs the same validation, so a sender cannot
   emit a frame its own receiver rejects.
6. `stream_id` must equal the bound stream (`WRONG_STREAM`).
7. Epoch and sequence (§4). Only now, if every earlier step passed, is the window updated.

A rejected datagram changes only the counters. In particular a tampered copy never consumes its
sequence number: the genuine datagram with that number is still admitted afterwards.

## 4. Identity, epoch, sequence

- `stream_id`: drawn by the sender from admitted entropy at every start. A restarted or rekeyed sender
  uses a fresh one and the receiver is told over the control channel (`bind_stream`); packets of the
  previous stream are then `WRONG_STREAM`, and the new stream reusing sequence 0 is not a replay. This
  is what makes (key, stream_id, epoch, seq) unique across restart and rekey. A sender with no admitted
  entropy must not transmit (`StreamId::new(0)` is refused).
- `epoch`: monotonically increasing within its authority. **Media packets never advance it.** A newer
  epoch is announced by the authenticated control channel (`advance_epoch`); a newer epoch seen in
  media is `FUTURE_EPOCH` and ignored; an older one is `STALE_EPOCH` and ignored. The stream is not
  modified by either.
- `seq`: starts at 0 in every epoch (or at a seeded origin for a mid-stream join). The receiver keeps a
  64-packet reorder window: up to 63 behind the highest is admitted once; 64 or more behind, or already
  seen, is `REPLAY_OR_DUPLICATE`. A packet more than **1024** ahead of the highest (or of the origin,
  for the first packet) is discarded and counted as `FUTURE_SEQUENCE` and leaves the window untouched.
  1024 is a provisional bound (about 5.4 s of blocks) chosen so loss bursts pass while a forged huge
  `seq` cannot turn every genuine packet into a replay. The sender stops at `u64::MAX`
  (`SEQUENCE_EXHAUSTED`) and must advance the epoch.

## 5. Diagnostics

Every error is built from integers; none can carry a key, tag or payload byte. `ReceiverCounters` has
one field per reason plus `accepted` and `mac_verifications`; `datagrams_seen == accepted + sum(rejected_*)`.
A bad version is reported as `UNSUPPORTED_VERSION` with the offending number and counted; **this layer
sends no response datagram** (an unauthenticated reply is an amplification vector). A rate-limited,
authenticated diagnostic reply belongs to N02/N07.

## 6. What jitter-buffer admission assumes

`BoundedJitterBuffer::push_packet` rejects non-media packets and reports undecodable PCM truthfully
(`NOT_MEDIA_PACKET`, `PAYLOAD_FORMAT_MISMATCH`). It still accepts any `AuthenticatedStreamPacket` value
a caller builds, so "authenticated before scheduling" is guaranteed by routing every datagram through
`StreamReceiver::accept`, not by the type system. Making the buffer take only receiver output is a
possible hardening, not done.

## 7. Verification

| Evidence | Command | Class |
|---|---|---|
| Independent reference, vectors, reference self-checks (17) | `scripts/e2e/n01` | offline host, Python stdlib; **does not run the Rust code** |
| Rust unit/property/vector tests, loopback UDP exchange | `RCH_REQUIRE_REMOTE=1 rch exec -- cargo test -p franken-stream` | central host build, little-endian host |
| Format, lint | `... cargo fmt --all -- --check`, `... cargo clippy -p franken-stream --all-targets -- -D warnings` | central |

`crates/franken-stream/tests/vectors/n01_wire_vectors.json` is generated by `tests/n01/reference_frames.py`
(37 vectors: 7 accepted incl. a byte-ordered field probe and min/max values, 30 rejected; 2 scenarios,
426 steps, one hand-written and one seeded random walk; every receive-path rejection code is exercised
by at least one vector or scenario step, which the reference checks). Expected
codes for rejection vectors and the hand-written scenario are written by hand; the reference replay
window is a set model, a different algorithm from the Rust bitmap. The Rust tests require byte-exact
agreement in both directions (decode and re-encode). The MAC primitive is cross-checked in Python
against RFC 4231 cases 1, 2 and 5 (128-bit truncation).

Mapping of acceptance items: golden vectors across endianness, §1 + GV-004/006/007 (byte-exact BE
layout; **no big-endian target execution was performed**); reject oversize, duplicate/replay, stale
epoch, unknown critical fields, GV-112/113, GV-116, SC-001/002; fuzz offline, seeded deterministic
mutation/truncation/garbage tests (not coverage-guided fuzzing); reject before scheduling and cap
unauthenticated work, §3 and the `mac_verifications` assertions; two real endpoints on loopback,
`tests/n01_loopback.rs`.

## 8. Not done (stays open)

- Compatibility negotiation for mixed firmware revisions (supported range, mandatory capabilities,
  authenticated capability binding, downgrade tests): not specified or implemented.
- Execution on a big-endian target (QEMU MIPS/PPC) and any measurement on real hardware.
- Coverage-guided fuzzing and a long-run soak; the property tests are bounded and seeded.
- Wiring the key and `stream_id` entropy to the P01 typed secret store; key zeroization (no zeroize
  dependency is admitted); key rotation beyond "new stream_id plus control-channel rebind".
- The `scripts/e2e/n01` entry covers only the reference side; the Q00 runner registration and the Q07
  real-process end-to-end are not done.
