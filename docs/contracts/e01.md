# E01 contract: reconcile device and firmware identity evidence

Bead `ffw-xdi`. Implementation: `inventory/reconcile.py`. Tests: `inventory/test_reconcile.py`
(unit/property), `tests/e01/` (named end-to-end cases, run with `tests/e01/e2e`),
`tests/e01/mutation_check.py` (planted-defect check). `scripts/e2e/e01` is the bead's entry point and
delegates to `tests/e01/e2e` (no arguments = full tier).

**Authority.** Offline engineering only. The tool reads files named on its command line and writes
files named on its command line. It never contacts a device, never scans a network, never touches
credentials or firmware images. Output is *evidence-complete or not*; it is not an activation
decision. Production admission of a profile is a separate update-policy decision (U02).

**What this does not prove.** Synthetic fixtures show the rules behave as written. They are not
evidence about any speaker. The seed evidence registry records no image digests, so no live
profile resolves yet (see *Known gaps*). Tests do not prove perfection.

## 1. Inputs

| Flag | Content |
|---|---|
| `--input PATH` (required, repeatable) | Observation batch: `{"observed_at"?, "devices": [{"url"?, "fields": {...}, "status"?: {...}, "observed_at"?}]}` (the `scan.py` / `enrich.py` shape), or a raw `device_description.xml`. No stdin, no directory discovery. |
| `--evidence PATH` (repeatable) | Image-evidence registry, schema `ffw.e01.image-evidence.v1` (section 5). |
| `--hypotheses PATH` | Published-teardown notes, read with `enrich.load_profiles` (legacy `hardware-profiles.json` or the versioned `ffw.published-hardware-profiles` shape; unknown keys are rejected). Referenced, never used for selection. |
| `--nominal-unit MB\|MiB` | Declares the unit of *bare* `memory`/`flash` numbers. Without it the unit is unknown. |
| `--allow-incomplete` | Exit 0 even when the result is incomplete (default: exit 3). |

**Shared engines (no private fallback).** `inventory/identity.py` is the single authority for the
canonical form of model, hardware revision, software build and generation, and for nominal sizes and
their units, and for the `profile_id` formula; `inventory/enrich.py` loads published-profile
documents. `reconcile.py` loads both lazily by path (nothing runs at import) and refuses to run (exit
2, `shared_module_missing`) if one is absent. What stays here: file I/O, the CLI, device dedupe by
strong identifier, conflict handling, evidence matching, output safety.

**One XML rule.** A raw `device_description.xml` is read by the public `reconcile.parse_description_xml`
only (`scan.py` now calls it too and imports no XML module):
* The device is the first `<device>` in document order that is in the UPnP device namespace
  `urn:schemas-upnp-org:device-1-0` (exact match; a default or a prefixed binding both work). Only its
  direct leaf children in that same namespace are fields. A `<device>` in another namespace or none
  is never used, so a look-alike device cannot supply the unit's values; a field in a foreign
  namespace (or `xmlns=""`) is ignored, so a look-alike `serialNum` can neither override a real one
  nor conflict with it. If the only `device` elements are un-namespaced or foreign the document is
  refused with `xml_namespace`; a document with no `device` at all is `xml_shape`.
* Nothing is read from the sub-devices real speakers embed (MediaServer/MediaRenderer).
* DOCTYPE/ENTITY declarations are refused, a repeated field with differing text is refused, and the
  input is size-bounded. Errors cite a code, never document content.

Why namespace-strict, and why no no-namespace compatibility: on the owner's 17 real description files
the root and the device are in the UPnP namespace 17/17 and all 599 direct leaf fields are too (0
foreign-namespace leaf fields); only synthetic fixtures are un-namespaced. All 11 identity/hardware
fields are direct children of the first device. In 14 of the 17 files nested devices repeat `UDN` (and
only `UDN`) with different text, which is what the old whole-tree "last wins" flattening in `scan.py`
stored for those units. The UDN base id is shared, so the `_MS`/`_MR` normalisation keeps identity
correct for captures made that way, but that stored `UDN` is not the root device's. Other tools
should call this function rather than write another parser.

Only these keys are read from a record: `serialNum MACAddress UDN deviceID modelNumber modelName
seriesid variant hardwareVersion softwareVersion swGen memory flash roomName friendlyName`, and from
`status`: `SerialNumber MACAddress IPAddress HouseholdControlID LocalUID ZoneName HardwareVersion
SeriesID Variant SoftwareVersion SWGen`. Everything else, including the legacy
`published_hardware_profile` block the old script attached, is ignored.

Bounds (fail closed, exit 2): 8 MiB per file, 4096 records per batch, 256 batches, 1024 chars per
value, duplicate JSON keys refused, XML with `DOCTYPE`/`ENTITY` refused.

## 2. Identity model

* Strong identifiers: serial, MAC, UDN. Normalised (case, separators; the `_MR`/`_MS` sub-device
  suffix of a UDN is stripped, so one speaker is not split by it).
* Observations that share any strong identifier are one **device** (union-find, so A-B via MAC and
  B-C via UDN make A, B, C one device). The partition does not depend on input order.
* A device whose observations carry two different values of one identifier kind (one serial with two
  MACs, one MAC under two serials) is **`identity_ambiguous`**: it is never merged silently and is
  excluded from every profile; it is listed under `conflicts` as ineligible.
* No usable identifier: counted as `unidentifiable_observations`, never attributed.
* Duplicates (identical content) are counted. A rename (room/friendly name) or an address change
  merges into the same device and is visible only in the private report.

## 3. Field classes

| Class | Fields | Disagreement between observations of one device |
|---|---|---|
| Immutable hardware | `modelNumber modelName seriesid variant hardwareVersion memory flash` (description XML and status/zp are compared with each other too) | `hardware_field_conflict`, device excluded |
| Firmware | `softwareVersion swGen` | Ordered by `observed_at` (record's own, else the batch's). Latest wins and the change is history. Missing timestamp or a tie: `firmware_unordered_conflict`. |
| Mutable, private only | room/friendly names, URL host, status IP | Recorded in the private report as `renamed` / `address_changed`; never public. |

Nominal sizes are *device-reported nominal*, `measured: false`, with `bytes` computed by identity.py
(`MB` = 10^6, `MiB` = 2^20: they differ). A bare number is never assumed to be MB: it is reported as
`{"value": 32, "unit": null, "unit_basis": "unknown", "bytes": null}` and blocks resolution
(`nominal_size_unit_unknown`) until the operator declares a unit, which is then labelled
`operator_asserted`. A unit stated in the value (`128 MiB`) is `device_stated` and wins over
`--nominal-unit`. A bare number agrees with the same quantity written with a unit. Unit grammar is
identity's: `128 mb` and `128 Mbit` are unrecognised units, an over-long unit word is malformed.

Model and revision are canonicalised by identity.py before grouping (`s5` = `S5`; `Sub` is reported as
`SUB`; `01.008.3.1-02` = `1.8.3.1-2`), so equivalent spellings are one profile in any order.
`sw_gen` is an integer. Other public-bound text (series, variant, model name) must be a short plain
token (`[A-Za-z0-9][A-Za-z0-9 ._:+/()-]{0,63}`); otherwise the value is withheld and
`hardware_field_malformed` is reported.

## 4. Profile entries and identifiers

Devices with identical `(model, name, series, variant, revision, memory, flash, firmware line,
sw_gen)` form one entry.

* `profile_id` is `identity.profile_id_for(model, revision)`: `bp-` + 16 hex of SHA-256 over canonical
  JSON `{"schema":"ffw.identity/v1","kind":"board-profile-id","product_model":M,"hardware_revision":R}`
  with M and R canonicalised. A function of model and revision only; `null` unless both resolve.
  Extra devices, firmware changes and different evidence do not move it. `enrich.py` calls the same
  function (`E01-CROSS-CALLER`, `E01-E2E-014`); independent `shasum` goldens pin it
  (`E01-ID-CROSSCHECK`).
* `evidence_digest` = bare 64-hex SHA-256 over the whole entry (domain `ffw.e01.evidence-digest.v1`),
  always present, under a digest key the shared scanner recognises; any change in evidence, reasons
  or counts changes it.
* `resolution`: `resolved` (no conflict/blocking reason), `unresolved` (blocking reason), `conflicted`
  (any conflict reason). `activation_eligible` is true only for `resolved`, and means
  *E01 evidence is complete*, nothing more (`admission_scope` says so in the output).
* Public output carries counts and class-level values only. No per-device value and no hash of an
  identifier appears (serials embed the MAC, so a hash would be reversible).

## 5. Evidence and ISA

ISA, ABI and image digest come **only** from registry records, never from product era, product
family, firmware generation or a published teardown. Record shape:

```json
{"evidence_id": "ev-...", "join": {"model_number": "S5|null", "join_basis": "image-verified|owner-attested|name-inferred|unmapped"},
 "firmware_lines": ["57.23"], "hardware_revisions": ["..."],
 "claim": {"machine": "powerpc|mips|arm|aarch64|x86|x86_64|riscv", "elf_class": 32, "endianness": "big",
           "abi": "...", "float_abi": "...", "atomic_widths": [8, 16, 32]},
 "image": {"name": "anacapad", "digest": "sha256:<64 hex>|null"},
 "provenance": {"source": "relative doc reference", "basis": "what the claim rests on"}}
```

* A record applies to a device only if the join is **attested** (`image-verified` or
  `owner-attested`), the model matches exactly, the device's firmware line is listed, and, when the
  record lists `hardware_revisions`, the revision is listed. Near misses are reported
  (`isa_evidence_firmware_line_mismatch`, `isa_evidence_revision_mismatch`,
  `isa_evidence_join_unattested`), never extrapolated.
* Matched records that disagree on ISA/ABI/atomic widths, or records that give one digest two ISAs,
  produce `isa_evidence_conflict`: the ISA is withheld.
* One image name with two digests: `image_digest_conflict`. No digest at all: `image_digest_absent`.
* Registry digests are written `sha256:<64 hex>`; the manifest emits `{"digest": "<64 hex>",
  "digest_algorithm": "sha256"}` (bare hex under the key `digest`, which the shared scanner is told
  is a digest key). Join models and `hardware_revisions` are canonicalised like device values.
* A malformed registry is refused wholesale (exit 2); a bad record is never partly used.

## 6. Reason codes

`conflict` makes an entry `conflicted`; `blocking` makes it `unresolved`; `info` is a diagnostic.

| Code | Severity | Meaning |
|---|---|---|
| `firmware_unordered_conflict` | conflict | Observations of one device disagree on a firmware field and cannot be ordered by `observed_at`. |
| `hardware_field_conflict` | conflict | Observations of one device disagree on an immutable hardware field. |
| `identity_ambiguous` | conflict | Strong identifiers (serial, MAC, UDN) link observations that disagree on another identifier; the group is not counted as a device. |
| `image_digest_conflict` | conflict | One image name carries different digests in the matched evidence. |
| `isa_evidence_conflict` | conflict | Matched image-evidence records contradict each other on ISA, ABI or atomic widths. |
| `abi_not_recorded` | blocking | Matched evidence does not record an ABI. |
| `firmware_line_unknown` | blocking | `softwareVersion` is absent or not `<major>.<minor>-<build>`. |
| `hardware_field_malformed` | blocking | A public-bound hardware field is not a short plain token. |
| `hardware_revision_absent` | blocking | `hardwareVersion` is absent; a model alone cannot select a board. |
| `identity_unidentifiable` | blocking | Observation has no usable strong identifier and cannot be attributed to a device. |
| `image_digest_absent` | blocking | Matched evidence records no image digest. |
| `isa_evidence_absent` | blocking | No image-evidence record exists for this model. |
| `isa_evidence_firmware_line_mismatch` | blocking | Attested evidence exists for this model but not for this firmware line. |
| `isa_evidence_join_unattested` | blocking | Evidence exists for this model but its join to `modelNumber` is not attested (`image-verified` or `owner-attested`). |
| `isa_evidence_revision_mismatch` | blocking | Attested evidence exists for this model/firmware line but not this hardware revision. |
| `model_absent` | blocking | `modelNumber` is absent. |
| `nominal_size_absent` | blocking | Nominal memory or flash is absent. |
| `nominal_size_invalid` | blocking | Nominal size is not a positive whole number. |
| `nominal_size_unit_unknown` | blocking | Nominal size has no unit (bare number) or an unrecognised unit; declare one with `--nominal-unit` only if it is known. |
| `atomic_widths_not_recorded` | info | Matched evidence does not record required atomic widths. |
| `duplicate_batch_ignored` | info | An identical batch was supplied more than once; extra copies were ignored. |
| `evidence_unjoined` | info | An evidence record has no model join and cannot be matched to any device. |
| `float_abi_not_recorded` | info | Matched evidence does not record a float ABI. |
| `identity_mac_malformed` | info | A `MACAddress` value was malformed and ignored for identity. |
| `identity_serial_absent` | info | Device was identified without a serial number. |
| `observed_at_invalid` | info | `observed_at` was not an ISO-8601 timestamp with a timezone. |
| `record_error_only` | info | A record carried only a scan error and was skipped. |
| `record_malformed` | info | A record was malformed and skipped. |

`reconcile.py --list-reason-codes` prints the same catalog; test `E01-DOC-SYNC` keeps this table
complete.

## 7. Outputs and safety

* Default: sanitized public manifest (`ffw.e01.profile-manifest.v1`) on stdout, JSON or `--format md`.
  No wall clock: identical inputs give identical bytes.
* `--private-out` writes the owner-local report (identifiers, run-local ordinals, change history).
  It must be under a `.local-real/` directory or have a `.local.` file name (both git-ignored),
  mode 0600. Ordinals are run-local and do not identify a device across runs.
* **Public structure is an allowlist.** Two independent guards then reject the document (exit 4,
  nothing written). The shared scanner (`identity.find_private_identifiers`, with identifier values
  from the input as canaries) catches IPv4/MAC/`RINCON_`/UUID/long-hex shapes and those values; the
  local guard additionally matches room/friendly names exactly (identity's scanner has no name
  list). The local guard rejects the document if it contains any identifier value seen in the input (substring match), any room/friendly
  name (exact match, unless it equals a public model string), or any IPv4, MAC, `RINCON_`, `uuid:`,
  URL, or absolute-path shape (`hardware_revision` is exempt from the IPv4 shape because real
  revisions look like `1.2.3.4-5.6`). Findings name a path and kind, never the value.
* Errors cite labels and offsets only; unexpected exceptions print the class name and `file:line`
  frames, never exception text.
* Outputs are written through a temp file in the target directory and never replace an input file.
  An existing output needs `--overwrite`. Interruption leaves neither the output nor a temp file.
* Exit codes: 0 everything resolved; 2 usage/input (including a missing shared module); 3 incomplete:
  anything unresolved, conflicted or unattributed, or an empty result (the manifest is still printed or
  written; `--allow-incomplete` turns this into 0); 4 leak guard; 5 output refused; 70 internal;
  130 interrupted.

Planted negatives: `negative_controls` patterns in `tests/e01/cases.json` that the output must *not*
match, and a matcher self-test that runs before every tier (a runner that cannot fail proves
nothing). `python3 -B -I tests/e01/mutation_check.py` plants one deliberate defect at a time in a
temporary copy of `reconcile.py` and requires a test to fail. It first runs an **unmutated control**
on every layer and aborts if the control fails (an earlier version without siblings in the copy
reported 49 bogus "kills"; the control exists to make that impossible). Last run: 55 mutants,
unit 37/37, e2e 13/13, real 5/5 killed, 0 survivors. Some mutants are only caught because two guards
overlap (e.g. the local and shared leak guards), so each guard also has a test only it can pass
(`LEAK-NAME`, `LEAK-SHARED`).

**Genuinely inapplicable.** There is no firmware, device, audio path or provider here, so deadline,
loss, skew, tailnet and video targets from the bead do not apply to E01; they belong to the beads
that name them. The CLI is one-shot with no retry loop (so no retries can launder a flaky pass).
*Cancellation* is covered at two points: `WRITE-INTERRUPT` interrupts output publication and asserts
neither the output nor a temp file survives and a rerun succeeds; `E2E-013` sends a real SIGINT to the
subprocess while it is blocked reading a FIFO input and asserts exit 130 and no files. Publication is
atomic (temp file in the target directory, then link/rename), which `WRITE-FAILURE` also exercises.

## 9. Migration from the old script

Fixed defects: `ET` was never imported (the peer-device path raised `NameError`); the peer device
was forced onto the `S5` profile whatever its model; `FSONOS_PEER_IP` triggered a network fetch at
import; the duplicate check compared against an unset value; the private input file was overwritten
in place; `INVENTORY.md` was regenerated with IPs and room names. Removed: environment switches
`FSONOS_DEVICES_JSON` and `FSONOS_PEER_IP`. Provide extra devices as another `--input`.

## 10. Known gaps (stated, not hidden)

* The repository records no image digest. `inventory/image-evidence.json` seeds two ELF-header
  statements from `FIRMWARE_ASSESSMENT.md` with `digest: null`; the model-16 join to `S5` is
  `name-inferred` and the model-12 record is `unmapped`. Result on the owner's 18 devices: every
  profile is `unresolved` (join unattested or no evidence, plus unit unknown). Resolution needs an
  owner-attested or image-verified join and a recorded digest, supplied in a local registry
  (`*.local.json`) or committed once E03 verifies them.
* `--nominal-unit` is an operator declaration, labelled `operator_asserted`; it is not a measurement.
* The Rust `franken-board-profile` cargo wrapper that briefly occupied `scripts/e2e/e01` is preserved
  byte-for-byte at `scripts/workspace-checks/e01` and builds, so it runs only through the centralized
  RCH path. This contract's end-to-end evidence is the Python runner; it says nothing about that crate.
* `tests/e01/e2e --tier real` reads the owner's private capture and description XMLs and reports
  counts only; it is not part of `smoke`/`full` and is `blocked` (a failure) where those files do not
  exist. `E2E-015` compares the public XML rule with the runner's own read of the real bytes field
  for field, because the pipeline output alone cannot show the difference (sub-device UDNs normalise
  to the same base id).
* `scan.py` (another lane) now calls this rule and writes raw XML under `.local-real/`; this contract
  tests the rule and its real-file behaviour, not the SSDP discovery code. A `devices.json` captured
  before that change still holds sub-device UDNs for the units whose descriptions nest devices;
  identity is unaffected (see above), and a fresh capture replaces them.
* The `model 16` / `model 12` image statements are not joined to live models (see above), so the
  ISA-evidence path is exercised end to end only with synthetic registries.
