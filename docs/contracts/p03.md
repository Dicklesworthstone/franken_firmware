# P03: caller-driven control owner

This is the implemented owner API and its current qualification boundary.
The original P03 acceptance in Beads remains binding and incomplete.

`franken-speaker::runtime::ControlRuntime` is consumed by `SettledRender`.
Production still pins Asupersync `36141e21fd2b47cf931e4c131949dfb1b764875e`.
The experimental P05 consumer at `1a144aa5696f600665e083df601ae4974f6950b5`
is separate; its guest results do not advance the production dependency.

## Admission and ownership

The caller drives one runtime; clones share its admission gate. The configured
logical worker count is one, with zero blocking threads and queued blocking
closures. Root region limits configure four tasks, one child, four obligations
and 64 KiB of region-owned heap. These do not bound total process allocations.
The 256 KiB profile stack allowance is not an enforced limit on the externally
owned calling thread's stack.

The private control-turn factory admits at most 64 bytes of capture and 2 KiB
of concrete future state before construction. This bounds inline layout only,
not the reachable heap. Rejection, completion and peak-layout counters remain
bounded, saturating observations. Cooperative polling cannot preempt a blocking
poll, synchronous storage operation, HAL call or descheduled process.

`service_turn` selects pollable journal ownership and accepts a nonzero
cooperative budget no greater than 20 ms. It checks local Stop and advances
render/drain before retiring control work. Accepted HTTP continuations retain
their original envelope even after observer loss or mailbox replacement.
Eligible signed datagram batches and actual HTTP intake alternate; a stream of
immediately answered reads cannot indefinitely starve accepted datagrams.

`ServiceTurn::http_control` carries the actual durable batch independently of
the HTTP reply. Direct `service_http` callers selecting pollable mode must
drain `take_http_control_completion()` before expecting the next batch to
progress. The single retained slot backpressures further polling and prevents
stopped-owner extraction. SOAP's duplicated settlement observations do not
reapply effects. Deferred datagrams still require fresh authentication.

Actual process storage is constructed off the render loop. Its child custody
must be quiesced and separately reaped after the HAL acknowledges drain;
software cancellation or an HTTP response is not an audio/DMA completion ACK.
The synchronous storage compatibility route retains its separate latency risk.

Attached host event delivery uses the existing finite callback queue independently
of reply consumption, with response-before-NOTIFY fencing, FIFO delivery and
counted refusal/abandonment. The HTTP observer and sole callback receiver poll
instead of registering a blocking receive waker in the reviewed standard
library. Final sender disconnect may still use an internal mutex. This is
neither an allocation-free producer nor a hard real-time guarantee.

## Executed checks and remaining acceptance

[The host evidence](../../toolchain/results/p03/20261115-fair-control-eventing/README.md)
binds ten Rust inputs: 17 actual journal-child process tests, 114 focused
callback/mailbox tests, the strengthened real-owner timeout test and the full
control/speaker run with 1,532 passed, zero failed and one existing ignored test.
Strict workspace/all-target Clippy includes both `harness` and `journal-process`.
Earlier stack, fixture, compilation and obsolete-expectation failures remain.
The host fixture now boxes its retained owner and separates construction and
retirement frames; production owner layout and stack limits are unchanged.

`scripts/e2e/p03 --tier smoke` invokes the actual journal process target through
strict RCH; `--tier full` invokes the control/speaker surface. The runner checks
the required executed case identities, complete test footers, source receipt
consistency and captured-byte loss. Parser mechanics fixtures are not runtime
proof. Use `--help` for invocation and artifact options.

The [P05 guest probe](../../toolchain/results/p05/20261115-prepared-cleanup-guests/RUN.md)
executes spawn/cancel/drain, timers and sockets on generic big-endian guests.
It does not run this complete speaker owner on a retained Sonos kernel. Actual
production stack/heap high-water, first-use allocation census, cleanup capacity
under allocator failure, process/kernel memory, render deadlines and physical
HAL resource retention remain unqualified. Required native Spotify, AirPlay,
Tailscale, Alexa and video behavior remain in their original integration beads.
