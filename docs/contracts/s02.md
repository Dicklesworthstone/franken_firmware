## 2. Native rate and the group baseline

The group domain is 48 kHz. Spotify delivers 44.1 kHz and AirPlay ALAC/AAC/PCM may be 44.1 or 48 kHz. A decoded block always carries its own
`PcmFormat { rate_hz, channels }`; nothing in this crate resamples implicitly.

* 48 kHz -> **direct**: the f32 samples become Q23 (`f32_to_q23`) and nothing else.
* 44.1 kHz -> **the 160/147 bridge** (`RateBridge`, `RateAdapter`), the only 44.1 path.
* any other rate (88.2 and 96 kHz are admitted by `source_session.rs:36` but negotiated by neither pin) -> `RateError::UnsupportedRate`, named.

D03's drift resampler is **not** this stage: it corrects +-500 ppm (hard ceiling 10 000 ppm) and 160/147 is 88 435 ppm. D03 stays the drift and
epoch stage in the 48 kHz domain after the bridge, with no change to its ratio ceiling or kernel, as settled with its owner. **No endpoint is
wired for 44.1 kHz until the bridge is exercised end to end by a test**; this slice exercises the bridge on the host against an independent
reference and does not wire it to a renderer.

### Bridge design (every constant is written in `tests/s02/gen_rate_table.py`)

* Rational polyphase FIR: up 160, lowpass, down 147. 64 taps per phase (10 240-tap Kaiser prototype, beta 6.75566, cut-off 20 560 Hz at the
  7 056 000 Hz up-sampled rate; design intent: pass-band to about 19.07 kHz, stop-band from 22.05 kHz).
* **Integer arithmetic**: Q23 samples (`s16 << 8` for 16-bit), Q30 `i32` coefficients, `i64` accumulator, round half up, clamp to Q23 with a
  clamp counter. Integer MACs are exactly reproducible by the independent reference, so the vectors are bit exact. This design does not
  establish a board's FPU availability or floating-point ABI; those require the separate hardware/ABI evidence.
* Every phase sums to exactly 2^30, so the DC gain is exactly 1 at every phase and a constant input comes out exactly constant.
* **Delay: exactly 32 input frames** (725.6 us at 44.1 kHz). A presentation mapping adds `BRIDGE_DELAY_IN_FRAMES` for a bridged source. The first
  output frames are the filter's start-up response to silence before the first frame.
* After `n` input frames exactly `ceil(160 n / 147)` output frames exist, whatever the chunking (tested for 12 chunkings and n = 0..400).
* Counted cost: 64 MACs per output sample, `64 x channels` per output frame (`BridgeStats::macs`). Table: 10 240 `i32` = 40 960 bytes of read-only data.
  **No cycle count on any target exists.** The cost of 128 integer MACs per stereo output frame on an admitted old-CPU profile is NOT measured;
  it is the open item that decides whether 64 taps is affordable there (section 9).
* Reset clears the history (use after a seek or a format change); `flush` pushes 64 zero frames for end of stream.

### Bridge quality (Python-verified, thresholds fixed before any Rust ran)

`bridge_reference.py --quality` measures the shipped table and the closed-form output: pass-band deviation <= 8e-4 up to 19 kHz; stop-band <= -68 dB
beyond 22.05 kHz; tones at 1, 5, 10, 15 and 18 kHz (two phases each) with gain within 0.35 %, phase within 3 mrad of the stated 32-frame delay, and
every spectral component outside +-8 bins of the tone below -66 dB (Blackman-Harris); and an rms difference below 0.3 % against
`scipy.signal.resample_poly` (a different implementation with a different filter) on a four-tone signal. Measured on the committed table:
pass-band deviation 3.5e-4, stop-band -70.05 dB, worst tone gain error 2.1e-4, phase errors about 1e-6 rad, worst spur -83.5 dB, scipy
difference 9.3e-4. The transition band 19-22 kHz is attenuated by design; content there is not preserved.

## 3. Decoders (`decode.rs`)

* `ContainerDecoder` (Ogg Vorbis, MP3): probe + decoder through Symphonia, gapless on, `SeekMode::Accurate`, decoder reset after a seek,
  `seek_preroll_frames` earlier (8192 for Vorbis, 3 x 1152 for MP3), frames before the target decoded and discarded, a position past the end
  saturates to the duration. Output is interleaved f32 at the native rate, with each block's position after trimming.
* `PacketDecoder` (ALAC from the 24-byte cookie, AAC-LC from the `AudioSpecificConfig`): one packet in, one block out; positions are cumulative.
  Preroll: ALAC 0 packets, AAC 1 packet (the overlap of the previous frame). Priming and padding belong to the sender's RTP timestamps.
* `decode_pcm_s16be`: big-endian bytes to f32, exact.
* A packet that fails to decode is dropped and counted in a container stream (more than `max_consecutive_decode_errors` in a row is an error);
  in a packet decoder it is an error value. Nothing panics on input.
* **Format changes are explicit.** A block carries `format_changed` on the first block of a new rate or channel count. For MP3, whose decoder
  reports a mid-stream change only as a generic decode error, the frame header is read here so the change is reported, the decoder is restarted
  at the new format, and the first stream's tag-derived end trim (which would otherwise swallow the whole second stream) is lifted.
* Refusals before decoding, by name (`CodecError::Unsupported`): AAC multichannel (named as the BLOCKED row, never downmixed), HE-AAC/SBR/PS,
  AAC-LD, AAC-ELD, a program config element, 960-sample frames, non-LC object types, ALAC depths other than 16 and 24, ALAC cookies that are not
  exactly 24 bytes, any container of a different codec than the one negotiated (`WrongCodec`).

### Caps (`Caps::default()`)

| cap | default | checked |

## 4. Vectors and tolerances

`tests/s02/make_vectors.py` makes ten tracks plus negative vectors from one integer source signal (`oracle.py`, rule written in its header;
the Rust test regenerates it bit for bit) using encoders and reference decoders that are not Symphonia: Apple `afconvert` (ALAC, AAC-LC), ffmpeg
libmp3lame and native Vorbis (Ogg pages of 40 ms so seek and truncation cross page boundaries), ffmpeg and a second independent decoder as references
(Apple's for MP3 and AAC-LC, libvorbis for Vorbis). Regeneration is deterministic for every file except the Vorbis streams: ffmpeg's Vorbis encoder writes a
random Ogg serial number, so the committed Vorbis streams (and the chain built from them) are the source of truth and `make_vectors.py --reuse-vorbis-streams`
derives everything else from those exact bytes.

**What the first central run found (2026-11-06) and how it was corrected.** `vorbis_44100` and `vorbis_48000` failed the tolerance by 6095 / 6272 LSB (rms
950.8378 / 922.7780). The retained failing run is `sd8`, log SHA-256
`ad773e96b123eed8279e25f0728fdb0b43dd3077a8a9ce153c76e0d58e869270`.
The original default ffmpeg references disagree with ffmpeg's scalar decode (`-cpuflags 0`) by 6095 / 6272 LSB peak
(rms 950.8378 / 922.7782) on the observed aarch64 host/build. Scalar ffmpeg agrees with libvorbis, the Xiph reference decoder, within 1 LSB
(rms 0.0158 / 0.0188). That independent corroboration supports correcting the references. Similar rounded maxima or rms values do **not** establish equality
of Rust PCM with either reference: Rust PCM was not captured for that original comparison. The subsequent corrected-reference host run is recorded in section 13. Only the
two `*.ref.s16` files were replaced, by the scalar decode of the unchanged streams. The old bytes are kept as `<id>.ref.ffmpeg-optimised.s16` (sha256 `5aff53cc...`
and `6bd94c52...`, the hashes the failing run used) and are listed in the manifest as retained BAD references; a control must show they FAIL the unchanged tolerance
against the new reference. The tolerance, the Rust tests, the three Ogg inputs, their `expected_frames` and the chain's `first_part_frames` are unchanged. The
chain has no PCM reference (its test counts frames and the format change), so nothing there was corrected. The expected lengths stay 22 080 / 24 000 frames,
with 22 080 in the chain's first part. MP3 and AAC-LC reference bytes remain unchanged and use ffmpeg's default decode
(its optimised path differs from the scalar one by at most 1 LSB there). `SCALAR_REFERENCE_CODECS` in `make_vectors.py` contains only Vorbis;
every Vorbis ffmpeg reference decode explicitly uses `-cpuflags 0`, and a non-scalar Ogg reference request is refused.
When reusing the exact committed streams, generation copies the archived bad controls only after checking their manifest and Ogg hashes; it never regenerates
them with default CPU flags. Newly encoded streams cannot inherit controls from different input bytes. The eight codec Rust source/test files,
`oracle.py`, `cases.json`, thresholds and Rust assertions remain unchanged.

* **Lossless** (ALAC 16 and 24 bit, PCM): equal to the source signal bit for bit.
* **Lossy** (Vorbis, MP3, AAC-LC): at most 4 LSB peak and 1.5 LSB rms against the reference decode. These are 4x the largest observed
  disagreement between two independent reference decoders (peak 1, rms 0.71), written in the manifest before any Rust ran. Every lossy track now
  names two (`inter_reference` in the manifest; generation refuses a track whose two decoders differ by more than 1 LSB). For Vorbis they are
  ffmpeg `-cpuflags 0` and libvorbis (via libsndfile).
* **Lengths**: Vorbis = the file's final Ogg granule; MP3 = `audio frames x 1152 - delay - padding` from the file's own LAME/Info tag; raw AAC =
  packets x 1024.
* **Negative vectors**: 5.1 AAC (refused before decoding); chained Vorbis and chained MP3 (44.1 then 48 kHz; one explicit change each).

## 12. Admission (`admission.rs`, RedPuma)

`admission::admit(&Offer) -> Result<Admitted, Refusal>` decides, before any decoder exists, whether a negotiated offer (format name, rate,
channels, bits, out-of-band config bytes) is one of the ledger's mandatory rows, and refuses everything else with one of 14 stable codes
(`UNKNOWN_FORMAT`, `NOT_REQUESTED_BY_PIN`, `BLOCKED_MULTICHANNEL`, `UNSUPPORTED_PROFILE`, `RATE_NOT_NEGOTIATED`, `CONFIG_INVALID`, ...). No allocation,
no panic on any input, a refusal echoes at most the sanitized name (32 bytes) and the config's length, never its bytes. 107 hand-written cases
(`tests/s02/admission.json`: 15 admitted, 92 refused) are replayed by `tests/s02_admission.rs` and by the independent Python port
(`tests/s02/test_admission.py`, also `S02-META-ADMISSION`), which re-derives the admitted set from the ledger. Choices made there and kept:
rates are per ledger row (Vorbis and MP3 are admitted at 44 100 Hz only, as the pinned client decodes; the 48 kHz decode vectors are decoder
capability and are refused at admission); lossy rows declare `bits = 0`; an ALAC cookie is exactly 24 bytes and an AAC config exactly 2; Vorbis,
MP3 and PCM take no config. `Admitted::needs_bridge` is true exactly for 44 100 Hz. The admission module's eight native tests now pass in the
section 13 host snapshot, including its independent 107-row admission corpus. The earlier desk checks are not counted as test execution.

## Finite reader-backed container input

`ContainerDecoder::open_reader` accepts a stable, finite, seekable `Read + Seek + Send + Sync` source for Ogg Vorbis and MP3. The declared byte length is checked by seeking and remains subject to `Caps::max_input_bytes`. A file-backed source avoids requiring the decoder to retain a complete input `Vec`; memory retained by the supplied source, the demuxer and the decoder still counts toward the caller's budget. The existing `Vec` constructor and raw AAC/ALAC/PCM interfaces retain their contracts.

`SourceReaderLimits` bounds lifetime reads, reads per probe/pull/seek operation, lifetime seeks and requested read chunk size. Limits are validated before input operations. Initial length validation uses two seeks. These are work-count bounds: a synchronous underlying read or seek can block, so source setup and decoding must run outside protected rendering with caller-managed scheduling and timeouts. Opening probes the source and may allocate before any playback selection; later eligibility checks govern steady-state source advancement.

A reader-backed I/O failure, premature EOF before the declared source length, exhausted budget or error returned by a public decode/seek operation poisons that decoder. Individual packet decode errors can be handled internally within the configured thresholds; a truncated encoded container whose length matches the declaration can instead end with `truncated() == true`, as in the retained Vec contract. Failed decode pulls clear their output; callers discard the failed reader-backed decoder. A temporary `WouldBlock` is explicitly a failure in this finite synchronous API. This API does not establish resumable nonblocking or long-track streaming, total process RSS, a board memory admission or provider playback.

`S02-READER` requires all eight native tests in `crates/franken-codec/tests/s02_reader.rs`. Their positive paths exercise the actual committed Ogg/MP3 vectors, bounded short reads and seeking; independent PCM references keep the existing tolerances, with a retained bad-reference rejection. Negative paths cover limits, declared size, probe faults, read shortages, poisoning and cleared output.
