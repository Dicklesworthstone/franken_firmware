## Real reusable implementation

`franken_stream::fec` owns authentication, capped coding windows, the scalar
solver, tail feedback and cancellation. `franken_speaker::MediaPlayout` explicitly
selects it through `enable_host_fec` only after a matching admitted MUSIC start.
The existing platform/N03 bridge and existing N04 queue are borrowed; no second
playout queue is introduced. Baseline N01 remains the default. Allocation is a
single fallible, ledger-checked state reservation at control selection; its
retained capacity stays charged even after clearing an epoch. Native Spotify,
AirPlay, tailnet, Alexa, artwork and the other requested features remain
required; this profile does not qualify their provider or target integration.

Host-development profile `n06.host-hybrid.k4-r4.v1` accepts only
K4/R4/1024, format1 and codec1/version1. Eight fixed coding-window slots retain
at most64 authenticated symbols, beside one fixed8x1028 solver matrix. Eight
windows cover the declared52ms collection and bounded72ms tail flight without
pretending a two-window cap can retain that pipeline. One solve/window and one
active solve total; one aggregate feedback/window and at most four outstanding
originals. Sender construction requires the trusted group member count1..21;
it admits group-size+1 pre-MAC checks per trusted work interval, at most22.
The entire maximum22checks plus4replies is221088 work units (11.0544ms ONLY in
the declared synthetic timebase), within the unchanged20ms ledger. Six members
with simultaneous differing losses are tested; four repeated requests for the
same original do not starve the later distinct request. Sender replies are group/session-bound broadcast originals: disjoint
member requests share a four-unique-original union/window, rather than consuming
another member's request. An already sent original is never amplified again:
a member losing that single broadcast remains a declared loss; its replay gets
Duplicate rather than another copy. This is bounded traffic, not guaranteed delivery.
After a receiver clock jump,
catch-up is capped to the retained horizon and creates at most one slot/poll.
Whole-window erasure reaches the tail through the trusted source schedule; it
does not require an oracle to report which future packets will be lost.

The actual Asup decoder at the selected pin has private dense/ESI budget
accounting but a monolithic public decode, with no cooperative cancellation
checkpoint. It is not admitted by a finite host timing. Instead, the firmware
module adapts only the fixed systematic8x4 generator and GF256 scalar algebra.
The generator constant was provisionally derived from that pin's RFC tables,
LDPC/HDPC/padding/LT equations. The thin `toolchain/n06-fec-profile` MUST validate
all65536 GF products and four full basis encodes against the actual pinned
library; all163 received subsets are then compared with actual Asup decode and
independent `raptorq=2.0.1`. None of these new tests has run yet. The heavy
libraries have no production dependency/lock edge. No upstream files changed.

## Authentication and integrity

N06 is a separately selected wire format, never N01 XOR Repair semantics under
a different label. Datagrams are exactly1152 bytes:112-byte header,1024-byte
payload,16-byte truncated HMAC-SHA256. The key is N01's redacted `StreamKey`;
identity is N01's caller-entropy-admitted nonzero `StreamId`. HMAC domain is
`FFWR-N06-v1-auth`. No key, tag or PCM byte is in diagnostics.

Header fields use explicit BE integers, not native structs:

| Bytes | Meaning |
| --- | --- |
| 0..12 | `FFWR`, version1, codec1,K4,R4,size1024,format1,reserved0 |
| 12..28 | stream identity and authority epoch (`u64` each) |
| 28..44 | coding window and its first source frame (`window*1024`) |
| 44..60 | first-frame presentation and declared consume_by (`u64` ns each) |
| 60..64 | reserved zero |
| 64..72 | sequence `window*8+ESI`, no wrap permitted |
| 72..80 | ESI0..7, kind0 source/1 retransmit/2 RFC repair, reserved zero |
| 80..112 | authenticated SHA256 commitment to canonical metadata+all4 PCM blocks |

Windows are at most`u32::MAX`; timestamp bounds include the last source frame
of the window. A controlled epoch/session transition is required before wrap.
Timestamp refers to first frame in the window, in the admitted group clock.
Individual source presentation uses ONE floor of the full absolute frame
count, never a sum of separately rounded window/offset times. Payload length
derives256 frames. Structure bounds precede MAC; identity/epoch/shape/timeline,
admissible future horizon and duplicate checks precede symbol-state writes.
Only the explicit control API can transition epoch; packet epochs never do.

The content commitment uses domain`FFWR-N06-v1-source`, canonical first64 header
bytes and4096 source PCM bytes. Recovered source is not published until every
received equation is checked and the reconstructed content commitment matches.
Thus a corrupt-but-authentic inconsistent equation, or a consistent wrong
solution with the wrong commitment, cannot publish recovered PCM. This is a
session-key trust boundary, not Byzantine agreement among compromised senders.

Feedback is96 bytes, `FFWA` plus canonical metadata, bounded original mask,
one-attempt marker, request time and HMAC. Receiver feedback is a returned
bounded control object; reliable control remains independent. `SenderWindow`
verifies it before at most four unique replies. Sender pre-MAC quota is the
explicit group-size+1 per trusted21.33ms work interval, refilled by the admitted clock, not a lifetime
latch. Receiver quota is two unauthenticated attempts per(window,ESI) per work
interval, within the same20ms ledger. Already held published pairs are dropped
before MAC without consuming another pair's authentication allowance. Sixteen
distinct forgeries leave the tested normal six-symbol recovery workload room;
an unbounded flood may still exhaust the shared work ledger. Wire timestamps
cannot refill either budget. Failed authentication is charged. The retained
window range is exactly[current-6,current+1], eight distinct modulo-eight slots;
an older authentic window cannot evict a larger held id.

Authenticated source bytes refused only by N04's queue horizon remain stored
with their publication bit clear. Poll re-offers at most one charged source
per call after the cursor advances, without repeating authentication; immediate
admissions are not re-offered. Repair symbols return no N04 admission. Typed
credit identity is(stream,epoch,origin,format,sequence), including the Source/Retransmit distinction.
Media exposes these authenticated fields and a Copy+Eq+Hash IngressIdentity;
N01 uses origin0 because its sequence does not restart inside an epoch.
Legacy MediaPlayout::ingest refuses selected N06 before authentication, so the
N07 N01-offset reader cannot see a successful differently formatted header.

## Work, cancellation and cutoff

The reusable receiver and scalar decoder allocate no payload/matrix storage
per packet or poll. This qualification does not cover the host carrier's
bounded datagram queues or control-negotiation temporary vectors.
Initialization/copies,
pivot search/swaps/normalization/elimination, received-equation consistency,
SHA chunks, state setup and N04 publication are all in the declared work model.
Full worst remaining bound is120000 units, reduced only by actually consumed
steps. Its source-derived ceiling includes8x1028 initialization,
4x(8+1028+1028+8x(1028+2)+4) row work,8x1024x5 verification,
66x256 hash work, inverse work,264 setup and4x2048 publication reserve.

The synthetic timebase is50ns/work unit;20ms/interval is the study ledger cap.
This number is an explicit host-model assumption, NOT CPU measurement, a
conservative physical instruction time or board WCET. Actual host CPU/time and
board kernel/driver/DMA/stack/allocator reservations require their own evidence.
N05's1ms timing reserve is neither changed nor used as N06 admission evidence.

Before starting and at every poll, conservative remaining work must fit before
at least one still-live missing block's own cutoff. An expired earlier block
cannot veto a live later one. Work and future ingress reservations share the
same ledger. At most512 units run/poll; cancellation is checked before every
scalar step and bounded64-byte SHA chunk, and before each N04 publication.
GF multiplication has exactly eight bit rounds. The largest solver atomic step
is the512-unit final hash. Packet authentication is a separate fixed1152-byte
HMAC boundary; it is not preemptible mid-compression and is charged before work.
No thread, detached task, join or external callback is used for a decode.
Active cancel/stop retires publication authority and releases the reservation while
retaining the same bounded backing buffers; a new window/epoch can recover.
Idle cancellation leaves still-receiving windows usable. Transient clock fault
or mute cancels active work without latching stop; a fresh N03 lock and admitted
same-epoch start rebinds N04/N06 and permits real recovery. A window-aligned
absolute anchor_frame may be nonzero: origin=start_group−frames_to_ns(anchor).
An isolated member can relock/catch up at a future original-stream window,
keeping the sender's origin, epoch, sequence/window numbering and healthy group.
This includes N03's existing catch-up deadline; it makes no latency admission.
Data before the new anchor is retired, while relevant same-origin stored data
can be re-offered. A genuine changed origin is a different credit generation;
the receiving endpoint detects it and resets its credit generation and pending
feedback. Sender profile selection requires a newer epoch and resets the local
peers' numbering; coordinated remote clock/start cutover remains required.
Changed start metadata
clears old symbols; same-context rebind can re-offer retained authenticated bytes.
Neither rebind nor clock faults refund work charged in the trusted work interval.
An admitted rebind or epoch transition can use a different group-clock origin:
the first usable work-time reading anchors a full 21,333,334 ns interval in
that timeline. The prior charge remains in force until that interval elapses,
including when the new leader's time is lower or higher than the old leader's.
If work was observed in the same aligned interval as expiry, the charge and
pair limits carry through expiry and refill only at the next aligned boundary.
Publication uses its fresh clock reading to account for its own work interval.
Same-context rebind also retains per-symbol authentication attempts until that
interval elapses and retains the last admitted clock reading, so a backwards
reading cannot start the new interval. Changed contexts clear those identities,
not the work charge.
Integrity Ready is a separately owned pending result, not permission to publish
using poll-start time. The actual media consumer reads the platform/N03 clock
again AFTER decode, checks authority/epoch/cancellation/render/deadline again,
then calls the separate N04 publication boundary. A clock fault retires the
pending result without publishing. No fabricated completion timestamp is used.

Selected views use at least500us uncertainty. N04 derives the actual cutoff:
presentation minus1ms downstream work,1ms lead and current guarded uncertainty.
Next-cutoff overlap is temporarily deferred and the COMPLETE just-decided2ms render/lead
interval is recorded after the N04 cursor advances. A job may run at that
interval's half-open end. Protected{until_ns} leaves the datagram unconsumed,
charges no authentication/decoder work and increments a bounded deferral counter;
the carrier must retain/retry it. If the cursor's decision is overdue, deferral
continues until that decision is taken and its complete render interval ends.
This differs from permanent Deadline abandonment. Decode and feedback scan the
earliest window, independent of ring index. Recovered bytes enter real `on_repair`, whose
Late/Duplicate result is authoritative; committed concealment cannot be
replaced, even before DAC presentation. Following-block progress is required.

## Authenticated per-member resource readiness (FFCNv2)

FFCNv1 Proposal/ACK establishes profile agreement. FFCNv2 PREPARE authenticates each member's actual transport stream, peer, media-key commitment/slot/generation, anchor, common start and expiry. The receiver imports a bounded owner-controlled media key and holds a charged future resource guard. Revocation or identical reinstall invalidates old candidates through the owner's generation; changing an unrelated SecretStore does not revoke a copied owner key.

`PreparedFutureReady::emit_ready` rechecks current authority, endpoint/key identity, the independently admitted future clock and the resource budget before signing, then checks clock and budget again before exposing output. Every error clears output. The coordinator latches trusted clock expiry/rollback, including observations made during malformed or rate-limited ingress. Identical authenticated retries retain their binding and deadline; v1 behavior and the shared endpoint bucket are preserved.

READY is an expiring assertion. Retained resources, decoded-data readiness and distributed activation need their own checks. The raw group-time entry point has an explicit caller-trusted clock boundary.

[Host qualification and captured output](../../toolchain/results/n06/20261111-ready-resources/RUN.md) record 1,320 library tests, three allocator tests and strict all-target Clippy at the focused 13-file snapshot. Board fit, provider services, physical output and the two original N06 integration cases remain unqualified. Typed-clock/UDP integration is a separate wave.

These gaps cannot be closed by the current component passes or by deleting blocked cases.
