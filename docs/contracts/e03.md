# Contract E03 — Kernel Version & Userspace Syscall/Libc ABI Compatibility Matrix

## Scope & Mission
Defines the per-board-class kernel ABI capability matrix (`franken_platform::KernelCapabilityMatrix`), runtime
capability probing, and the admission gate that consumes it, for the legacy Linux `2.6.14` (PowerPC
S5/ZB100) and `2.6.35` (MIPS32r2 S1/S3/S9/S12/Sub) stock kernels, and for the Debian `4.9` (BE-PPC) and
`4.19` (BE-MIPS) QEMU harness kernels that stand in for them.

Nothing here touches a device. The only kernels ever exercised are the two harness kernels, in full-system
QEMU guests. Everything said about a stock kernel is therefore **unqualified** (below), as the bead requires:
*"If no matching guest exists, record compatibility as unqualified."*

## Evidence classes
Every cell of the matrix is exactly one of these. A result is evidence about the kernel it ran on and about no
other; it is never carried from one kernel to another.

| Class | Meaning |
|---|---|
| **observed** | A line in a committed serial transcript from a full-system guest of that kernel: central run `1412ac47120d4e5b865f9de6e05f50fe` (`toolchain/results/runs/1412ac47120d4e5b865f9de6e05f50fe/boot-*-serial.log`, digests in that run's `e07-e03-verification-receipt.json`, pinned by `E03-IDENT-001`). The probes are freestanding raw-syscall PID-1 code, so an observation is about the **kernel's** syscall, not about musl, `std` or Asupersync running on it. |
| **probe, no transcript** | The guest probe exists in the source but no committed real transcript contains its line yet. No result is claimed. Every probe that existed when run `1412ac47` was made is `observed`, so no cell uses this class today; a probe added later starts here. |
| **unprobed** | No guest probe emits it. No result is claimed, and the host classifier lists it as `unprobed`. |
| **unqualified** | A stock-kernel profile with no matching full-system guest. User-mode QEMU runs the host kernel's syscalls and is CPU evidence only. |

## Capability matrix
"Declared policy" is what the platform does if the capability is absent. **Required** probes are runtime behaviors
the executor cannot run without: the runner needs their exact PASS line (an `-ENOSYS` there is a defect on the
harness kernels) and the classifier turns a missing or ambiguous result red. **Optional** probes are capabilities an
old kernel may lack: an exact `-ENOSYS` is a classified absence that degrades the verdict.

| Capability (what the probe checks) | Harness BE-PPC `4.9.0-0.bpo.6-powerpc` | Harness BE-MIPS `4.19.0-21-4kc-malta` | Stock PPC `2.6.14` | Stock MIPS `2.6.35` | Declared policy if absent |
|---|---|---|---|---|---|
| `clock_gettime(CLOCK_MONOTONIC)` and `clock_getres` (reports 1 ns; the tick is not measured) | observed | observed | unqualified | unqualified | Required; hard boot gate |
| Nonblocking pipe (`pipe2` `O_NONBLOCK`, `EAGAIN` on empty read, 4-byte round trip) | observed | observed | unqualified | unqualified | Required |
| Partial write on a full nonblocking pipe (`FFW_TEST:PARTIAL_WRITE`) | observed | observed | unqualified | unqualified | Required |
| `poll` readiness (`POLLIN` on a readable pipe) | observed | observed | unqualified | unqualified | Required |
| `epoll_create` (descriptor creation only; `epoll_wait` is not exercised) | observed | observed | unqualified | unqualified | Falls back to `poll(2)` |
| UDP `socket()` creation only (no bind, send, receive or truncation) | observed | observed | unqualified | unqualified | Required (creation) |
| `/dev/urandom` open and read (liveness only: the MIPS log reports `random: init: uninitialized urandom read (16 bytes read)`, so those bytes were **not** secure entropy; the PPC log has `random: fast init done` before the read and no such warning, which says the pool was past its first stage and **not** that it is secure) | observed (liveness only) | observed (unseeded pool) | unqualified | unqualified | Required to open and read; says nothing about entropy quality |
| 32-bit atomics (userspace compare-exchange and fetch-add: CPU evidence, not a kernel capability) | observed | observed | unqualified | unqualified | Required; 64-bit atomics come from `portable-atomic` where the target lacks them (`P05`) |
| `getrandom` (seeded: `PASS rc=16`; `UNSEEDED rc=-11` when the call exists but the pool has no entropy yet; see below) | observed (`PASS rc=16`) | observed (**`UNSEEDED rc=-11`**) | unqualified | unqualified | Optional; `/dev/urandom` keeps firmware live but reads the same pool, so it is **not** a secure-entropy fallback |
| `eventfd2` | observed | observed | unqualified | unqualified | Optional; self-pipe (`ReactorWakeMechanism::SelfPipe`) |

| Thread creation (`clone` with `CLONE_VM\|FS\|FILES\|SIGHAND\|THREAD\|SYSVSEM\|SETTLS\|CHILD_CLEARTID`, joined on the cleared tid word) | observed | observed | unqualified | unqualified | Optional; none: single-thread executor only |

| `epoll_create1` | unprobed | unprobed | unqualified | unqualified | None admitted |
| Loopback bring-up (`ioctl` `SIOCSIFFLAGS` on `lo`) and UDP over it, including truncated-datagram reporting (`MSG_TRUNC`, real length 24 in a 16-byte buffer) | observed | observed | unqualified | unqualified | Required; kernel UDP semantics over `lo` only, not any real network path |

An exact `-ENOSYS` in the guest's own ABI numbering (38 on PowerPC, 89 on MIPS) from an optional probe is a
classified capability absence, not a guest failure; the other ABI's number, any other errno and any other failure
mean the call exists and misbehaves, and are ambiguous. A probe line that is **missing** from a transcript whose
guest carries the probes (it printed `FFW_BUILD`) means the probe did not run; that is red and is never filed with
an `-ENOSYS`.

**Entropy at PID-1 boot (`UNSEEDED`).** The harness guests attach no RNG device and load no modules, and the two guests answered differently in run `1412ac47`. **MIPS** (4.19): the pool is not seeded when `/init` runs (the kernel logs `random: init: uninitialized urandom read (16 bytes read)` about 2 s into boot), so `getrandom(GRND_NONBLOCK)` answered `-EAGAIN`; the probe then proves the call exists without needing entropy (a reserved flag bit must give exactly `-EINVAL`) and prints `FFW_PROBE:GETRANDOM status=UNSEEDED rc=-11` (`EAGAIN` is 11 on both ABIs). **PPC** (4.9): `getrandom` returned 16 bytes (`PASS rc=16`) with `random: fast init done` in the log and no uninitialized-read warning. This run does not show how that kernel judged its pool ready (no RNG device is attached), so the PPC PASS is a fact about that guest's boot and **not** a claim that PPC boards seed at boot or that a PASS line is cryptographic evidence. `UNSEEDED` is a third outcome, recorded as its own state (`unseeded_capabilities`, never merged with `unsupported_capabilities`) and accepted for `GETRANDOM` alone, with exactly that value; the same line on any other probe is invalid. It is not a pass (no entropy was obtained), not an absence and not a misbehaving call. The classifier reports it as `unseeded` and the verdict is `degraded` (the real MIPS run), and the consequence is stated: firmware must not block on `getrandom` at boot, must not assume the pool is ready on any board, and the existing `ENTROPY` probe's PASS reads `/dev/urandom` and **does not establish secure entropy**. No entropy is credited or faked to make the probe pass, and no non-secure generator is substituted.

**Design consequence of `futex` having no fallback:** if `futex` is absent the platform cannot run threads, so the
verdict is `degraded` and the only admissible executor is single-threaded. That is a profile decision, not a probe
failure. **A wedge is a failure:** a probe that hangs or kills PID 1 leaves no `TEST_SUCCESS` marker, so the runner
fails the guest (missing markers) and records the capture timeout; it is never read as an absent or unsupported
probe, and every line printed before the wedge stays in the raw log. The thread probes run last for that reason.

## Stock-kernel profiles are unqualified
No `2.6.14` PowerPC or `2.6.35` MIPS full-system guest exists, so every stock cell above is **unqualified**,
including the fallbacks. A harness result is not a stock result, and a hypothesis such as "this call is absent on
a 2.6.x kernel" stays a hypothesis until a matching guest runs the probe. This is enforced, not just stated:

- `KernelCapabilityMatrix::check_admission` refuses every profile whose `guest_kernel_observed` is missing or is
  not the profile's `nominal_kernel_version` on a release boundary (`2.6.14` matches `2.6.14.7` and
  `2.6.14-sonos`, not `2.6.145` and not `4.9.0-0.bpo.6-powerpc`). The error is
  `PlatformAdmissionError::NoMatchingGuest`, raised before any capability status is read.
- The host classifier (`tests/e03/abi.py`) reports the same split as evidence classes: `matching-guest` is the
  only one that can make a capability `supported`; `non-matching-guest`, `cpu-emulation` and
  `unavailable-guest` never can. A positive observed matching guest and a deliberate non-matching guest are
  distinct cases throughout `tests/e03/cases.json`.

## Probe build identity
The bead requires the probe to record its target triple, compiler version, linker and libc. The receipt is
**observed provenance, not enforcement**: the toolchain is deliberately not pinned (`cargo +nightly` selects
whatever nightly the worker has, and pinning one a worker lacks would turn every build into an infrastructure
failure), so the receipt records what actually built the booted bytes.

- The PID-1 probe prints two lines before its probes:
  `FFW_BUILD target=<triple> rustc=<release> rustc_commit=<short> linker_flavor=<flavor> libc=none runtime=no_std`
  and `FFW_RUSTC release=<r> commit=<40 hex> date=<d> host=<h> llvm=<v>` (`rustc -vV` as the building compiler saw
  itself). Both come from `ffw-hello-init/build.rs` (cargo's own `TARGET`, `RUSTC` and rustflags); the runner
  fails the guest if they disagree on release or commit.
- `libc=none` is the build's **own claim** about the crate (`no_std`, `no_main`, own `memcpy`/`memset`). What the
  runner can **prove** is narrower: the booted ELF is static, 32-bit big-endian, for the right machine, with
  neither `PT_INTERP` nor `PT_DYNAMIC`. That cannot distinguish "no libc" from "statically linked musl", so the
  receipt records it as `libc.conclusion: "static_no_loader"` next to `libc.reported_by_probe`.
- `toolchain/src/run-qemu-verification.py` records, per guest: `target_triple` (what it built and booted),
  `build_identity`, `rustc_identity`, `libc`, `linker_configured` (the linker and flavor the committed
  `.cargo/config.toml` names; a configuration claim) and `build_manifest` (the exact build command, the sha256 of
  the manifest, lockfile, cargo config, build script and every source, the target, rustflags and `-Z build-std`
  set; the digests are bound to the binary only when the runner built it, never under `--skip-build`). It fails the
  guest when the triple differs from the one it built, when either line is missing, duplicated or malformed, when
  a compiler or flavor is `unknown`/`unspecified`, when the flavor contradicts the committed config, when the ELF
  is dynamic or for the wrong machine, or when the init entry QEMU executed does not hash to the binary the
  receipt names (`initramfs_init_differs_from_binary`).
- **What this is not:** the lines are the compile's own report, not an attestation of the remote compiler or
  linker, which still needs the separate build receipt (`build_provenance.status` stays
  `not_attested_by_this_boot_runner`).

## Gates and exit codes
- Host classifier verdict: `green` only when every required capability is `supported` on a matching guest and the
  build identity is recorded and consistent; `degraded` when the only gaps are optional capabilities whose declared
  fallback is itself supported (or that have no fallback and simply leave the feature unavailable); `red`
  otherwise. `abi.py classify` exits 0, 4, 1 respectively (2 on usage). The classifier gates on `FFW_BUILD`; the
  runner additionally pins the compiler through `FFW_RUSTC`.
- `scripts/e2e/e03` runs the host-side case suite (`tests/e03/run_cases.py`): exit 0 only when every case passed
  and none is blocked, 1 on a failed case, 3 when the only non-passes are blocked cases (reported, never counted as
  passed), 2 on usage or a malformed case file. While any blocked case remains, the suite prints `NOT QUALIFIED`.
- **Labels are enforced.** `REAL` means an unmodified committed transcript of run `1412ac47`: a case titled `REAL` with any
  mutation, any case that adds a line or builds its transcript inline without saying `SYNTHETIC`, and any case that
  says `SYNTHETIC` while adding no line (a changed or removed real line is `PLANTED`) makes the case file malformed
  (exit 2) before any case runs. A mutation must also change the text: writing the line a transcript already has
  plants nothing and is refused. The earlier `SYNTHETIC` baseline of twenty added lines is retired: the planted
  cases (`E03-BUILD-*`, `PROBE-*`, `RT-*`, `NET-*`, `SEED-*`) now change one real line at a time, and the suite
  checks that each of them fails when its plant is removed. The two real baselines differ in one probe: MIPS is
  `degraded` (unseeded `GETRANDOM`), PPC is `green`.

## Open items (blocked cases in `tests/e03/cases.json`)
- Resolved by central run `1412ac47` (their cases are retired; the evidence is `E03-IDENT-001`, `E03-CLASS-001/002` and the planted cases): `E03-BLK-001` (a transcript with `PARTIAL_WRITE` and a receipt that agrees with it), `E03-BLK-003` (real lines for `getrandom`, `eventfd2`, `timerfd`, `futex`, `accept4`, threads and TLS), `E03-BLK-004` (real lines for timer wakeup, signals, `EINTR`, the allocator, peak memory and atomic width) and `E03-BLK-005` (the build identity in the transcript and the receipt).
- `E03-BLK-006` stays blocked: readiness, underrun and wake behavior of the retained audio driver are not probed and not claimed, and need the E04 driver in an exact-version guest. Rename durability on the device's own storage is also unobserved: `FS_RENAME` renames a pair of files on the guest's root filesystem.
- No stock-kernel guest exists. That is the unqualified state the bead prescribes, not a blocker; `E03-STOCK-001`
  checks that this contract and `franken-platform` record and enforce it (a text check: the refusal itself is
  proven by the crate's unit tests, which run in the central RCH batch).

## Known limits (recorded, not built)
- The linker-flavor cross-check against the committed config is skipped, not failed, when the config cannot be read
  (`linker_configured.error` is recorded instead).
- The classifier matches the target triple by its first component (`mips`, `powerpc`) against the profile's ABI,
  not the full triple; the runner is the one that compares the full triple with what it built.
- The receipt lists every probe line per guest at full width, without a summary table.
- The `ENTROPY` probe cannot tell a seeded read from an unseeded one; only the kernel's own message and the
  `GETRANDOM` `UNSEEDED` outcome carry that information.
- `epoll_wait` and the `epoll_create1` flag form are unprobed; `ATOMIC_WIDTH` records the width the compiler claims
  and does not audit the atomics of the selected dependency graph.
- `MEM_PEAK` is the probe process's own `VmPeak`/`VmHWM` (64 kB MIPS, 60 kB PPC in run `1412ac47`): not a budget for the
  firmware, and nothing here measures kernel, driver or DMA memory.
- The probes are freestanding raw-syscall code (`no_std`, no libc, `libc.conclusion: static_no_loader`). A musl or
  `std` binary issues the same kernel calls through a library that may substitute others (musl's `accept4` is the
  case to check first), so these results do not qualify any library on top.
- Run `f0a91e7b` (the first central run) built the same binaries and printed the same probe lines, but its receipt
  listed 10 source digests (the manifest files and the six top-level `src/*.rs`) and omitted
  `src/e03_probes/net.rs` and `src/e03_judge/net.rs` while recording `sources_bound_to_binary: true`. The runner now
  digests every file under `src/` recursively and run `1412ac47` re-ran it: its receipt lists all 12 sources, and
  `E03-IDENT-001` pins that set from the committed blobs the run built. No case reads `f0a91e7b`; its directory is
  committed evidence of the gap and is not edited.
- Two guests, one run each, 4.9 and 4.19: no repeat runs, so nothing here measures run-to-run variation (for example
  whether the PPC pool is always ready at PID 1).
