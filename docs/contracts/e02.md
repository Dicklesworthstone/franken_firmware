# E02 contract: incumbent resource and dropout baseline analyzer (ffw-za4)

**Status.** Offline analyzer and its synthetic qualification. **No incumbent resource or dropout capture
exists in either repository, and nothing here measures a device.** Live measurement is a separate,
externally authorised receipt that this analyzer would consume. A passing run proves the analyzer, not
any speaker.

Code: `crates/franken-baseline` (`forbid(unsafe_code)`, no dependencies in the library). CLI:
`ffw-baseline series|memory|compare`. Cases: `tests/e02/` (`cases.json` maps every invariant to a case).
The synthetic inputs are in `tests/e02/synthetic/`, deliberately not `captures/`: the repository's
`.gitignore` excludes `captures/` so that real device captures can never be committed here. A real
incumbent capture, when one exists, stays outside git and is fed to the analyzer by path.
Entry point: `scripts/e2e/e02`. Central build: `RCH_REQUIRE_REMOTE=1 rch exec -- cargo test -p franken-baseline`.
All arithmetic is integer; reports are one line of JSON.

## Inputs

**Series capture** (`ffw.baseline.capture.v1`), one record per line, `#` comments:

```
meta evidence=synthetic profile=P cadence_ms=1000 declared_ms=10000 [playout_ms= hole_factor_pct=150
     wall_step_ms=1000 spike_factor=8 device_rate_hz= device_width=64 device_stall_frames=
     min_coverage_ppm= max_dropout_intervals=]
counter name=N role=dev_underruns|late_packets|cpu_misses|source_bytes|other width=32|64 [max_rate_per_s=0]
gauge   name=N role=playing|value [max=]
sample  mono_ns=T [wall_ns=W] [dev_frames=F] name=value ...
```

`evidence` is `synthetic | host-simulation | guest-execution | real-service | physical`. The thresholds
(`min_coverage_ppm`, `max_dropout_intervals`) are declared in the capture, before the run. A series
missing from a sample is a missing value, not zero. Unknown keys, undeclared series, duplicate names or
roles, declarations after samples and non-integer values are errors with a line number.

**Memory snapshots** (`ffw.baseline.memory.v1 page_size=4096 [reserve_kib=]`): `snapshot label= at_mono_ns=`
then `--- meminfo | status pid= | smaps_rollup pid= | statm pid=` sections holding the raw `/proc` text.
Kernel `kB` means KiB; `statm` counts pages and converts only through the declared page size.

## What each result means

- **Coverage** `observed_ns / declared_ns` in ppm. An interval longer than `cadence * hole_factor_pct`
  is a **hole**: reported with its length and estimated swallowed samples, **never interpolated**.
  A capture ending early is **truncated**; the missing time is reported, not extrapolated.
- **Counters.** A rise is a delta. A fall is a **wraparound** only for a 32-bit counter whose wrapped
  delta fits under `max_rate_per_s * dt`; otherwise a **reset**, which has no rate and censors its span.
  Events in a hole or reset are `unlocated_events_min`, kept out of every rate.
- **Clock domains** are separate types. Gaps and rates use only the monotonic clock. A wall-clock step
  is reported as a step and creates no gap. The device sample clock is related to monotonic time by
  `drift_ppm`; a 32-bit wrap there is not a stall.
- **Dropouts.** A dropout interval is an uncensored interval in which the underrun counter rose (or the
  device clock fell short by the declared stall). **With no such signal the dropout count is `unknown`,
  never zero**, and a "zero dropouts" threshold is then not met.
- **Cause** per dropout, judged only from each candidate's own signal over a window (the interval, the
  interval before it, and any earlier interval ending within `playout_ms` of its start), and only if
  that signal is complete over the window:
  `source_outage` (source bytes stalled while playing), `network_lateness` (late-packet counter rose),
  `cpu_deadline_miss` (deadline-miss counter rose). Exactly one firing is `determined` and lists the
  candidates it could not rule out; two or more is `ambiguous`; none firing with all three observed and
  quiet is `output_underrun` (only for a counted underrun); anything else is `undetermined` and **names
  the missing signals**. No cause is ever guessed.
- **Memory.** RSS comes from `smaps_rollup`, else `status`, else `statm`; disagreeing sources are
  findings, not averaged. Shared pages are counted once via PSS and the naive-RSS overstatement is
  reported (`double_counted_kib`). Kernel memory (slab, kernel stacks, page tables) is a separate line.
  `unattributed_kib` is a signed residual, not a measurement of any consumer. Headroom is judged only
  against a `reserve_kib` declared in the input.
- **Absolute verdict** (`qualified | not_qualified | not_assessed`) only against the capture's own
  declared thresholds. It needs no baseline.
- **Comparative claims.** `compare` returns a comparison only against a `Baseline`, which can be built
  only from a **`physical`** capture with at least 900 000 ppm coverage and a known dropout rate, and
  only if the current run is also physical, of the same profile, with no censored dropouts. Otherwise it
  is refused with a reason (exit 3). A synthetic capture can never be a baseline or an improvement.

## Human-run baseline recipe

How a person produces a capture of an incumbent speaker that this analyzer can read. **It is documentation a person runs, and
it issues no device-affecting command: it reads files and prints text. It flashes nothing, changes no setting, opens no socket
and runs no network experiment.** Getting a read-only shell on a speaker you own is outside this recipe and outside this
repository; if you cannot read the files below without changing the device, stop. Nothing here is run against a speaker by this
repository, and a capture taken this way is a separately authorised receipt, not something the offline cases supply.

### Before you start

1. **Pick the names now, and make them generic.** The profile (`incumbent-music-v1`), each series name (`xruns`) and each snapshot
   label (`steady`) travel into every report. Never a model, serial, address, room, person or account. The analyzer refuses what
   looks like one (see "Logging and redaction") but cannot know what it has not been told is private.
2. **Declare the thresholds before you look at any result:** `min_coverage_ppm` and `max_dropout_intervals` for the series,
   `reserve_kib` for memory. The analyzer judges only against what the capture declared, and a threshold written afterwards is a
   different claim.
3. **Work outside git.** Write the files under `.local-real/`, which `.gitignore` excludes. Never under `tests/`, and never in a
   directory called `captures/`: that name is excluded so that a real capture cannot be committed by accident.
4. **Play a steady, known source** for the whole run, and write down what it was and for how long. A capture says nothing about
   behaviour you did not exercise.

### What to read

Only these, and only those that exist on your device. A source that does not exist is left out and the analyzer says what it then
cannot know (the dropout count is `unknown`, a cause is `undetermined` and names the missing signal), never a zero.

| Need | Read-only source | Becomes |
|---|---|---|
| monotonic time | the first field of `/proc/uptime` | `mono_ns` |
| wall time (optional) | `date +%s` | `wall_ns` |
| device sample clock (optional) | a frame counter the audio stack exposes, only if you can say what it counts and how wide it is | `dev_frames`, `device_rate_hz`, `device_width` (add by hand) |
| output underruns | any counter that rises when the output buffer runs dry | `counter role=dev_underruns` |
| late packets | any counter of packets that arrived after their playout time | `counter role=late_packets` |
| deadline misses | any counter of render deadlines missed | `counter role=cpu_misses` |
| source bytes | cumulative bytes received from the source | `counter role=source_bytes` |
| playback state | a file that holds 1 while playing and 0 otherwise | `gauge role=playing` |
| memory | `/proc/meminfo`; per process `/proc/<pid>/status`, `smaps_rollup` (kernel 4.14 and later) and `statm` | memory snapshot sections |

Read nothing else. Not `cmdline`, `environ`, `maps`, `smaps`, `fd`, `net/*`, logs or configuration: they carry exactly what must
not be shared, and the analyzer has no use for them. Do not invent a counter: record one only if you can say what it counts.
Counters the stock firmware does not expose are simply absent from the capture.

### Clocks, cadence and thresholds

* **`mono_ns`** comes from `/proc/uptime`, which counts seconds and hundredths since boot (including any time spent suspended). On
  a speaker that does not suspend it advances like the monotonic clock, at 10 ms resolution, so keep the interval at one second or
  more. The script writes it as
  nanoseconds by appending seven zeros to the digits, with no arithmetic: `101.01` becomes `101010000000`.
* **`wall_ns`** is `date +%s` followed by nine zeros. Its resolution is a second, so the script declares `wall_step_ms=2000`: a step
  is reported only beyond that. If the device has no usable wall clock, set `NOW=false` and the field is left out.
* **Cadence** is one sample per second (`cadence_ms=1000`). `declared_ms` is `(samples - 1) * cadence_ms`. An interval longer than
  150% of the cadence is a coverage hole, reported and never filled; a missed `TICK` therefore shows up as a hole, not as a smooth
  line. A longer run is more evidence, not a different method; a 24-hour campaign is its own authorised receipt.
* **`playout_ms`**, if you know the playout horizon, lets a cause be judged over the interval before a dropout; the default is 0.
* **`max_rate_per_s`** on a counter is the fastest it can plausibly grow. Without it a falling 32-bit counter is a reset, never a
  wraparound. The script does not write it; add it to the `counter` line by hand if you know it.

### The two scripts

Edit the variables at the top, read the whole script, then run it. Both are POSIX `sh`, use no arithmetic beyond small counters,
call no tool of their own except `printf`, `read` and `cat`, and write only to `$OUT` or `$MEMOUT`. The two commands you supply,
`TICK` and `NOW`, default to `sleep 1` and `date +%s`, which read nothing from the device and change nothing; if you set either to
something else, that command is yours to vouch for.

<!-- e02-recipe:sample.sh -->
```sh
#!/bin/sh
# E02 baseline sampler. READ-ONLY: it reads files and prints text. It changes no setting, flashes nothing,
# opens no socket and starts no network test. Edit the variables, read them, then run it.
PROC=${PROC:-/proc}                      # where the kernel's /proc is mounted
OUT=${OUT:-baseline.cap}                 # the capture: keep it OUTSIDE git, for example under .local-real/
PROFILE=${PROFILE:-incumbent-music-v1}   # a generic name: never a model, serial, address, room or person
EVIDENCE=${EVIDENCE:-physical}           # physical only for a capture taken on a real speaker
COUNT=${COUNT:-3601}                     # number of samples: 3601 at one per second is one hour
CADENCE_MS=${CADENCE_MS:-1000}           # the interval you intend; TICK must wait about this long
TICK=${TICK:-sleep 1}                    # the command that waits one interval
NOW=${NOW:-date +%s}                     # wall clock in whole seconds; NOW=false leaves wall_ns out
NOTE=${NOTE:-}                           # one comment line: what and why, never where or whose
# Declared before the run, never after: leave a threshold unset to declare none.
MIN_COVERAGE_PPM=${MIN_COVERAGE_PPM:-}
MAX_DROPOUT_INTERVALS=${MAX_DROPOUT_INTERVALS:-}
PLAYOUT_MS=${PLAYOUT_MS:-}
# Counters, four words each: NAME ROLE WIDTH FILE. ROLE is dev_underruns, late_packets, cpu_misses,
# source_bytes or other; WIDTH is 32 or 64; FILE holds the counter's value as its first word.
COUNTERS=${COUNTERS:-}
# Gauges, four words each: NAME ROLE FILE MAX. ROLE is playing (FILE holds 0 or 1, MAX is 1) or value
# (MAX is the largest reading you would believe).
GAUGES=${GAUGES:-}

mono_ns() { # /proc/uptime is seconds.hundredths since boot: append seven zeros to get nanoseconds
    read -r up _ < "$PROC/uptime"
    printf '%s%s0000000' "${up%.*}" "${up#*.}"
}

value_of() { # the first word of file $1 when it is a plain decimal number, else nothing (a missing value, never a zero)
    [ -r "$1" ] || return 0
    read -r v _ < "$1"
    case $v in '' | *[!0-9]*) return 0 ;; esac
    printf '%s' "$v"
}

emit_header() {
    printf '%s\n' 'ffw.baseline.capture.v1'
    [ -z "$NOTE" ] || printf '# %s\n' "$NOTE"
    meta="meta evidence=$EVIDENCE profile=$PROFILE cadence_ms=$CADENCE_MS declared_ms=$(( (COUNT - 1) * CADENCE_MS )) wall_step_ms=2000"
    [ -z "$PLAYOUT_MS" ] || meta="$meta playout_ms=$PLAYOUT_MS"
    [ -z "$MIN_COVERAGE_PPM" ] || meta="$meta min_coverage_ppm=$MIN_COVERAGE_PPM"
    [ -z "$MAX_DROPOUT_INTERVALS" ] || meta="$meta max_dropout_intervals=$MAX_DROPOUT_INTERVALS"
    printf '%s\n' "$meta"
    set -- $COUNTERS
    while [ "$#" -ge 4 ]; do
        printf 'counter name=%s role=%s width=%s\n' "$1" "$2" "$3"
        shift 4
    done
    set -- $GAUGES
    while [ "$#" -ge 4 ]; do
        printf 'gauge name=%s role=%s max=%s\n' "$1" "$2" "$4"
        shift 4
    done
}

emit_sample() {
    line="sample mono_ns=$(mono_ns)"
    if [ "${NOW%% *}" != false ]; then
        w=$($NOW)
        case $w in '' | *[!0-9]*) ;; *) line="$line wall_ns=${w}000000000" ;; esac
    fi
    set -- $COUNTERS
    while [ "$#" -ge 4 ]; do
        v=$(value_of "$4")
        [ -z "$v" ] || line="$line $1=$v"
        shift 4
    done
    set -- $GAUGES
    while [ "$#" -ge 4 ]; do
        v=$(value_of "$3")
        [ -z "$v" ] || line="$line $1=$v"
        shift 4
    done
    printf '%s\n' "$line"
}

{
    emit_header
    i=0
    while [ "$i" -lt "$COUNT" ]; do
        emit_sample
        i=$((i + 1))
        if [ "$i" -lt "$COUNT" ]; then $TICK; fi
    done
} > "$OUT"
```

<!-- e02-recipe:snapshot.sh -->
```sh
#!/bin/sh
# E02 memory snapshot. READ-ONLY: it reads /proc files and appends text to $MEMOUT.
# usage: PAGE_SIZE=4096 RESERVE_KIB=4096 MEMOUT=memory.txt snapshot.sh LABEL PID [PID...]
# LABEL is a generic word such as steady or transition: never a model, serial, address, room or person.
PROC=${PROC:-/proc}                      # where the kernel's /proc is mounted
MEMOUT=${MEMOUT:-memory.txt}             # keep it OUTSIDE git, for example under .local-real/
PAGE_SIZE=${PAGE_SIZE:?set PAGE_SIZE in bytes, for example from getconf PAGESIZE}
RESERVE_KIB=${RESERVE_KIB:-}             # the headroom you require, declared before the run; unset declares none
label=${1:?usage: snapshot.sh LABEL PID [PID...]}
shift

if [ ! -s "$MEMOUT" ]; then
    printf 'ffw.baseline.memory.v1 page_size=%s%s\n' "$PAGE_SIZE" "${RESERVE_KIB:+ reserve_kib=$RESERVE_KIB}" > "$MEMOUT"
fi
{
    read -r up _ < "$PROC/uptime"
    printf 'snapshot label=%s at_mono_ns=%s%s0000000\n' "$label" "${up%.*}" "${up#*.}"
    printf '%s\n' '--- meminfo'
    cat "$PROC/meminfo"
    for pid in "$@"; do
        printf '%s\n' "--- status pid=$pid"
        cat "$PROC/$pid/status"
        if [ -r "$PROC/$pid/smaps_rollup" ]; then
            printf '%s\n' "--- smaps_rollup pid=$pid"
            cat "$PROC/$pid/smaps_rollup"
        fi
        if [ -r "$PROC/$pid/statm" ]; then
            printf '%s\n' "--- statm pid=$pid"
            cat "$PROC/$pid/statm"
        fi
    done
} >> "$MEMOUT"
```

The series sampler is run with `OUT=.local-real/baseline.cap COUNT=3601 PROFILE=incumbent-music-v1` and the counters and gauge of
your device. The snapshot script is run once per moment you want a ledger of (steady playback, a source change, a reconnect), for
example `PAGE_SIZE=4096 RESERVE_KIB=4096 MEMOUT=.local-real/memory.txt snapshot.sh steady 123 456`, where the PIDs are the audio
path's processes. Take the page size from `getconf PAGESIZE` on the device; if you do not know it, do not guess: the script refuses to run
without it, because a `statm` page count means nothing in the wrong unit. The first snapshot creates the file and its header; later
ones append.

### Scrub before anything is shared

A capture is taken on a real speaker. Before a file leaves your machine:

1. **Read the whole file.** The scripts write only what is described above plus the one `NOTE` comment you chose, but check the
   comment, the profile, the series names, the labels and each `Name:` line of a `status` section.
2. **Look for what the analyzer cannot recognise.** It refuses names shaped like an address, a hardware or serial number or a
   host name, but a bare host name, a room, a person or an account is not shaped like anything. If you see one, change it in
   your copy, not in the original.
3. **Prefer to share the report, not the capture.** A report carries only numbers, the words the analyzer chose, the profile, the
   series names and the snapshot labels, and process names (redacted if they look like identifiers). The capture carries
   everything you typed.
4. **Never put the file in git**, in a `captures/` directory or under `tests/`, and never attach it to an issue or a bead.
5. If the analyzer **refuses** a name (see below), that is a stop sign for that file: rename and run again, do not edit the
   analyzer or the case files to let it through.

### Run the analyzer

The binary comes from the workspace's central build (`RCH_REQUIRE_REMOTE=1 rch exec -- cargo build --release -p franken-baseline`).
Given the files above:

```
ffw-baseline series .local-real/baseline.cap
ffw-baseline memory .local-real/memory.txt
ffw-baseline compare .local-real/current.cap --baseline .local-real/incumbent.cap [--margin-pct N]
```

Each prints one line of JSON on stdout and then one summary line on stderr (see "The summary line"), and exits 0; exit 2 is bad
input or usage (a one-line diagnostic on stderr, no report and no summary); exit 3 is a `compare` that refused to make a
comparative claim, with the reason in the JSON and a summary that says refused. `compare` needs a **physical** baseline with at
least 900 000 ppm coverage, and a current run of the same profile and also physical; anything else is refused.

### Reading the report

The summary line on stderr restates the verdict, coverage, dropouts and causes in words; the JSON has everything else.

* `evidence`, `profile`, `measured_on_device`: what kind of run this was. A synthetic or simulated capture is never a measurement.
* `denominators.coverage_ppm`, `expected_samples`, `intervals_observed`, `intervals_censored`: how much of the declared time has
  evidence. `holes` and `truncated` say where it has none.
* `counters[]`: `observed_events` and `per_hour_milli` (events per hour times 1000) over observed time only; `resets` and `wraps`;
  `unlocated_events_min` for events that fell in a hole or a reset and are kept out of every rate.
* `dropouts.known` is false when the capture has no underrun signal: the count is then unknown, never zero. Each dropout has a
  `cause` (`source_outage`, `network_lateness`, `cpu_deadline_miss`, `output_underrun`, `ambiguous` or `undetermined`) judged only
  from its own signal; `undetermined` names the signals the capture lacked.
* `absolute.verdict` (`qualified`, `not_qualified`, `not_assessed`) and its `reasons`, judged only against the thresholds you declared.
* `findings` (typed, capped at 256) and `findings_dropped` (how many were discarded past the cap).
* Memory: `snapshots[].processes[]` (`rss_kib`, `pss_kib`, `uss_kib`), `system.double_counted_kib` (what summing RSS would have
  overstated), `kernel_reported_kib`, `unattributed_kib` (a residual, not a measurement of any consumer), `peaks`, and
  `headroom.verdict` against your declared `reserve_kib`.

### What the repository checks about this recipe

`tests/e02/oracle.py --check` extracts the two scripts above from this file, lints them (no command that could change a device or
reach a network, writes only to `$OUT` or `$MEMOUT`, reads only `/proc`), checks their syntax under every POSIX shell on the host
(`sh`, `dash`, `bash`), runs them against scripted stand-in `/proc` files, and requires their output to be byte for byte
`tests/e02/synthetic/recipe_series.cap` and `recipe_memory.txt`. The cases `E02-RECIPE-SERIES` and `E02-RECIPE-MEMORY` then run the
analyzer on those files against hand-written expected reports, so the recipe and the parser agree. Three planted changes to the
scripts (a wrong padding, a wrong wall padding, a dropped `statm` section) must each stop reproducing the fixtures, and four planted
commands must each be caught by the lint. **What this does not show:** that the scripts behave on a device that has never run them,
that a counter you name means what you think it means, or anything about any speaker. A lint of shell text is not a proof of safety.

## Logging and redaction

The Logging clause of the bead asks for structured output with a human summary, redaction of tokens, keys, account and site
identifiers, bounded output, and that lost critical evidence marks a result incomplete. The analyzer is an offline batch function,
so each part is either met by a case or inapplicable for a stated reason (`tests/e02/cases.json`, the `INV-LOG-*` and `INV-REDACT-*`
invariants):

| Part of the clause | Here | Case or reason |
|---|---|---|
| versioned structured output | one line of JSON per run, with `schema`, `evidence`, `profile`, `measured_on_device` | `INV-LOG-STRUCTURED` |
| concise human summary | one line on stderr after the JSON, derived only from the report's own fields ("The summary line") | `INV-LOG-HUMAN-SUMMARY`, `INV-LOG-SUMMARY-NO-SITE-TEXT` |
| timebase, run/case/correlation IDs, member IDs, epochs, revisions, queue counters, fault schedule, causal chain | no running system emits events | `INV-LOG-EVENT-IDENTITY` (inapplicable) |
| bounded output, dropped-event counts | 4096-byte lines, 32-character echoes, 256 findings, `findings_dropped` | `INV-LOG-BOUNDED`, `INV-LOG-DROPPED-COUNTS` |
| redact tokens, keys, account and site identifiers | see below | `INV-REDACT-*` |
| render path, nonblocking sink, deadlines | no render path, sink or audio payload | `INV-LOG-RENDER-SINK` (inapplicable) |
| critical evidence loss marks the result incomplete | a lost span is a hole, truncation, `unknown` or `undetermined`, and the verdict is not met | `INV-LOG-EVIDENCE-LOSS` |

### The summary line

After the JSON report on stdout, `ffw-baseline series`, `memory` and `compare` print **one** line on stderr. A run that writes no
report (exit 2) prints none. The line is read back out of the report that was just printed, so it says nothing the report does not,
and its wording is fixed:

```
series:  ffw-baseline series: verdict VERDICT[ (REASON; REASON)]; evidence EVIDENCE, (measured|not measured) on a device; coverage PPM ppm
         (OBSERVED of TOTAL intervals observed, CENSORED censored); holes N; truncated (no|N ns missing); dropouts (unknown|N[, C censored]);
         causes (unknown|none|CAUSE N, ...); findings N, D dropped            (all on one line)
memory:  ffw-baseline memory: snapshots N; peak used X; max PSS sum X; max VmHWM X; headroom VERDICT (reserve X, required Y); findings N, D dropped
compare: ffw-baseline compare: claim refused (REASON); current evidence EVIDENCE
         ffw-baseline compare: claim made, VERDICT; baseline_per_hour_milli B, current_per_hour_milli C, margin M pct; current evidence EVIDENCE
```

* A REASON is `coverage_below_min: have P ppm, min Q ppm`, `dropouts_exceed_max: have H, max M` or `dropouts_unknown`, each as the report
  carries it. CAUSE is one of `source_outage`, `network_lateness`, `cpu_deadline_miss`, `output_underrun`, `ambiguous`, `undetermined`,
  listed in that order, only those with a nonzero count. X is `N KiB`, `unknown` (the kernel did not provide it) or, for Y, `not declared`.
* **`unknown` and `undetermined` read as exactly that.** A capture with no underrun signal reads `dropouts unknown; causes unknown`,
  never `dropouts 0` or `causes none`; a dropout whose cause the capture cannot tell reads `causes undetermined 1`. A refused comparison
  reads `claim refused`, with the report's own reason word.
* A value the report does not carry reads `?`; nothing is guessed.
* The line contains numbers and the analyzer's own fixed words only: **no profile, series name, snapshot label or process name**, so no
  input text can leave through it. For the clean synthetic capture it reads:

`ffw-baseline series: verdict qualified; evidence synthetic, not measured on a device; coverage 1000000 ppm (10 of 10 intervals observed, 0 censored); holes 0; truncated no; dropouts 0; causes none; findings 0, 0 dropped`

and for the first memory fixture (`mem_good.txt`):

`ffw-baseline memory: snapshots 2; peak used 13000 KiB; max PSS sum 2500 KiB; max VmHWM 3400 KiB; headroom pass (reserve 17000 KiB, required 4096 KiB); findings 1, 0 dropped`

Each `E02-SUM-*` case in `cases.json` carries its line written by hand. `tests/e02/oracle.py` derives the same line from its own
independent report (and, for `compare`, from the hand-written expected report) and requires both to agree, and the Rust test requires
the real binary's stderr to equal the line exactly, to be one line, and stdout to be exactly one line of JSON.

### Where input text is copied

An audit of every place the analyzer repeats text from its input, in a report or in a diagnostic:

| Where | Text | What happens |
|---|---|---|
| series report `profile`, and `current_profile` of `compare` | `meta profile=` | refused if shaped like a site identifier; otherwise repeated (letters, digits, `_`, `.`, `-`; at most 64) |
| series report `counters[].name`, `gauges[].name`, finding subjects | `counter name=`, `gauge name=` | refused if shaped like a site identifier; otherwise repeated (a letter, then letters, digits, `_`; at most 64) |
| memory report `label` | `snapshot label=` | refused if shaped like a site identifier; otherwise repeated (as a profile) |
| memory report `processes[].name` | the `Name:` line of `/proc/<pid>/status` | replaced by `<redacted:class>` if shaped like a site identifier; otherwise cut to 32 characters |
| diagnostics on stderr | a token, key, tag or section name, a value, a file's base name | replaced by `<redacted:class>` if shaped like a site identifier; otherwise cut to 32 characters |
| the summary line on stderr | none | numbers and the analyzer's fixed words only: no profile, name, label or process name |
| anywhere | `#` comment lines | skipped by both parsers and never copied |

Everything else in a report is a number, a fixed word the analyzer chose, or a validated enumeration. PIDs are numbers and are
reported; they identify a process within one boot, not a site.

### The screen

`crates/franken-baseline/src/redact.rs` classifies text by shape, in this order, and the first match names the class. All matching
is by ASCII bytes and fails closed: a false alarm is a refusal the analyst can rename around.

* `mac`: six two-digit hex groups joined by one kind of separator (`:` or `-`), anywhere in the text, or a whole run of exactly
  twelve hex digits.
* `ipv4`: a run of digits and dots that, without its leading and trailing dots, is exactly four groups of one to three digits.
* `ipv6`: a run of hex digits and `:` with at least two colons, no group longer than four characters and at least one hex digit.
* `hostname`: a run of letters, digits, `.` and `-` whose last label is `local`, `lan`, `home`, `internal`, `localdomain` or `arpa`
  (without regard to case) with a non-empty label before it.
* `serial`: a run of letters and digits at least 8 long with at least 3 digits and at least 3 letters.

A profile, series name or snapshot label with one of these shapes is **refused** with a typed error that names the line, the field
and the class and never repeats the text, for example `line 3: SiteIdentifier { field: "profile", class: "ipv4" }`. Any other input
text a diagnostic or a report repeats goes through `bounded`, which replaces text containing one of these shapes anywhere in it by
`<redacted:class>` before cutting to 32 characters, so no piece of an identifier survives the cut. `tests/e02/redaction_vectors.json`
pins the classifier's answer for 64 texts; the Rust test and `oracle.py` (which implements the same rules independently, with regular
expressions) must both agree with every one.

**What it does not do.** It recognises shapes, not meaning. A bare host name (`kitchen`), a room, a person's name, an account, or a
serial with fewer than three digits (`ABCDEFGH12`) has no recognisable shape and passes; the recipe's rules (generic names, scrub
before sharing) are the first defence and this screen is the backstop. It has false alarms by design: a version of four dotted
groups looks like an address, and a time of day (`12:30:45`) looks like an IPv6 address. It does not look inside
numbers. And it screens what the analyzer repeats; it cannot know what a person types into a file that is never run through it.

## Not proven

- Anything about a device, kernel, driver or network: inputs are synthetic.
- That a cause is *the* cause: `determined` means that candidate's signal fired and every other
  observable signal was quiet. Unobserved candidates are listed, not excluded.
- That a quiet capture is dropout-free beyond its observed time and its sampling cadence.
- That `unattributed_kib` is driver or DMA memory; it is whatever the simple model leaves over.
- Anything about 24-hour behaviour, group synchronisation or CPU deadlines on a board: those are the
  later campaigns and need their own authorised receipts.
- That the site-identifier screen finds every site identifier: it recognises shapes only (see "The screen"), so a bare host
  name, a room or a person passes. Nor that the recipe's scripts are safe on a device they have never run on.

## Verification

`tests/e02/oracle.py` (stdlib) re-derives each series and memory report independently; the Rust
integration test `crates/franken-baseline/tests/e02_cases.rs` runs the real binary over the same
captures against the same hand-written expected files, plus planted-difference tests of its own matcher.
Cancellation and restart do not apply (a pure batch function with no partial output); see
`cases.json`.

The recipe, the redaction rules and the Logging clause are checked as described in their sections above; `cases.json` may also name
strings a case's output must never contain (`stdout_lacks`, `stderr_lacks`), each of which must really be in the case's capture.
