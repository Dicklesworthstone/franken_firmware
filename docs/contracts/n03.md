# N03 contract: group clock and synchronized join (member side)

Bead `ffw-u07`. Code: `crates/franken-clock/src/group.rs` (tests in `group/tests.rs`). Independent
reference, vectors, judge: `tests/n03/`. Entry point: `scripts/e2e/n03`.

Status: **host simulation only.** Nothing here touches a device, a network or a clock other than the ones the
tests construct. The Rust was written before it was compiled; the evidence level of every claim below is the
judged central run recorded in the tracker comment, not this document.

## 1. What this is, and what it is not

The member side of a group clock. A member exchanges authenticated clock probes with the group's coordinator
(the leader of the current epoch), fits a transform from its own monotonic clock to the group clock, says how far
that transform can be trusted, and is allowed to make sound only while that uncertainty is within an explicit
threshold and a start has been admitted.

* **A network-clock fit, not DAC alignment.** Every answer is "the group clock reads X at local time T, give or
  take U". Decode, resampler and DSP delay, DMA depth and the DAC pipeline are separate terms the render path
  adds. The only board terms modelled here are the calibrated output delay and its stated uncertainty
  (`BoardProfile::calibrated_output_delay_us`, `calibration_uncertainty_us`). A small U is not a claim about the
  speaker cone, and every `ClockReport` carries `claim = "network-clock-fit-only: not DAC or acoustic alignment"`.
* **No promise from an NTP-style offset alone.** The four-timestamp offset is exact only if the two path delays
  are equal, which the timestamps cannot show. For forward delay `df` and return delay `dr` the offset is wrong by
  exactly `(df - dr) / 2`, which is bounded by half the exchange delay but not otherwise knowable. That half is
  **in** the uncertainty (section 4). A path whose half-delay alone is above the threshold never locks
  (case `N03-ASYMMETRIC`).
* **Authenticity is N01's job.** Probes arrive over the authenticated control channel (N01 `AuthenticatedStreamPacket`
  coverage of epoch, sequence and timestamps). This module checks what is left: epoch, leader, request/response
  pairing (replay), timing sanity and plausibility. A caller that feeds it unauthenticated bytes has not met the
  precondition.
* **Standalone.** Plain-typed inputs (`u64` epoch and nanosecond timestamps, as N01 carries them); no dependency on
  the stream or session crates. `franken-clock` depends only on `franken-board-profile`.

## 2. Inputs consumed

| from | what | how it is used |
|---|---|---|
| N01 | epoch (`u64`), timestamps (ns, at most 2^62), replay window | `ProbeRequest`/`ProbeResponse` carry plain `u64`s; epochs advance only by `begin_epoch` (control), never by a probe |
| D03 | `RateEstimator` (`franken-clock::rate`) | the group timeline, as a wrapping 48 kHz `u32` frame counter, against the local clock in microseconds; supplies the frequency ratio and its standard error, and absorbs counter wrap |
| P02 | monotonic ns clock, `ClockError::WentBackwards` | a platform clock failure is reported with `report_clock_fault()`; the timer resolution is the `timer_resolution_ns` parameter |
| G01 | authority validity | `set_authority(epoch, expires_at_local_ns, now)`; holdover never outlasts it |
| board profile | output delay, calibration uncertainty | `GroupClockConfig::for_board` (microseconds to nanoseconds) |

## 3. The exchange

A request is `ProbeRequest { epoch, seq, t1_local_ns }`. The response is
`ProbeResponse { epoch, leader, seq, t1_echo_ns, t2_group_ns, t3_group_ns }`: the coordinator's group-clock
readings when it received the request (`t2`) and when it sent the response (`t3`). The member reads `t4` on arrival.

`seq` starts at a `seq_base` the caller takes from the platform entropy source on every boot, and the response
echoes `t1`. A response matches an outstanding request only if **both** repeat, so a response recorded before a
restart (it carries a valid MAC) cannot answer a request made after it. Reusing `seq_base` and `t1` across a
restart would defeat this; that is the caller's contract (section 12).

Sample rules, in this order (`Sample::from_exchange`; the reference's `sample`):

1. `t4 <= t1` -> `LocalClockRegression` (a sample-level reject; the fit is untouched).
2. `t4 - t1 > request_ttl_ns` -> `ExpiredRequest`.
3. `t3 < t2`, or `t2` or `t3` above 2^62 -> `Malformed`.
4. dwell `t3 - t2` greater than the round trip -> `Malformed`.
5. delay `(t4 - t1) - (t3 - t2)` above `max_delay_ns` -> `ExcessiveDelay`.

Otherwise the sample is `local_mid = t1 + rtt / 2`, `group_mid = t2 + dwell / 2` (both floor), `delay`, and
`offset = group_mid - local_mid`. Boundaries are inclusive: a round trip equal to the lifetime, a delay equal to the
maximum, a timestamp equal to 2^62 are accepted by these rules.

## 4. Uncertainty, anchor, transform

* Base uncertainty of a sample: `ceil(delay / 2) + timer_resolution_ns + calibration_uncertainty_ns`.
* At local time `at`: base + `ceil(max(0, at - local_mid) * ratio_unc_ppb / 1e9)`. The growth rounds **up**; a
  time before the midpoint costs nothing.
* **Anchor:** the sample with the smallest uncertainty at the query time; ties go to the newer midpoint, then to the
  later sample. (The ordering of samples does not change with time, so the anchor is stable between probes.)
* **Transform** (exact integer, floor): `group(now) = group_mid + floor((now - local_mid) * (1e9 + ratio) / 1e9)`
  and its inverse `local(g) = local_mid + floor((g - group_mid) * 1e9 / (1e9 + ratio))`, both clamped at zero.
* The claim the tests check against known truth: **at any query time, the true group time is within
  `uncertainty_ns` of the reported group time.** Every scripted world carries the true group time at its checks;
  the generator refuses a world that breaks the claim, and the Rust and the judge re-check it from what the Rust
  reported.

## 5. Frequency

Only good samples feed the frequency fit: a delayed exchange is mostly path asymmetry. A sample is fed to D03's
`RateEstimator` when its delay is within `rate_delay_slack_ns` of the best delay in the window and its midpoint
(in microseconds) is later than the last fed one. The fed position is `frame_position(group_mid)`, the group
time as a wrapping `u32` at 48 kHz (it wraps near 24.86 hours); D03 unwraps it.

* **Ratio state** (does not depend on the query time, so holdover and start planning have closed forms): if the
  estimator has a `Valid` estimate, `ratio = correction_ppb` and `ratio_unc = rate_sigma_multiple * sigma + wander_ppb`
  (3 sigma plus an assumed 6 ppm of wander over a holdover); otherwise `ratio = 0` and
  `ratio_unc = oscillator_bound_ppb` (100 ppm).
* A D03 discontinuity (an observation gap, an implausible rate, a position jump, an ambiguous timeline) restarts the
  **frequency fit only** (a new rate epoch), never the offset fit. An offset step is judged by the prediction check
  (section 7), which is what clears the clock. Case `N03-DRIFT` (sparse probes) shows the restart with the clock
  staying locked.
* The 3 sigma is a modelling choice, not a proof: the estimator's `uncertainty_ppb` is a one-sigma standard error
  of a straight-line fit and assumes independent noise. The tests check it against known truth in the worlds they
  build (`N03-DRIFT`, `N03-SOAK`, `N03-TRUTH-SIM`); they do not prove it for arbitrary networks.

## 6. Status and holdover

`status(now)`, in this order:

1. fewer than `min_probes_for_lock` (4) samples accepted since the last reset -> **Unlocked**;
2. anchor uncertainty above `lock_uncertainty_ns` (the explicit threshold, default 2 ms) -> **Expired** if the
   member has ever been locked in this epoch, otherwise **Unlocked**;
3. last accepted probe no older than `fresh_ns` (3 s) -> **Locked**;
4. never locked -> **Unlocked**; otherwise **Holdover** while `now` is before the holdover limit, else **Expired**.

**Holdover limit** = the first local instant at which holdover is no longer allowed =
`min(authority_until, buffer_until, uncertainty horizon)`, where the horizon is the first instant at which the
anchor's uncertainty exceeds the threshold:
`local_mid + floor(max(0, threshold - base) * 1e9 / ratio_unc) + 1` (never, if `ratio_unc` is 0). Absent bounds are
ignored. Ties are reported in the order **Authority, Buffer, Uncertainty**. The result names which bound set it
(`Binding`). The judge and the anchors check, by brute force, that the last allowed instant and the first refused
instant bracket the threshold.

An unlocked member is never audible. A recovery from `Expired` is **muted**: the admitted start is cleared the
moment the expiry is observed (by `tick`, by a response arriving, or by `set_authority`), so sound returns only after
a fresh lock and a fresh admission (`N03-HOLDOVER`, `N03-JOIN`).

## 7. Admission of probes, and discontinuity

`on_response` checks in this order; every rejection is counted in its own slot and leaves the fit untouched except
where stated:

1. `resp.epoch < epoch` -> `StaleEpoch`; `>` -> `FutureEpoch` (epochs arrive by control, not by probe).
2. `resp.leader != leader` -> `UnadmittedLeader`.
3. no outstanding request with this `seq` **and** `t1_echo` -> `UnsolicitedOrReplayed` (a request is answered at most
   once; the table holds at most `max_outstanding` requests and drops those older than the lifetime).
4. `t4` earlier than the last accepted `t4` -> `LocalClockRegression` **and a full reset**: the local clock went back,
   so nothing measured on the old readings describes the new ones.
5. the sample rules of section 3.
6. **Prediction check:** if the sample's group midpoint differs from what the current fit predicts for its local
   midpoint by more than
   `uncertainty(anchor at the sample's midpoint) + ceil(sample delay / 2) + prediction_slack_ns`, the exchange is a
   clock jump (a suspend, a group-clock step, a counter reset, a half-range or one-counter-period jump, which the
   frame counter cannot tell from no jump): `Discontinuity`, **full reset, muted**, relock required. A step equal to the
   allowance is noise and is accepted; one nanosecond more is a jump (`N03-JUMP`, boundary pair).

A **full reset** drops all samples and outstanding requests, restarts the frequency fit, clears the admitted start,
and mutes with reason `Discontinuity`.

`begin_epoch(epoch, leader)` (control) requires `epoch` to increase, clears everything including the authority, and
mutes with `EpochChange`. The new leader's timebase is not the old leader's. Probes of the old epoch afterwards are
`StaleEpoch` and change nothing (`N03-LEADER-CHANGE`).

A **reboot** is a new instance: no lock, no outstanding requests, no persisted fit (`N03-REBOOT`).

`report_clock_fault()` (P02 reported a clock failure) is a full reset with reason `ClockFault`. **Suspend detection is
the platform's job**: a monotonic clock that stops during suspend leaves the member believing its old fit until the next
probe, at most one probe interval later, which the prediction check then calls a discontinuity (`N03-JUMP`).

## 8. Synchronized join

A future start is `StartSchedule { epoch, start_group_ns }`: a group time at which a frame boundary is presented
(N01's `presentation_time_ns`). `plan_start` (a pure query) and `admit` (the same, then arms) decide, in this order:

1. schedule epoch below the member's -> `StaleEpoch`; above -> `FutureEpoch`;
2. status not `Locked` -> `NotLocked` (a member in holdover can keep sounding, but does not take on a new start);
3. start more than `max_future_ns` (5 s) ahead of the group clock now -> `TooFarAhead`;
4. `start_local = local(start_group) - output_delay_ns`; `deadline = start_local - catchup_ns` (100 ms of muted
   catch-up); `now > deadline` -> `TooLate`;
5. uncertainty **at the start instant** above the threshold -> `UncertaintyAtStart`;
6. start at or after the holdover limit -> `ExpiresBeforeStart`.

An accepted plan reports `start_local_ns`, `deadline_local_ns`, `uncertainty_at_start_ns`, `valid_until_local_ns` and
the `binding`. `tick(now)` is **audible** only when: the clock is `Locked` or in `Holdover`, the authority (if any) has
not expired, a start was admitted, and the group clock has reached `start_group - output_delay`. Before that it is
`Armed { starts_in_ns }`. Everything else is `Muted(reason)` with one of `NotLocked`, `NotAdmitted`, `ClockExpired`,
`AuthorityExpired`, `Discontinuity`, `EpochChange`, `ClockFault`.

**Mixed profiles.** Two members with different local clocks, skews and board profiles (output delay, calibration
uncertainty) join the same start; the true instants at which they begin sounding (their local start, mapped back through
their own clock, plus their own output delay) differ by no more than the sum of their uncertainties at the start, and by no
more than the provisional room-group gate of 2 ms (`N03-MIXED-PROFILE`). The gate is provisional, as in the bead.

## 10. Cases and the acceptance map

(`N03-JUMP`) with the audible relock; each admission reject (`N03-ADMISSION`) with an accepted exchange.

## 11. Parameters (defaults; the Rust `standard()` must equal `tests/n03/reference.py DEFAULTS`)

| name | default | meaning |
|---|---|---|
| `max_delay_ns` | 50 000 000 | a sample with a larger path delay is not used |
| `request_ttl_ns` | 2 000 000 000 | a request unanswered this long is dead |
| `min_probes_for_lock` | 4 | samples needed to lock |
| `lock_uncertainty_ns` | 2 000 000 | the explicit threshold (`DEFAULT_MAX_ADMITTED_UNCERTAINTY_US` = 2000 us) |
| `fresh_ns` | 3 000 000 000 | a probe this recent keeps the status `Locked` |
| `oscillator_bound_ppb` | 100 000 | worst-case ratio error before an estimate is in force |
| `rate_sigma_multiple` | 3 | sigmas of the rate estimate in `ratio_unc` |
| `wander_ppb` | 6 000 | assumed change of the ratio over a holdover |
| `timer_resolution_ns` | 1 000 | resolution of the clocks' readings |
| `calibration_uncertainty_ns` | 0 | board term (`for_board`) |
| `output_delay_ns` | 0 | board term (`for_board`) |
| `prediction_slack_ns` | 500 000 | allowance beyond the fit's own uncertainty before a step is a jump |
| `rate_delay_slack_ns` | 500 000 | only samples this close to the best delay feed the frequency fit |
| `catchup_ns` | 100 000 000 | muted catch-up before a start |
| `max_future_ns` | 5 000 000 000 | furthest admissible start |
| `window` | 16 | samples kept (at most 64) |
| `max_outstanding` | 8 | requests awaiting a response |

A member behind a long network path cannot lock at the default threshold: a Wi-Fi member with a 6 ms round trip has 3 ms
of unavoidable asymmetry bound. That is the honest consequence of section 1, not a defect; the threshold is configuration.

## 12. Not covered, and why

1. DAC, acoustic and analog alignment; audible quality; **cycles on a real core**: not measured, need hardware. The clock's
   decisions and its cost in executed instructions on the soft-float big-endian MIPS target ARE measured, under QEMU (section 14).
2. Everything is host simulation with scripted clocks. No real network, no real timer resolution, no real suspend.
3. N01 MAC verification and its replay window are assumed done by the caller. `seq_base` must come from entropy on every boot
   and not repeat with the same `t1` across a restart; the module cannot check that.
4. Suspend and resume are detected by the next probe (<= one probe interval), not at the instant; a platform that can detect them
   (boottime versus monotonic) must call `report_clock_fault()`.
5. The 3 sigma plus 6 ppm ratio bound is a model, checked against known truth in the worlds built here, not proven in general.
6. The 2 ms room-group gate is provisional (as in the bead); no measurement of real room skew exists here.
7. The legacy `GroupClockEstimator` in `franken-clock/src/lib.rs` is left untouched; its retirement is outside this bead.
8. Exact tolerance of the frequency fit's float standard error is stated in the judge, not eliminated.
9. The events leave the clock as plain `ClockEvent`s in the shared buffer (section 13), and `group` writes the
   production `ffw.log.v1` line for one. The Virtual House harness is the first consumer: `franken-speaker/src/clock_log.rs`
   drains each member's events into a bounded `BoundedDiagnosticSink` of that member's own (256 events, 128 KiB) after
   bring-up and after every block's gate, and section 13 says what is pinned. **Still not covered:**
   * a real pseudonym key: a member's clock log can be made pseudonymous (`ClockLog::new_with_key`, section 13) and tests
     pin that no raw label then reaches any stored field, but the key is a parameter and nothing supplies one. Where it
     comes from is the platform's entropy capability (P02). The harness passes none: its labels are synthetic and go in as
     they are, as in the campaign's own sink;
   * the harness's own campaign events (`stream_refused`, `fault_injected`, `campaign_failed`) write the raw member id into
     `correlation_id`, `message`, `fault` and `cause`, which a keyed sink does not rewrite. They have no key today, so this
     is latent, and it is outside the clock log;
   * a file, a shipped log or a sink shared between members: each member has its own sink, so logs are not merged and
     a line's timestamp is its member's own monotonic clock;
   * a sink under real load or concurrency: the drain is a single-threaded call in a simulation, and the claim is only
     that it never retries, never waits and never touches the clock beyond popping its buffer;
   * a drain on a device: the sink lives in `franken-test-support`, which the P01 contract keeps out of every device
     closure, so the drain exists only behind the `harness` feature.

## 13. Diagnostics: structured clock events

`GroupClock` records what it does as plain `ClockEvent`s in the crate's shared fixed-storage buffer
(`franken_clock::events::EventBuffer`, capacity `EVENT_RING_CAPACITY` = 64). The owner pops them (`pop_event`) and
serializes on its own side; the clock performs no I/O, callback or allocation per event. An event is one thing the clock
did or saw:

| kind | critical | when | notable fields |
|---|---|---|---|
| `n03.probe.accepted` | no | an exchange was accepted | `delay_ns`, `uncertainty_ns`, relock progress `accepted_in_epoch` of `lock_needed` (n of 4) |
| `n03.probe.rejected` | no | an exchange was rejected | `cause` = the reject code |
| `n03.reset` | yes | the fit was cleared (`Discontinuity`, `LocalClockRegression`, `ClockFault`) | `cause` |
| `n03.epoch.begin` | yes | `begin_epoch` advanced the epoch | |
| `n03.status.locked` / `holdover` / `expired` / `unlocked` | yes | the status changed since the last observation | `uncertainty_ns`; for holdover `cause` = which limit binds (Authority, Buffer or Uncertainty) |
| `n03.output.muted` / `armed` / `audible` | no | `tick` found a change in what the output may do | `cause` = the mute reason |
| `n03.admit.accepted` / `rejected` | no | `admit` | `uncertainty_ns` at the start, or `cause` = the reject code |
| `n03.truth.within` / `violated` | violated is critical | `note_truth(now, true_group_ns)` | `error_ns` = the estimate minus the known truth (signed, saturating), `uncertainty_ns` |

Observation points are exact and mirrored by the reference: a status change is looked for after every response, after
`tick`, `begin_epoch` and `report_clock_fault` (the last two at the last event time, since they carry none); an output
change after every `tick`. `set_authority` and `set_buffer_until` are not observation points: a status change they cause
is logged at the next response or tick, with that later timestamp. Order within one call: the exchange event, then the
reset event, then the status event.

* **A clock-fit claim.** Every event carries `claim` = `network-clock-fit-only: not DAC or acoustic alignment`, and so
  does the message of every log line. An estimated error against a known truth is an error of the *clock fit*, nothing
  more.
* **Nothing from a peer.** `kind` and `cause` come from a fixed vocabulary; the numbers are this member's own counters,
  epoch and readings of its own clock. A leader id, a member name or a string that arrived in a probe is never copied into
  an event or a line (`n03_log_labels_are_validated...` plants a stranger's leader id and checks it is absent). Timestamps
  are the member's monotonic local clock, clamped never to go backwards. `revision` counts the events the clock created,
  including any later dropped.
* **Bounded, counted, critical kept.** Ordinary events are admitted at most `EVENT_RATE_PER_WINDOW` = 32 per
  `EVENT_WINDOW_NS` = 1 s of the clock's own time (the rest are counted `rate_limited`) and are dropped when the buffer is
  full; a critical event bypasses the rate cap and evicts the oldest ordinary one when the buffer is full, and is lost
  (counted in `lost_critical` and `critical_lost`) only when the buffer holds nothing but critical events. An unavailable
  log (`set_events_available(false)`) drops everything and counts it. The accounting is exact:
  `emitted == delivered + pending + dropped`, and `critical_lost` (a subset of `dropped`) non-zero means the evidence of
  the run is incomplete. `ClockReport` carries `events_dropped` and `events_critical_lost`.
* **No feedback.** Popping the buffer, never popping it, a full buffer, a rate-limited flood or an unavailable log changes
  no decision: `n03_a_full_unpopped_or_unavailable_event_buffer_changes_no_decision` runs one world three ways and requires
  identical decisions, with drops counted in the other two.
* **The drain into a sink.** `clock_log::drain_clock_events` pops the events pending when it is called, oldest first, and
  hands each to the sink once: `emit_critical` for a critical event, `try_emit` for the rest. It never retries, never
  waits and calls nothing else on the clock. Pinned by `clock_log` tests: the sequence in the sink after a lock, a tick, a
  replayed answer, a 2 s step and the relock equals the list the tables above give (16 events, causes included); in a
  five-slot sink the three critical status and reset events survive and every other drop is counted (emitted 16 = stored
  5 + dropped 11, 3 of them evicted); one 120-step world decides identically with a working, a full, a zero-sized and an
  unavailable sink and with no sink, while the sinks differ in what they kept (the unavailable and zero-sized ones keep
  nothing and report critical evidence lost); a node's audible gate over 400 blocks is identical with a working, a full
  and an unavailable clock log; every member of a campaign reports its log counts (`MemberSimulationStats.clock_log`).
  **Planted:** a drain that retries a refused event is caught by the offer count (events offered to the sink versus
  events popped), and a drain that reports a clock fault when the sink refuses is caught by the comparison with the
  no-sink decisions; the real drain passes the same judge.
* **Pseudonyms reach every field.** A keyed `BoundedDiagnosticSink` rewrites `member_id` and `group_id` only, and the clock
  builds `correlation_id` from the member label, so a keyed sink handed raw labels stores the raw member label in every
  `correlation_id` (`a_keyed_sink_alone_leaves_the_raw_member_label_in_the_correlation_id` pins it, with a scan over every
  serialised field and the `to_jsonl` output that names the field). `ClockLog::new_with_key` derives the labels first,
  through the sink's own keyed path, and leaves its own sink unkeyed: the scan then finds no raw label in any field or in
  the serialised log (`a_pseudonymous_clock_log_carries_no_raw_label_in_any_field_or_in_the_jsonl`), the events are the
  documented sequence, and the pseudonyms equal independently computed vectors, are stable per member, differ across members
  and keys, and equal what a campaign's keyed sink and the control channel's log give the same id.
* **The production line.** `ClockEvent::to_log_line(&LogContext)` writes one `ffw.log.v1` line: the fields and the field
  order of `franken-test-support`'s `DiagnosticEvent` (`schema_version`, `timestamp_mono_ns`, `run_id`, `case_id`,
  `correlation_id` = member label + `#` + revision, `member_id`, `group_id`, `source_epoch`, `state_revision`,
  `event_kind`, `message`, `queue_depth` = samples held, `latency_us` = the exchange delay, optional `fault` and `cause`).
  `LogContext` takes the owner's run, case, member and group labels (and an optional fault-schedule label), each 1-64 bytes
  of `a-z0-9._-` starting with a letter or digit; `franken-clock` does no hashing, links no `franken-test-support` in
  production code, and refuses a line over 1024 bytes (the caller counts it dropped) instead of truncating it. A
  dev-dependency test parses every line into `DiagnosticEvent` and checks that serializing it again gives the same bytes.
* **Judged against the reference.** The reference's member model emits the same events by the same rules, with a
  restatement of the buffer's policy. Every scripted world's per-op event list is re-derived by the judge and compared with
  what the Rust printed (so each world case above also judges its events). The buffer accounting is checked against
  hand-derived numbers: 100 unsolicited responses one second apart leave 64 pending and 36 dropped, and 70 critical epoch
  events then evict 64 ordinary ones and lose 6 (emitted 170 = 64 pending + 106 dropped); the same 100 responses one
  microsecond apart leave 32 pending and 68 rate limited; 13 events offered to an unavailable log are all dropped, 3
  of them critical. The sequence of a lock, a replay, a clock jump and the relock, and a platform clock fault, are checked
  against hand-derived label lists, and the production lines of the lock/jump/relock scenario are compared byte for byte
  with the reference's.

## 14. The target ISA: the clock's decisions and cost on a big-endian MIPS guest (`N03-TARGET-RECEIPT`)

`toolchain/src/n03-target` is `GroupClock` and its rate estimator built for `mips-unknown-linux-musl` (soft-float, MIPS32r2,
big-endian, 32-bit `usize`) and run as PID 1 of the Debian 4.19 Malta guest under QEMU 11.1.2 with `-icount shift=0` (24Kf).
The clock does 64-bit and 128-bit integer arithmetic, a rational least-squares rate fit and `f64` (`i128` sums converted to `f64`,
a soft-float `sqrt`, a `ceil`), which is where host-green code can differ. `toolchain/src/measure-n03-target.py` boots it and
judges the serial transcript; `crates/franken-clock/tests/n03_target_worlds.rs` runs the same `cases.rs` on the build host.

* **Worlds.** The 28 scripted worlds of `tests/n03/vectors.json` and the two members of the mixed-generation join (1,839 ops),
  through the public API only, one JSON record per op. The judge compares every record with the independent Python reference
  (`judge_world`, which re-derives the expectation at judge time) and compares a digest per world, byte for byte, with the host
  build. A difference where the guest still agrees with the reference would be a finding about the target ISA, reported as such
  and not adjusted.
* **Seeded worlds.** Two simulated worlds (coordinator clock, member clock with offset, skew and 1 us resolution, seeded
  asymmetric delay, jitter and loss) whose LCG seeds are derived from a per-run seed the host packs into the initramfs
  (SplitMix64, mirrored bit for bit in the judge and pinned by known answers in both languages). The judge re-derives every
  figure from a mirror of the reference's `Sim`, so records from another run, canned records or records copied from the host build
  cannot carry the right ones (`N03T-SEEDED`). A truncated dump fails `N03T-TRANSCRIPT`. Both are planted in the receipt and must
  fail; so must a reordered record, a changed record under a matching digest, and a host digest that differs.
* **CPU.** Guest instructions for a steady stream of exchanges (`next_probe` + `on_response`, 100 per repetition after a warm-up that
  fills the sample window and the rate fit) and for the per-block gate path (`tick`, `local_for_group`, `output`, 400 per
  repetition), read from the CP0 Count through a ruler calibrated in the same boot against loops of known length, before and after,
  after a settling sleep, with nothing printed until everything is measured. Gates: the ruler's shape agreement, drift and linearity,
  every operation completing (every exchange accepted, every presentation time mapped), each region inside the ruler's calibrated
  3.9 to 60 M instructions (a region outside it is "extrapolated" and fails: the first boot's 2,000-call gate region ran 118 M
  instructions and was refused, then re-cut to 400 calls), and a stable floor.

**Recorded run** (`toolchain/results/runs/c7946b45bd86b92b864fede44c9fdec5/`, ELF sha256 `bf1957e2...`): two real boots with
different seeds pass all six gates; the planted replay fails `N03T-SEEDED` and the planted truncation fails `N03T-TRANSCRIPT`.
All 30 worlds equal the reference and the host build. Guest instructions (minimum of 5 repetitions): **155,057 per exchange** and
**56,934 per gate call** (the second boot agrees within 0.1 %), about 11.6 M instructions per second of one member's clock work
at one gate call per 256-frame block and one exchange per 32 blocks. For scale, D03's resampler costs 2,284 to 3,040
instructions per output frame (section 4.2 of `d03.md`), 110 to 146 M per second for one stereo stream: the clock is about a tenth
of that.

`N03-TARGET-RECEIPT` (in `scripts/e2e/n03`, every tier) re-judges every committed receipt of this kind: each stored transcript must
match its recorded sha256 and size, the host records their sha256, every re-derivable gate and the first finding and exit code
must equal the receipt's, the real run must pass and both planted negatives must fail, and the recorded ELF must be proven
soft-float (0 FPU opcode words, `.MIPS.abiflags` soft). The ELF is not committed, so those two facts are recorded and not
re-derived here. With no receipt the case is blocked.

**Not covered by 14:** cycles on a real core (QEMU counts executed instructions; no cache, pipeline, memory-latency or multiplier
timing; no board clock, and the repository records none for any MIPS board, so no percentage of a CPU is claimed); the PowerPC
boards (hard-float, a different ISA, no run); real network delay, a real timer resolution, suspend and resume; DAC, acoustic or
analog alignment (the clock is a network-clock fit only). The ruler's fitted intercept was negative in both boots (about -340 and
-709 ticks against regions of millions of instructions); its residual and drift gates held, and the cause is not explained.
