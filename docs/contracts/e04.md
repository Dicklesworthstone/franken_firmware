# E04 contract: retained audio driver ownership and protection (`ffw-25l`)

Status: implemented offline, **verification pending**. Nothing here is a hardware claim. Every result
is a host simulation or a document check. The driver contract is **not established**: every
interface and radio-duty field in the committed matrix is `unknown` with a named external blocker,
and hardware eligibility is therefore refused. That is the intended, honest state, not a gap to paper
over.

## Contract records

A record describes one retained-driver interface, field by field. Each field is **known** (a value
plus an anchor), **unknown** (a named `EXT-E04-*` blocker says what would establish it) or **not
applicable** (with a reason). Fields: interface kind (ioctl, write, read, poll, mmap), command
number, full command word, direction, payload size, endianness, alignment, field map. A radio-duty
record has an owner (kernel driver, stock daemon or chip firmware), whether it survives daemon
replacement, and a bound on the audio scheduling delay it can cause.

Two more kinds of record cover the rest of the bead's scope, with the same known / unknown /
not-applicable rule:

* **Topology** (one required): the channel count, which transducer each driver channel feeds (the
  board-profile role vocabulary, for example `woofer_mono`), the supported sample rates and the sample
  encoding. A topology contradicts itself if it has zero channels, a route count that differs from the
  channel count, channel indices that are not `0..n-1` once each, a channel that feeds no named role,
  or rates that are empty, outside 8 kHz to 384 kHz, or not strictly increasing.
* **Amplifier sequences** (a startup, a shutdown and a fault, all required): the ordered steps
  (`assert_mute`, `enable_clocks`, `configure_codec`, `prime_silence`, `deassert_mute`,
  `disable_clocks`) with the least delay after the previous step, and whether the sequence waits for
  the mute to be acknowledged. The policy is the board profile's safe order: **mute first**, and a
  startup is a subsequence of assert-mute, enable-clocks, configure-codec, prime-silence,
  deassert-mute in that order that **ends by unmuting**; a shutdown or a fault may only mute and cut
  the clocks and **never unmutes**; no action repeats; and a sequence that does not wait for the mute
  to be acknowledged is refused, because a mute that was only requested is not a mute.

An **anchor** is one of: an artifact digest plus section, offset and optional symbol; a public
source reference; or an explicitly labelled synthetic fixture. An artifact anchor must name a
registered artifact, a registered section and an offset inside it.

**Eligibility** (`ContractMatrix::evaluate`): hardware-eligible only if every required operation
(query capabilities, acquire exclusive, prepare format, submit block, query position, start, set
gain, drain, abort into mute, release) and every required radio duty (multicast, unicast,
power-save, roam, congestion, mesh membership, scheduler interference) has a record, there is a
topology and a startup, shutdown and fault sequence, and every field of every record is known and
anchored on an artifact or public source, or is not applicable with a reason, and no record
contradicts itself. The verdict lists each missing item exactly: record,
field, and the reason or blocker. Synthetic anchors satisfy the offline model and never hardware.
Driver size is registered metadata and is **not an input**; a test evaluates the committed matrix
with sizes from 0 to `u64::MAX` and requires identical verdicts.

`AudioHalDevice::open_for_hardware` (and `HalSession::open_hardware`) checks the board profile first,
then the matrix **against that profile** (`ContractMatrix::evaluate_for_profile`), and returns
`HalError::ContractIncomplete { missing }` with the exact list. The profile check is a cross-check
of the topology: a driver that feeds a different number of channels than the profile says, or a
different transducer on a channel, is a contradiction and is listed (Rust-tested only; the Python
model does not know board profiles). A topology that is still unknown adds nothing here, because it is
already listed as unknown. Offline use stays on `open_for_profile`, which never reaches an amplifier.

## What the artifact establishes (model-16 `audiodev.o`, sha256 `14c202fa…9bd2`, 77380 bytes)

Re-derived by `anchor_extract.py` from the git-ignored capture (not committed): ELF32 MSB
relocatable PowerPC, three char-device ioctl handlers (`dsp_device_ioctl` at `.text+0x29f0`,
`audioctl_device_ioctl` at `.text+0x6fac`, `i2c_device_ioctl`, an 8-byte stub). For
`dsp_device_ioctl`, decoded from instruction fields:

- The command word uses the **PowerPC `_IOC` layout**, not an x86 or Arm host layout: number bits
  0..7, type 8..15, size 16..28 (13 bits, `rlwinm` shift 16, mask bits 19..31), direction 29..31.
  Bit 31 (write) selects a copy-in and bit 30 (read) a copy-out.
- The size is **clamped to 16 bytes** and both copies use one 16-byte stack buffer. The driver reads
  only the low byte to dispatch; it does not check the type byte or the exact size.
- Dispatch is a 42-entry jump table at `.rodata+0x10` (number bound 41). **14 numbers are handled**
  (2, 10, 11, 20, 32..41; 40 and 41 share a target); the other 28 return -1.

### `audioctl_device_ioctl` (3,460 bytes at `.text+0x6fac`)

The same `_IOC` decoding as `dsp`: low byte dispatches, the type byte and the exact size are not checked.
Differences, each a decoded instruction field and not a guess:

- The copy is **clamped to 32 bytes**, in and out (`min(32, size)`; the copy-out happens only when the read bit is
  set and a per-case length register, `r30`, is positive when the case finishes).
- Dispatch is a **150-entry** jump table at `.rodata+0xe8`, indexed by `number - 6`, so it covers numbers **6..155**.
  **24 numbers are handled** on 23 distinct targets (18 and 38 share one): 6, 12, 18, 24, 25, 28, 30, 38, 44 to 49,
  52 to 54, 59, 62 to 64, 144, 147 and 155. The other 126 go to one block, `li 3, -1`.
- For each handled number the facts list the **external functions its code reaches** (a control-flow walk, excluding
  the shared copy-out tail, which calls only `__copy_tofrom_user`) and the **payload words it touches directly
  through the stack frame**. The callee names are, in groups: port pins (`m8260_port_set`, `m8260_port_read`,
  `mio_set`), PWM (`dsp_device_set_pwm`, `eden_set_pwm`, `dsp_device_set_led_pwm`, `dsp_device_set_dcofs`), LEDs
  (`audioctl_set_leds`, `audioctl_ledtimer`), buttons (`audioctl_get_button_state`, `button_event_send`), I2C register
  access (`i2c_read_reg`, `i2c_write_reg`), a time-format helper, and kernel locking and scheduling.
  Some cases read `sys_mdp` fields first, so what they do depends on the board type.

**What this does not show.** The callee names above are listed as evidence and nothing is inferred from them: a PWM
or a port pin could be amplifier-related, and the names do not say what any command means. There is no operation
mapping, and the matrix is unchanged: `EXT-E04-OP-MAPPING` and
`EXT-E04-IOCTL-LAYOUT` stay open, and the handler never checks the type byte or exact size, so a command's direction
and layout are the userspace caller's choice and are not in this artifact. The payload accesses are a **lower bound**
(a payload reached through a pointer in a register is not seen; number 155 moves 8 payload bytes through an address
taken at offset 0, which appears only as `payload_address_taken_at`).

### `i2c_device_ioctl` (8 bytes)

`li 3, 0 ; blr`. It returns 0 for every command, reads none of its arguments and has no relocations. A success return
from this handler is therefore no evidence that a command did anything, and it cannot implement any HAL operation with
an observable effect. (I2C register access in the driver goes through `i2c_read_reg` and `i2c_write_reg`, which
`audioctl` cases 18, 24, 25 and 38 call.)

### How these facts are checked

Three readings that do not share code: `anchor_extract.py` decodes the object file's words and walks the control
flow; `anchor_crosscheck.py` reparses `llvm-objdump`'s text with its own branch handling; and
`anchors/audioctl_hand_derived.json` is a reading by eye. The runner compares the committed facts to the hand
reading (`E04-ANCHOR-002`), shows seven wrong facts are each caught (`E04-ANCHOR-DEFECT-01..07`), and re-derives the
committed file from the artifact wherever the capture exists (`E04-ANCHOR-001`). The cross-check was shown to catch
eight corruptions of the facts file after a green baseline. All of it is static analysis of one object file: nothing
was run, and nothing here is board behaviour.

## What it does not establish (all `unknown`)

Which interface implements which HAL operation (`EXT-E04-OP-MAPPING`); any per-command direction,
payload layout, endianness, alignment or full command word (`EXT-E04-IOCTL-LAYOUT`); who performs
each radio duty and whether it survives daemon replacement (`EXT-E04-RADIO-OWNERSHIP`); how many
channels the path drives and which transducer each feeds (`EXT-E04-CHANNEL-TOPOLOGY`); the sample
rates and encoding (`EXT-E04-RATES`); the order and minimum delays of the amplifier steps
(`EXT-E04-AMP-SEQUENCE`) and whether the driver acknowledges a mute (`EXT-E04-MUTE-ACK`); and any
real-board behavior: multicast, unicast, power-save, roam, congestion, amplifier sequencing, timing
(`EXT-E04-LIVE-QUAL`, human-led, no live test here). The committed matrix therefore has **111**
unknown fields (unchanged by the audioctl and i2c analysis above: it shows what code a number reaches, not what
the number means). The Wi-Fi driver is not analyzed. The board
profile has no driver-digest field, so the matrix cannot be cross-checked against a profile by
digest (dependency on E01/P04); only the channel map is cross-checked.

## Simulator semantics

State: owner, phase (`closed`, `prepared`, `running`, `draining`, `faulted`, `power_save`), amplifier
(`muted`, `unmuted`, `mute_failed`), slots (`free`, `dma_owned`, `quarantined`, `released`), a clock,
frame totals, the counter base, and a radio ledger. A host action that would break an invariant is
**refused** with a typed reason and changes nothing. A driver report that contradicts the contract is
an **anomaly** and changes nothing. Checks run in the listed order.

| Event | Rules, in order | On success |
|---|---|---|
| `acquire` | owner set: `busy` | owner = caller |
| `prepare n` | no owner: `not_owner`; phase not closed: `wrong_phase`; n = 0 or > 64: `bad_slot_count` | n free slots, prepared, muted |
| `start` | not prepared: `wrong_phase`; mute failed: `mute_not_acknowledged` | running, unmuted |
| `submit` (slot, frames, accepted) | phase not prepared/running: `wrong_phase`; slot out of range: `bad_slot`; slot not free: `slot_not_free`; frames 0: `empty_submit`; accepted > frames: anomaly `accepted_more_than_offered`; accepted 0: partial, all remaining | slot `dma_owned`; partial with remainder if accepted < frames |
| `completion` | slot `dma_owned` only; `quarantined`: anomaly `completion_for_quarantined_slot`; else anomaly `spurious_completion` | slot free |
| `release_slot` | out of range: `bad_slot`; `dma_owned`: `release_while_dma_owned`; `quarantined`: `slot_quarantined`; `released`: `already_released` | slot released |
| `drain n` | phase not running/prepared: `wrong_phase` | draining, muted, deadline = now + n |
| `tick` | deadline reached while draining: `drain_timed_out`, in-flight slots quarantined, faulted | clock advances |
| `flush_ack` | not draining: anomaly `flush_ack_outside_drain` | in-flight slots free, prepared |
| `abort_mute ack` | closed: `wrong_phase`; ack true: muted, draining (no wait bound); ack false: `mute_failed`, faulted | |
| `device_reset ack` | no owner: `not_owner`; ack false: anomaly `reset_unacknowledged` | in-flight and quarantined slots free; faulted/draining become prepared |
| `device_loss` | always | in-flight slots quarantined, mute unknown, faulted |
| `power_save enter` | no owner: `not_owner`; not prepared: `wrong_phase`; not muted: `power_save_needs_mute`; slots in flight or quarantined: `power_save_needs_idle` | power-save; `exit` needs power-save: else `not_in_power_save` |
| `consumed_counter v` | `v - last` (wrapping 32-bit) exceeding frames in flight: anomaly `counter_exceeds_in_flight` | consumed and last updated |
| `release_device` | not the owner: `not_owner`; mute failed: `mute_not_acknowledged`; `dma_owned`: `dma_owned_slots`; `quarantined`: `quarantined_slots`; phase not closed/prepared: `wrong_phase` | closed, counters reset |
| `declare_duty`, `daemon_replaced`, `adopt_duty` | adopt: undeclared `duty_not_declared`; owner not daemon `not_daemon_owned`; daemon not replaced `daemon_not_replaced` | replacement orphans `held_daemon` duties; unknown owners stay `owner_unknown` |

A stop request is not an acknowledged flush: draining ends only on `flush_ack` or a timeout, and
`release_device` needs one of them. Counters are untrusted input and never used as an index.

### With a contract model

A trace may carry a **model**: a channel count and bytes per sample, the rates the driver lists, and
the startup sequence (its last step is `deassert_mute`, which `start` performs). With a model the
simulator runs the contract's amplifier order and channel map; one sim tick is one microsecond. Without
one these events are refused (`no_model`) and everything above is unchanged.

| Event | Rules, in order | On success |
|---|---|---|
| `set_rate hz` | no model: `no_model`; no owner: `not_owner`; phase not prepared: `wrong_phase`; rate not listed: `rate_not_supported` | rate set |
| `amp_step disable_clocks` | no model, no owner as above; amplifier not muted: `clocks_off_while_unmuted` | clocks off; startup progress back to zero |
| `amp_step` (a startup action) | phase not prepared: `wrong_phase`; progress already at the last pre-unmute step, or not the next action: `amp_step_out_of_order`; progress above zero and less than the step's minimum delay since the previous step: `amp_step_too_early` | progress + 1, clock noted; `enable_clocks` turns the clocks on |
| `start` (with a model) | after the usual checks: no rate: `rate_not_set`; progress short of the pre-unmute steps: `amp_sequence_incomplete`; less than the unmute step's minimum delay since the last step: `amp_step_too_early` | unmuted, running, progress back to zero |
| `submit_bytes slot bytes accepted_bytes` | no model: `no_model`; the usual phase and slot checks; zero bytes: `empty_submit`; bytes not a whole number of frames (channels times bytes per sample): `partial_frame`; accepted more than offered: anomaly; accepted not a whole number of frames: anomaly `accepted_partial_frame` | as `submit`, in frames |

A step is accepted exactly at its minimum delay and refused one tick before (a boundary pair in the
cases). A drain, an abort into mute, a reset and a device loss all send the startup back to the
beginning, so a fault cannot leave a half-finished sequence to be resumed; the chosen rate survives
until the device is prepared again or released.

## Diagnostics

`contract_log.rs` writes `ffw.log.v1` JSONL itself; `franken-test-support` is a dev-dependency used
only by tests to check the shape. A verdict logs a summary line and a **critical** line for every
missing item (record, field, and the reason or external blocker id). A simulator step logs an
ordinary line for what applied or was refused, and a **critical** line for a driver anomaly, a drain
timeout or an unacknowledged mute; a replay that disagrees with its hand-written expectation logs a
critical line naming the step. The log is bounded: when full it drops ordinary lines first, a critical
line evicts the oldest ordinary one, and a critical line is lost only when the log holds nothing but
critical lines, which is counted and marks the evidence incomplete. It never blocks.

Lines are redacted by construction. A line is built from enum names, numbers and identifiers that
passed `safe_id` (letters, digits and `. _ : -`, at most 64 characters; anything else, including a bare
dotted quad, becomes `invalid_id`). Free text from a matrix, a blocker's `needs` or an inconsistency's
detail, is never copied. `timestamp_mono_ns` is a line counter, not wall time.

## Running and verifying

```
scripts/e2e/e04 --tier smoke      # 71 cases, qualified when all pass (host simulation only)
scripts/e2e/e04 --tier full       # adds planted defects, anchor re-derivation, structure; exits 3
```

The full tier exits 3 (NOT QUALIFIED) by design: two required invariants are counted as blocked, not
passed. `E04-RUST-CENTRAL` needs the central run below; `E04-EXT-QUAL` is the human-led qualification.
`E04-ANCHOR-001` is also blocked wherever the git-ignored artifact is absent.

Central Rust verification (each its own invocation, no local cargo):

```
RCH_REQUIRE_REMOTE=1 rch exec -- cargo test -p franken-hal
RCH_REQUIRE_REMOTE=1 rch exec -- cargo clippy --workspace --all-targets -- -D warnings
RCH_REQUIRE_REMOTE=1 rch exec -- cargo fmt --all -- --check
```

The expected values in the case files are hand-written, and both implementations replay the same
files. They share one author, so agreement is a cross-check, not independence from a second author.
Tests do not prove perfection.
