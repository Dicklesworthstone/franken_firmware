## 1. Scope

Endpoint identity, control registration, discovery, NAT traversal, relay and key rotation feasibility beyond WireGuard encryption alone, on the two retained-kernel families: PowerPC
32-bit big-endian (stock Linux 2.6.14, nominal 32 MB) and MIPS32r2 big-endian (stock Linux 2.6.35, nominal 128 MB). Both kernels are **unqualified** (E03: no matching full-system
guest exists); the Debian 4.9 (PowerPC) and 4.19 (MIPS) QEMU guests are separate harness rows and are never evidence about a stock kernel. Offline work only: the sources were fetched
read-only and are pinned by commit or exact version; no tailnet, account, device or provider was contacted.

## 2. Definitions

Native support (the bead): each node enrolls under its own identity, receives network state and applies access policy; its control and data planes interoperate with the owner's
tailnet. A userspace WireGuard tunnel by itself does not implement Tailscale membership (ledger T01-E45). The classes a candidate can have, derived from its facts by `classify`:

| class | meaning | counts as the native implementation? |
|---|---|---|
| `native_strict_rust` | a strict-Rust process with its own tailnet identity, control plane and data plane | only if every behavior is `supported` on the target, which needs a run on the target |
| `official_reference` | the same, in another language (the Go client) | never: it is the reference for behavior, not strict Rust |
| `wireguard_only` | a WireGuard data plane with no control plane | never (no membership) |
| `wrapper` | rides on another daemon on the same device, or embeds another runtime | never |
| `gateway` | access through another host's identity | never; named separately, as the bead requires |
| `control_server_only` | a coordination server | never |

No Go reference client or gateway counts as a strict-Rust native implementation. `tests/t01/cases.json` holds twelve hand-written facts-to-class rows, including the unclassifiable ones.

## 4. Rules

* `classify(facts)`: the table in section 2; an unrecognizable fact set is an error, not a default.
* `derive_cell(behavior, platform, extensible)`: a platform that cannot run the candidate is `incompatible` whatever it implements; a `partial` or `not_implemented` behavior is
  `implementable_upstream_work` only where the gap can be closed in a code base we can extend, else `incompatible`; an `unknown` behavior is `no_evidence`; an `implemented` behavior is `supported`
  **only** when the candidate has run on the target (`ran_on_target`, with a receipt), otherwise `no_evidence`. `not_applicable` (a gateway on a speaker) is not a verdict about the speaker.
  An incompatibility that rests on a stock kernel release must say so (`conditional_on`), because that release is reported, not verified.
* `budget_verdict(measured, cap, reserve_floor, reserve)`: a reserve below the 4 MiB floor is invalid; no measurement is `pending`; no cap is `pending`; a unit mismatch or a measurement
  without a receipt is invalid; otherwise `pass` only if `measured + reserve <= cap`. No admitted numeric RAM cap exists until the shared budget is allocated, so absent budget is pending, not pass,
  and every figure in the profile is pending, not applicable, or an explicitly labelled observation that is not a footprint. No native footprint is promised before a complete configuration has been measured.

## 5. Synthetic fixtures and what they assert

`tests/tailscale-fixtures/synthetic/` holds a synthetic identity set (placeholder keys, `.invalid` names, tailnet-range addresses), a network map, a relay map and a key-expiry timeline. Nothing in
them is a real key, device, account or site. The expectations in the files were written by hand from these sentences:

* Packet filter: default deny; a packet is allowed only if some rule matches its source, destination, port and protocol; `*` matches any. Twelve hand-written decisions.
* Route: `direct` if the direct path works; else the peer's home relay region if it exists and is reachable; else the reachable region with the lowest measured latency; else `unreachable`. Nine cases.
* Key expiry: an expired key stops the endpoint's connections until it reauthenticates (official documentation, ledger T01-E10); the expiry instant itself is expired; an expired key wins over every
  other condition. The warning window (7 days), the offline bound on a stale network map (1 day) and the refusal to judge expiry on an untrusted clock are **provisional policy of the native design**,
  decided for the first time by T04, not Tailscale behavior and not measurements. Twelve hand-written steps.

**T01-X02 as it stands: the probe ran once in one harness guest per architecture and both runs pass the judge; the figures are indicative only and T01 stays open.**

* **The probe**, `toolchain/src/t01-core-probe/` (its own Cargo workspace root and lockfile, declared in the P01 contract as a standalone probe; this contract builds nothing). It links the seven pinned tailscale-rs core crates of section 3 (`ts_keys`, `ts_noise`, `ts_tunnel`, `ts_control_serde`, `ts_packetfilter_state`, `ts_disco_protocol`, `ts_overlay_router`, default features off), plus `ts_packet` and `ts_bart` (path crates of the same pinned tree, already in the graph through `ts_tunnel` and `ts_overlay_router`), `serde_json` (the version those crates lock) and, for `kat.rs`, `blake2`, `chacha20poly1305` and `hkdf` (the specs the core crates take); nothing outside the committed `Cargo.lock`. It uses no network and no async runtime and does no enrollment; two `ts_tunnel` endpoints exchange packets only with each other, in memory, and it is not a tailnet client. It runs **eight phases** in this order: `TS_KEYS`, `TS_NOISE`, `TS_TUNNEL`, `TS_CONTROL_SERDE`, `TS_PACKETFILTER_STATE`, `TS_DISCO_PROTOCOL`, `TS_OVERLAY_ROUTER`, `CRYPTO_KAT`, where `CRYPTO_KAT` is the known-answer module `kat.rs` (published RFC vectors for the primitives the core crates link). It then reads its own `VmHWM`, `VmRSS`, `utime` and `stime` from `/proc/self` and prints `END`; it exits 0 whenever it printed `END`, because the verdict is the transcript. Before `TS_NOISE` it draws once from the operating system's random source on a worker thread and waits at most 40 s, so a guest whose pool is not ready prints `fail reason=rng_blocked` for `TS_NOISE` and the `TS_TUNNEL` handshake instead of stalling (an RNG *error*, as opposed to a wait, still aborts the process and prints no `END`). The two ELFs that ran were built centrally by the operator from these source bytes; that is the operator's statement, not something a committed log shows (the receipts record `source_provenance: not_attested_by_this_runner`).

* **The transcript grammar** (`ffw.t01.x02_transcript.v1`; the judge's phase table must equal what the built probe prints, so a probe with fewer or more phases is refused):

```
T01X02 PHASE <NAME> ok|fail <k=v ...>   once per expected phase, in this order; facts are space-separated key=value pairs (key [a-z][a-z0-9_]*, value printable ASCII, no space, no '=')
T01X02 VmHWM <uint>|UNKNOWN             kB as /proc/self/status reports them; then VmRSS (kB), utime and stime (raw /proc clock ticks), each exactly once, in that order
T01X02 END ok=<n> fail=<n> unknown=<n>  the last T01X02 line; ok and fail count the PHASE lines, unknown counts the resource lines that read UNKNOWN
```

* **The judge**, `tests/t01/x02_judge.py` (standard library only). FAIL: framing other than LF or CRLF, any control character, a marker that is not at the start of a line, an unrecognized or malformed T01X02 line, a missing, duplicate, extra or out-of-order PHASE, any PHASE `fail`, a non-canonical integer, a duplicate or out-of-order resource line, `VmHWM` below `VmRSS` or either of them 0, a missing, duplicate, non-final or contradicting `END`, and, for a captured run, a timeout or output limit, a QEMU exit other than 0, a missing reboot, or any kernel, initramfs, supervisor or ELF hash that differs before and after. BLOCKED: a resource line that reads `UNKNOWN` or is missing; that is never a pass. A FAIL outranks a BLOCKED, and exit codes are 1, 3 and 0.
* **The guest-run front end**, `scripts/e2e/t01 --x02 run|analyze`. `run` boots an already-built probe ELF under the existing QEMU guests (MIPS Malta with the Debian 4.19 kernel, PowerPC g3beige with the Debian 4.9 kernel) in the existing E07 speaker-smoke supervisor slot, through the P05 runtime layer (`toolchain/src/measure-p05-target.py`, which wraps `run-qemu-verification.py`; it is imported, not copied): a 1 MiB and 180 s capture bound, a fresh log directory, an exclusive receipt, and the ELF, kernel and initramfs hashes checked before and after. It compiles nothing. `analyze` judges a supplied transcript and labels the result `supplied_transcript_analysis`.
* **The receipt**, schema `ffw.t01.x02_receipt.v1`: the result, the architecture, `evidence_kind` (`captured_guest_execution` or `supplied_transcript_analysis`), the parsed phases, resources and `END`, the gate list, and the ELF, supervisor, kernel and initramfs hashes. It is written exclusively and carries **no absolute host path**: a path under the repository is recorded repo-relative, any other as `<outside-repo>/<basename>`, and each rewritten path is listed in `path_hashes` with the sha256 of the file it named; the writer refuses to write a receipt in which an absolute path survives, and the consumer fails one that has it.
* **The runner case** `T01-X02-target-resources` (`case_resources` in `tests/t01/run_cases.py`, with `judge_receipt` in the judge) reads every receipt under `toolchain/results/tailscale/measurements/`. It re-judges the facts a receipt records and never trusts its own `result`. No receipt: BLOCKED. A malformed receipt, another schema, an absolute path, or a captured run that did not pass: FAILED, by file name. A `supplied_transcript_analysis` never counts as a run. PASSED only when **each** legacy target (mips and powerpc) has a captured guest run with all eight phases ok, no UNKNOWN reading and its hashes; one target alone stays BLOCKED. The two committed receipts (section 9, "What ran") make the case PASS; the default run still exits 3, because the five source probes T01-P01 to T01-P05 need `--sources`.
