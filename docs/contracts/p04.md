# P04 contract: board HAL adapters and the fake-device harness (`ffw-0bh`)

Status: implemented offline, **verification pending**. Everything here runs against a deterministic
**fake device**, which is a model. It shows the adapter and ownership logic and says nothing about any
board. No real driver interface is admitted yet (the E04 matrix is still entirely unknown), so there
is no real-device adapter, and a real device cannot be opened without a hardware-eligible contract.

## What exists

| Piece | Path | What it is |
|---|---|---|
| Wire codecs | `crates/franken-hal/src/abi.rs` | big-endian geometry and event records, strict decoders, golden vectors |
| Owner-held slots | `crates/franken-hal/src/slots.rs` | the slot table, inert tokens, the leak ledger, the kernel's non-owning view |
| Driver boundary and fake | `crates/franken-hal/src/backend.rs` | `DeviceBackend` trait, `FakeBackend`, `FakeProbe` |

| Vectors, cases, runner | `tests/p04/`, `scripts/e2e/p04` | independent Python codec, invariant-to-test map |

The existing offline typestate (`AudioHalDevice`) is unchanged. `franken-speaker` still uses it.

## The ownership rule

**Storage the kernel may still read is never freed or reused.** Concretely:

* The `SlotTable` owns every slot's storage. A slot becomes `Free` only on a device acknowledgment: a
  completion matching the slot **and its generation**, a flush acknowledgment, or a reset
  acknowledgment. A submit that fails with an error cannot be assumed not to have been kept, so its
  slot is quarantined.
* A `SubmitToken` is a slot number, a generation and a session id. It owns nothing and has no `Drop`.
  Forgetting it, dropping it, or never polling cannot return storage. The owner finishes the job when
  the device acknowledges.
* The kernel is modelled safely: it holds a `KernelView`, a `Weak` reference that does **not** keep
  storage alive, as a raw pointer given to a driver would not. The fake records `use_after_free` if a
  view fails to upgrade when the kernel reads it, and `modified_while_owned` if the bytes changed. A
  test that ends with both at zero has shown the HAL did not give the storage back early. A control
  test shows the view really does detect a free.
* **Destroying the owner.** `Drop for SlotTable` keeps every non-`Free` slot's storage alive for the
  rest of the process (a deliberate, counted leak). A `LeakLedger` caps how many slots a process will
  leak; once reached, new tables are refused. Dropping the session also asks for a mute.
* Quarantine is bounded by the table (at most 64 slots) and by a per-session cap whose breach is
  recorded as a fault. Only an **acknowledged reset** frees quarantined slots. A flush
  acknowledgment frees what was merely in flight.

## Fail muted

A driver error, a malformed geometry or event record, a byte count that is not a whole number of
frames or exceeds what was offered, a completion for a slot that is out of range, free, quarantined or
on a stale generation, a completion on an ABI that has none, or a counter that claims more than is in
flight, all do the same thing: record the fault, quarantine what is in flight, enter `Faulted`, and
ask the device to mute. If the mute is not acknowledged the amplifier is `Unknown`, which blocks
start and release until a mute is acknowledged. A vanished device is a **persistent** fault: reset is
refused. A flush acknowledgment that arrives outside a drain is counted as an anomaly, not a fault, and
frees nothing.

## Stop requested is not stopped

`drain(max_wait_ticks)` mutes, settles any events the device had already queued, requests a flush, and
waits. It returns `Acknowledged` only after it observes the acknowledgment. Otherwise it quarantines
what is in flight, faults, and returns `TimedOut`. An acknowledgment carries no id, so the settle step
is what stops a stale acknowledgment from answering a newer request. `cancel_drain` quarantines and
never frees. `start` is refused unless the amplifier is known muted, a presentation mapping and a safe
gain are installed, and the device can state a **stop deadline**; with an unknown deadline the receipt
says `audible_transition_admitted: false` with its reason.

The session exposes the minimum submission lead, the stop deadline, an `irrevocable_until` cursor (the
frames the device has accepted, which cannot be revoked) and a consumed-frame count with an
uncertainty class (`exact`, `bounded`, `unknown`). The consumed counter wraps; a report is accepted
only if its wrapping delta does not exceed the frames in flight, and the first report after open or
reset only sets the baseline.

## Copying versus retained ABIs

`AbiKind::CopyingWrite { evidence }` avoids slot leases because the driver copies before the call
returns; a blank `evidence` is refused when the session opens. `AbiKind::RetainedBuffer` keeps the
slot owned until completion. A short write leaves the remainder with the caller; a zero accept returns
the slot at once, because the device holds nothing; a partial accept keeps the whole slot, because
the device may read all of it. The retained-driver evidence in `docs/contracts/e04.md` is that
`write()` copies synchronously, but no adapter binds to it yet.

## Evidence: model versus driver

The geometry record's layout (four big-endian words) and values were decoded from the retained
model-16 driver's ioctl handler (E04); its field names are inferred. The 12-byte event record is a
**harness model**: no retained driver is known to emit it. Every receipt says
`evidence: "model"` and `scope: "host_simulation"` for the fake and would say `driver` and `device` for
a real backend. A true-device ledger is a separate artifact owned by the human lane.

## Not covered (stated, not claimed)

* The local button, LED and fault-event ABI (the fresh-eyes clause). The capability is reported as
  `Unsupported` with a reason, and nothing is inferred from driver strings. There is no event adapter,
  bounded event queue, malformed-event handling or debounce input yet.
* Structured JSONL diagnostics. The session produces a serializable receipt, not a bounded log.
* Any real-driver adapter, and migration of `franken-speaker` onto `HalSession`. The offline
  typestate's `finish_drain_and_close` frees quarantined slots with no acknowledgment at all, which is
  the hazard this session closes; the speaker has not been moved off it.
* Platform `unsafe`. The crate keeps `#![forbid(unsafe_code)]`; real kernel access would need a
  platform crate with written invariants.

## Running and verifying

```
scripts/e2e/p04 --tier smoke      # vectors, invariant map, structure: qualified when all pass
scripts/e2e/p04 --tier full       # adds the planted defect and the self-test; exits 3 by design
```

The full tier exits 3 (NOT QUALIFIED) because two required items are counted as blocked, not passed:
`P04-RUST-CENTRAL`, which is the behavioral verification, and `P04-EXT-QUAL`, the separate device
ledger. Central Rust verification, each its own invocation:

```
RCH_REQUIRE_REMOTE=1 rch exec -- cargo test -p franken-hal
RCH_REQUIRE_REMOTE=1 rch exec -- cargo clippy --workspace --all-targets -- -D warnings
RCH_REQUIRE_REMOTE=1 rch exec -- cargo fmt --all -- --check
```

Expected values are hand-written, and the Python and Rust codecs share an author. Tests do not prove
perfection.
